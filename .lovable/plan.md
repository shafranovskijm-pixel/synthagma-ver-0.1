

## Два исправления: генерация учётных данных + защита от студенческого дашборда

### Проблема 1: Нет кнопки «Сгенерировать учётные данные»
В карточке организации (вкладка «Настройки») при отсутствии записи в `organization_credentials` показывается «Пароль не сохранён», но нет кнопки для генерации. Генерация доступна только из списка организаций (`OrganizationsManager`), но не из детальной карточки.

### Проблема 2: Пользователь с ролью «организация» видит студенческий дашборд
У пользователя `mail@avrora27.ru` роль `organization`, но на скриншоте — студенческий интерфейс. Маршрут `/student` не проверяет `requiredRole`, поэтому любой авторизованный пользователь может на нём оказаться (через закладку, кеш, прямой URL).

### Решение

**1. `OrganizationDetailsView.tsx`** — добавить кнопку «Сгенерировать учётные данные»:
- В блоке `else` (когда `credentials` нет) добавить кнопку, вызывающую edge-функцию `generate-org-credentials`
- После успешной генерации — обновить `credentials` state и показать логин/пароль
- Также добавить кнопку «Сбросить пароль» когда credentials уже есть (через `reset-org-password`)

**2. Студенческий дашборд** — добавить редирект для организаций:
- В `src/pages/StudentDashboard.tsx` (или соответствующий компонент) добавить проверку: если `userRole === 'organization'`, перенаправить на `/organization`
- Либо в `App.tsx` добавить `requiredRole="student"` к маршруту `/student` — но это может сломать кейсы, когда студент заходит без явной роли

Предпочтительный вариант: в компоненте студенческого дашборда добавить редирект для не-студентов.

### Файлы
| Файл | Изменение |
|------|-----------|
| `OrganizationDetailsView.tsx` | Кнопка «Сгенерировать учётные данные» + «Сбросить пароль» |
| Студенческий дашборд (страница) | Редирект org/company/admin пользователей на их дашборды |
