
## Что хочет пользователь

Когда админ заходит в организацию через «Войти как организация» (`adminViewAsOrg`), на каждой карточке курса нужна доп. кнопка «Перенести в организацию». По клику — выбор целевой организации из списка → копирование (дублирование) курса в её аккаунт.

## Что уже есть в проекте

- **Дублирование курсов** уже реализовано (мемори `course-duplication-system`) — кнопка «Дублировать курс» в выпадающем меню, делает deep clone (уроки, тесты, банк вопросов, обложки).
- **Admin-режим** определяется через `localStorage.adminViewAsOrg` + флаг `d.isAdminView` в `OrgDashboardContext`.
- **Edge-функция дублирования** уже существует — нужно проверить, поддерживает ли она параметр `target_organization_id`.

## План

### 1. Найти текущий механизм дублирования
- Изучить компонент карточки курса в дашборде организации (вероятно `src/components/organization/courses/CourseCard.tsx` или подобный) и edge-функцию `duplicate-course`.
- Понять, можно ли расширить существующую функцию параметром «целевая организация», или нужна новая edge-функция `transfer-course-to-org`.

### 2. UI — кнопка «Перенести в организацию»
- В карточке курса (вкладка «Курсы» в OrgDashboard) добавить **отдельную кнопку**, видимую **только когда `d.isAdminView === true`**.
- Стиль: маленький icon-button с иконкой `ArrowRightLeft` (Lucide), цвет акцентный teal/cyan (по бренду — НЕ жёлтый, согласно core-памяти про luxury minimalism).
- Тултип: «Перенести копию в другую организацию (только для админа)».

### 3. Диалог выбора целевой организации
- Новый компонент `TransferCourseDialog.tsx`:
  - Поиск/комбобокс со списком всех организаций (запрос к `organizations`, доступен админу через RLS override).
  - Превью: название курса → стрелка → выбранная организация.
  - Кнопка «Перенести копию» (создаёт дубликат, оригинал остаётся в текущей организации).
  - Опционально: чекбокс «Опубликовать сразу» (по умолчанию выкл — курс приходит черновиком).

### 4. Бэкенд — edge-функция
- Расширить существующую `duplicate-course` параметром `target_organization_id` (опциональный):
  - Если параметр есть и вызывающий — admin (`has_role('admin')`), копия создаётся в целевой организации.
  - Полное deep-clone: курс + уроки + тесты + банк вопросов + обложки + материалы (как в текущей логике дублирования).
  - Возвращает `new_course_id` + `target_org_name` для тоста.
- Проверка прав: ТОЛЬКО админ может указывать `target_organization_id`. Без админ-роли — игнорируется.

### 5. UX после переноса
- Toast: «Курс «X» скопирован в организацию «Y»» с кнопкой «Перейти» (опционально — переключиться в режим просмотра целевой организации).
- Лог: запись в `audit_log` через существующий триггер.

## Технические детали

- **Файлы для изменений:**
  - `src/components/organization/courses/...CourseCard.tsx` (кнопка)
  - `src/components/organization/dialogs/TransferCourseDialog.tsx` (новый)
  - `src/components/organization/dialogs/DialogsContainer.tsx` (регистрация диалога)
  - `supabase/functions/duplicate-course/index.ts` (расширение)
- **Без изменений в БД** — используются существующие таблицы.
- **Безопасность:** проверка `has_role('admin')` в edge-функции при использовании `target_organization_id`. RLS уже разрешает админам видеть все организации.
