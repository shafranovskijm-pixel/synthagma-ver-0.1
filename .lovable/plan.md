
## Что просит пользователь (4 пункта)

1. **Соглашение ПЭП в попап.** Маленькая `ScrollArea` неудобна — нужно открывать полный текст в модалке. Слово «Соглашение» в чекбоксе должно быть кликабельным и открывать тот же попап.
2. **ФИО подписанта со стороны организации = «ИП Шафрановский Максим Михайлович» (ИНН 253615392404)**, а не «Администратор Синтагма». Должны подтягиваться реквизиты Оператора, как в счетах/актах.
3. **Кнопки «Посмотреть подписанный договор» и «Скачать»** — нужны и организации, и клиенту после подписания (с ПЭП-штампом, метаданными, обоими подписантами).
4. **Выбор способа подписи: ПЭП или загрузка скана с подписью/печатью.** Где-то в блоке действий должен быть выбор «Электронно (ПЭП)» / «Загрузить скан с моей подписью и печатью».

## Решение

### A. Константы Оператора
Создать `src/constants/operatorDetails.ts`:
```ts
export const OPERATOR = {
  fullName: "ИП Шафрановский Максим Михайлович",
  shortName: "Шафрановский М.М.",
  inn: "253615392404",
  ogrnip: "324253600042754",
  email: "support@sintagma.com.ru",
};
```
В `ContractReviewBody` при `isOrg && action === "sign_as_is"` подставлять `OPERATOR.fullName` и `OPERATOR.email` вместо `user_metadata.full_name`. Поля остаются редактируемыми (вдруг подписывает не ИП, а представитель), но дефолт — ИП.

### B. Попап с Соглашением ПЭП
Новый компонент `src/components/signing/PepAgreementDialog.tsx` — `Dialog` с `ScrollArea max-h:80vh`, рендерит полный `agreementText` крупным шрифтом, кнопка «Я ознакомился(ась)» внизу (при клике закрывает попап и автоматически проставляет чекбокс). 

В панели подписания:
- Убрать встроенный маленький `ScrollArea` (строки 678–682).
- Заменить чекбокс на: `[ ]` Я ознакомился(ась) и принимаю условия **[Соглашения об использовании ПЭП]** (63-ФЗ) — где **подчёркнутый текст** открывает попап.
- Дополнительно кнопка «Открыть полный текст соглашения» рядом.

### C. Двухвариантный способ подписания
В блоке «Подписать прямо здесь» добавить переключатель `Tabs`:
- **Электронно (ПЭП)** — текущий флоу (ФИО + email + соглашение + чекбокс). Дефолт.
- **Загрузить скан с подписью и печатью** — `SignatureRevisionUploader`-подобный загрузчик: drag-n-drop PDF/JPG, превью, поле комментария, кнопка «Прикрепить и подписать». Файл сохраняется в `external-contracts` бакет, путь записывается в новое поле `document_signatures.handwritten_scan_path` + статус становится `signed` через ту же `finalize-signature` (с флагом `method: 'handwritten_scan'`, минуя проверку SHA-256).

Миграция БД:
```sql
ALTER TABLE document_signatures
  ADD COLUMN signature_method TEXT NOT NULL DEFAULT 'pep'
    CHECK (signature_method IN ('pep','handwritten_scan')),
  ADD COLUMN handwritten_scan_path TEXT,
  ADD COLUMN signed_document_path TEXT;  -- путь к финальному PDF с штампом
```

### D. Кнопки «Посмотреть подписанный документ» и «Скачать»
В блоке `SIGNED CONFIRMATION` (строки 781–799) добавить две кнопки для **обеих сторон** (org и recipient):

- **«Посмотреть подписанный документ»** — открывает модалку `SignedDocumentPreview`, которая рендерит:
  - оригинальный документ (HTML/DOCX/PDF — переиспользуем существующие рендереры),
  - снизу — оба ПЭП-штампа (отправитель + получатель) либо превью загруженного скана,
  - метаданные подписания (ФИО, IP, дата, SHA-256, ID соглашения).
- **«Скачать PDF»** — вызывает новую edge-функцию `generate-signed-pdf` (на базе уже работающего HTML→PDF пайплайна), которая собирает финальный документ + ПЭП-штампы + блок «Подписи сторон» и отдаёт PDF. Результат кешируется в `signed_document_path` (бакет `external-contracts/signed/`).

Если способ = `handwritten_scan` — кнопка «Посмотреть» открывает прямо загруженный скан, «Скачать» отдаёт его же.

Видимость:
- Организация — всегда после `signed`.
- Клиент — всегда после `signed` (загружает по `signature_token`, RLS уже разрешает recipient).

### E. Шапка после подписания: показать обе подписи
Сейчас `PepSignatureStamp` рендерится один раз. После подписи **двумя сторонами** показывать карточку «Документ подписан сторонами»: слева — штамп Оператора (ИП Шафрановский), справа — штамп Получателя. Берём данные из `document_signatures.signed_*` + `pep_agreements` записи (для каждой стороны своя).

- `src/components/signing/ContractReviewBody.tsx` — заменить дефолт ФИО для орг, заменить inline scroll на попап-ссылку, добавить tabs «ПЭП / Скан», добавить кнопки «Посмотреть/Скачать» в SIGNED-блоке, рендерить штампы обеих сторон.

- `supabase/functions/finalize-signature/index.ts` — поддержать `method: 'handwritten_scan'` (пропуск SHA-проверки, запись пути).

## Этапы

1. Миграция БД (3 поля).
2. Константа Оператора + дефолты ФИО/Email при `sign_as_is`.
3. `PepAgreementDialog` + интеграция в подпись-панель (убрать маленький scroll, кликабельная ссылка).
4. Tabs «ПЭП / Скан» + `HandwrittenSignUploader` + ветка в `finalize-signature`.
5. Edge-функция `generate-signed-pdf` (с штампами обеих сторон) + кеш.
6. `SignedDocumentPreview` + кнопки «Посмотреть/Скачать» в блоке подписан.
7. Двухсторонние штампы в шапке после подписи.
8. Проверить флоу: организация подписывает (ИП Шафрановский подставлен) → клиент подписывает → у обоих видны кнопки «Посмотреть/Скачать», PDF корректно собран. Альтернативно — клиент выбирает «Скан», грузит PDF подписанный — видно у обеих сторон.
