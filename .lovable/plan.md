
# Расширенная аналитика посещений в админ-панели

## Что будет сделано

Добавление новой вкладки **"Посещения"** в `AdminAnalytics`, которая покажет:

### 1. Сводные карточки
- Всего посещений платформы (за выбранный период)
- Всего заходов на курсы (за период)
- Уникальных пользователей
- Среднее число посещений в день

### 2. График посещений по дням
- AreaChart с двумя линиями: "Заходы на платформу" (из `student_login_history`) и "Заходы на курсы" (из `course_access_log`)
- Зависит от выбранного периода (7/30/90 дней)

### 3. Таблица посещений с детализацией
- Список всех визитов по дням (группировка по дате)
- Для каждого визита: имя пользователя, email, время, IP-адрес, устройство (парсинг user_agent), тип (платформа/курс), название курса (если заход на курс)
- Фильтр по типу: все / платформа / курсы
- Поиск по имени/email
- Пагинация или ScrollArea с ограничением

### 4. Топ активных пользователей
- Таблица топ-20 пользователей по количеству посещений за период
- Имя, email, количество заходов на платформу, количество заходов на курсы

## Технические детали

### Загрузка данных
В `fetchAnalytics` добавить два новых запроса:
- `supabase.from("student_login_history").select("user_id, logged_in_at, ip_address, user_agent")`
- `supabase.from("course_access_log").select("user_id, course_id, accessed_at, ip_address, user_agent")`

Дополнительно загрузить имена курсов из `courses` (уже загружаются, нужно добавить `id, title`).

Для имен пользователей: `profiles` уже загружаются, нужно добавить `user_id, full_name, email`.

### Файлы для изменения
1. **`src/components/admin/AdminAnalytics.tsx`**:
   - Расширить интерфейс `AnalyticsData` полями `loginHistory` и `courseAccessLog`
   - Расширить `fetchAnalytics` двумя новыми запросами
   - Добавить `useMemo` для обработки данных посещений по дням
   - Добавить вкладку "Посещения" в TabsList и TabsContent
   - Расширить загрузку `profiles` и `courses` дополнительными полями (`user_id`, `full_name`, `email`, `id`, `title`)

2. Все изменения в одном файле -- никаких новых компонентов или миграций не требуется, данные уже есть в базе и доступны админу через существующие RLS-политики.
