

# План: исправить кнопку «Свернуть/Развернуть меню» в кабинете организации

## В чём проблема
1. **Кнопка-стрелка выглядит как декорация.** Это крошечный 28×28 значок с двойным шевроном (`ChevronsLeft/Right`) серого тона — пользователь не понимает, что это переключатель ширины меню. Тултип появляется только при наведении и только на десктопе.
2. **Состояние «expanded» применяется и к мобильной версии.** Флаг `expanded` сохраняется в `localStorage` и читается при инициализации без проверки ширины экрана. Если пользователь развернул меню на десктопе, а потом открыл сайт на телефоне — выезжающее меню становится 220px и накладывается поверх контента. На скриншоте видно именно это: меню «Продажи / Чаты / Каталог / Мои курсы …» наезжает на «Готовые программы».
3. **Авто-сворачивание есть, но только для десктопа** (`max-width: 1279px`), а для **мобильного выезжающего сайдбара (`<lg`) ширина по-прежнему берётся из `expanded`** — при `expanded=true` мобильная панель шириной 220px перекрывает почти весь экран iPhone (375px).
4. **Смысл «развернуть» неочевиден.** Пользователю не показывают, что именно меняется: иконки + подписи vs иконки + полные названия в строку. Нет ни заголовка, ни короткого пояснения.

## Что делаю

### 1. На мобиле всегда показывать «компактный» сайдбар, игнорируя `expanded`
- В `OrgSidebar.tsx`:
  - Завожу `useIsMobile()` (или `window.matchMedia("(max-width: 1023px)")` через состояние).
  - Вычисляю `effectiveExpanded = expanded && !isMobile`. Все классы (`w-[220px]/w-[88px]`, рендер подписей, footer) переключаются по `effectiveExpanded`, а не по сырому `expanded`.
  - В `OrganizationDashboard.tsx` убираю влияние `sidebarExpanded` на `lg:ml-[220px]` — там это уже завязано на `lg:`, поэтому ок, но проверю, что на `<lg` margin = 0 (он и так 0, потому что префикс `lg:`).
  - Это устраняет наложение меню на контент на телефоне, не трогая десктоп-логику.

### 2. Сделать кнопку-переключатель заметной и понятной
- В шапке сайдбара заменяю крошечную стрелку на **большую кнопку с текстом** (только в развёрнутом виде) и **отдельную «гантель» с подписью «Развернуть»** в свёрнутом:
  - Развёрнутый режим: кнопка `<button>` шириной во всю строку под названием школы с иконкой `PanelLeftClose` + текст «Свернуть в иконки». Hover/focus-стили заметные (border + bg-muted).
  - Свёрнутый режим: под лого — компактная вертикальная кнопка `PanelLeftOpen` + миниатюрная подпись «Шире» (или просто иконка с заметным hover-фоном `bg-primary/10` и border).
- Кнопка **скрыта на мобильных** (`hidden lg:flex`), как и сейчас, но сама по себе теперь выглядит как кнопка, а не как декорация.
- При первом разворачивании (`expanded` поменялось c false→true) показываю **тост** (`sonner`): «Меню развёрнуто — теперь видны полные названия. Можно свернуть обратно той же кнопкой.» Один раз на пользователя (флаг в localStorage `org-sidebar-expanded-hint-shown`).

### 3. Сбросить «зависший» `expanded=true` при первом заходе с узкого экрана
- На монтировании компонента: если `window.innerWidth < 1024` и `localStorage[expanded] === "1"`, считываю как `false` и **не пишу обратно в storage** (чтобы при возврате на десктоп пользователь снова получил развёрнутое меню). То есть `expanded` остаётся в storage = "1", но в текущей сессии на мобиле эффект не применяется. Это решается через `effectiveExpanded` из шага 1 — отдельной правки в storage не нужно, просто фиксирую логику в комментарии.

### 4. Обновить запись в Memory
- Дополнить `mem://features/organization/dashboard-navigation-ux`: «Кнопка «Свернуть/Развернуть меню» — крупная, с подписью; на мобиле всегда компактный режим вне зависимости от сохранённого `expanded`.»

- Админ-сайдбар — там фиксированная ширина 88px без режима «развернуть», проблемы нет.
- Стили тем, бейджей, разделов — не трогаю.

## Что НЕ делаю
- Не переделываю мобильную навигацию на drawer-панель (она уже выезжает по клику в шапке/нижней навигации).
- Не убираю функцию «развернуть» — она удобна на широких мониторах для новых пользователей, которые не запоминают иконки.
- Не меняю порядок/набор пунктов меню.
