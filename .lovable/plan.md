

## Проблема 1: Контроль скорости видео на разных браузерах

### Текущая ситуация
На скриншотах видно два разных интерфейса видеоплеера:
- Первый скриншот: нативные браузерные контроли с кнопкой "Скорость" (мобильный браузер показывает свои контроли)
- Второй скриншот: кастомные контроли приложения (без кнопки скорости, как и задумано)

Когда `allowSeek = false`, кастомные контроли скрывают меню скорости, а обработчик `handleRateChange` принудительно сбрасывает скорость на 1x. Однако на некоторых мобильных браузерах (особенно встроенных WebView и Samsung Internet) нативные контроли могут "просачиваться" поверх кастомных, давая доступ к изменению скорости.

### Решение
1. Добавить CSS-правила для полного скрытия нативных контролей во всех браузерах (включая webkit-псевдоэлементы: `::-webkit-media-controls`, `::-webkit-media-controls-enclosure` и т.д.)
2. Усилить защиту `handleRateChange`: принудительный сброс скорости на 1x через `setInterval` (каждые 500мс проверять и сбрасывать), а не только по событию `ratechange`
3. Добавить атрибут `playbackRate` напрямую при каждом рендере для гарантии

### Файлы
- `src/components/course-learning/VideoPlayerInline.tsx` -- усиление блокировки скорости
- `src/index.css` -- CSS для скрытия нативных контролей во всех браузерах

## Проблема 2: Тест не виден после просмотра видео

### Текущая ситуация
Когда пользователь досматривает видео до 90%, срабатывает `onVideoComplete`, который вызывает `markLessonComplete()`. Эта функция:
1. Отмечает видео-урок как завершённый
2. Автоматически переходит к следующему уроку (тесту) через `goToNextLesson()`

Проблема: если пользователь закрывает страницу/вкладку между моментом завершения видео (90%) и сохранением прогресса в базу -- урок НЕ отмечается как пройденный. При возвращении:
- В режиме `sequential_lessons` тест заблокирован, потому что видео-урок "не пройден"
- Пользователю нужно снова смотреть видео с начала (сохраненная позиция может быть потеряна)
- Даже если позиция сохранена, кнопка "Завершить урок" появляется только при `videoWatchProgress >= 90`, а `videoWatchProgress` стартует с 0 при новом открытии страницы

### Решение
1. При загрузке видео-урока: если сохранённая позиция (`savedPosition`) уже >= 90% от `savedDuration`, сразу установить `videoWatchProgress` в соответствующее значение. Это позволит кнопке "Завершить урок" появиться без повторного просмотра
2. Разделить `onVideoComplete` на два действия: не вызывать `markLessonComplete()` автоматически при 90%, а только показать кнопку "Завершить урок". Сейчас `onVideoComplete` дублирует поведение -- и автозавершает, и кнопка тоже есть при `videoEnded`
3. Сохранять `video_position` чаще для видео с запретом перемотки (каждые 5 секунд вместо 10)

### Файлы
- `src/pages/CourseLearning.tsx` -- инициализация `videoWatchProgress` из сохранённой позиции
- `src/hooks/useVideoProgress.ts` -- вернуть `savedDuration` для расчёта процента
- `src/components/course-learning/VideoPlayerInline.tsx` -- CSS для нативных контролей
