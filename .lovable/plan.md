
## Что делаем

Сейчас на странице курса (`CourseDetailsContent`) кнопка **«Просмотр»** ведёт на отдельный роут `/course-preview/:courseId` (страница `CoursePreview.tsx`) — пользователь выпадает из контекста курса, теряет вкладки, кнопка «Назад» в браузере ведёт «куда-то не туда» (особенно если курс был открыт из вкладки `course-details` дашборда).

Сделаем «Просмотр» **встроенной вкладкой**, как «Редактор», прямо в боковом меню `CourseDetailsContent`.

### 1. Новая вкладка `preview` в `CourseDetailsContent`

- В тип `activeTab` добавить значение `"preview"`.
- В блок «Настройки» бокового меню (рядом с «Редактор», «Страница курса», «Настройки», «Напоминания») добавить пункт **«Просмотр»** (иконка `Eye`).
  - Точнее, лучше положить «Просмотр» в блок «Обучение» сверху (логичнее) или прямо первой кнопкой — обсудим: положим первой в блоке «Настройки» рядом с «Редактор», чтобы пара «Просмотр / Редактор» была вместе.
- В контент-области добавить ветку: `if (activeTab === "preview") return <CoursePreviewEmbedded courseId={course.id} />`.

### 2. Кнопка «Просмотр» в шапке курса

Сейчас (`CourseDetailsContent.tsx:70`):
```tsx
onClick={() => h.navigate(`/course-preview/${course.id}`)}
```
Меняем на:
```tsx
onClick={() => onTabChange("preview")}
```
То же делаем в `CourseDetailsModal.tsx` (если он используется) — если открыт модалкой, оставить как было или закрыть модалку и переключить вкладку. Уточним при имплементации.

### 3. Эмбеддед-версия `CoursePreview`

Текущий `src/pages/CoursePreview.tsx` — это **полноэкранная** страница с `useParams`, собственным хедером (`SigmaLogo`, кнопка «Назад» через `getAdminAwareBackPath`), на 429 строк через `useCoursePreview`.

Подход: **переиспользовать** компонент, но превратить его в гибрид:
- Извлечь внутренности в новый компонент `src/components/course-preview/CoursePreviewView.tsx`, принимающий `courseId: string` пропом и флаг `embedded?: boolean`.
- Когда `embedded = true`:
  - Скрывать собственный «полноэкранный» хедер (логотип Sigma + кнопка «Назад в админку»).
  - Не использовать `useParams` — `courseId` приходит пропом.
  - Внутренние ссылки (например, на редактор курса) переключают вкладку через коллбэк, а не `navigate`.
- Старый `src/pages/CoursePreview.tsx` остаётся: просто становится тонкой обёрткой `<CoursePreviewView courseId={useParams().courseId!} embedded={false} />`. Это сохранит работающим и прямой URL `/course-preview/:id` (вдруг где-то остался).

### 4. Кнопки «Просмотр» в карточках курсов и других местах

Опционально (предложу, но не делаю обязательным): кнопки «Просмотр» в `CourseCardView`, `CoursesTab`, `CourseDetailsModal` — они открывают курс прямо «по глазу» из списка. Их можно оставить как есть (они ведут на standalone-страницу с кнопкой «Назад» — это норм для сценария «беглый просмотр из списка»), либо тоже переключить на навигацию через таб (`?tab=course-details&courseId=...&subtab=preview`). 

Предлагаю **оставить их как есть** — пользователь жаловался именно на сценарий «я внутри курса, нажал Просмотр и вылетел». Если из списка курсов — там кнопка «Назад» и так возвращает в список нормально.

### 5. Назад из «Просмотра» внутри редактора

Не нужна отдельная кнопка «Назад» — пользователь просто кликает другую вкладку в боковом меню (например, «Редактор» или «Ученики»). Это и есть нативная навигация.
