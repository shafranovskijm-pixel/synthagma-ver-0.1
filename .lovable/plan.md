

# План: переработать вкладку «Документы» ученика и добавить inbox для документов от организации

## Проблемы сейчас

1. **Вкладка «Документы» не приоритезирована.** Видеоидентификация занимает 80% экрана при первом открытии, хотя обычно она проходится один раз. Согласие ПД и загрузка документов уезжают в самый низ.
2. **Нет inbox'а от организации.** В таблице `document_signatures` есть `recipient_user_id` (ученик), статусы `sent/viewed/signed`, но в кабинете ученика **нигде не отображаются** входящие документы — они приходят только письмом со ссылкой `/sign/:token`. Если письмо ушло в спам или ученик уже залогинен — он не узнает о документе. В БД сейчас 0 документов на студентов, потому что нет UI на стороне организации, чтобы массово рассылать ученикам, и нет UI у ученика, чтобы их видеть.
3. **Нет статуса «всё хорошо».** Когда видеоидентификация пройдена, согласие подписано, документы загружены — карточки всё равно занимают экран.

## Что меняется

### 1. Новая структура вкладки «Документы» — два раздела со «свёрткой»

Заменяем текущий вертикальный стек из четырёх карточек на двухсекционную раскладку:

```text
┌─ Требуют действия (3) ─────────────────────────┐
│ • Согласие на обработку ПД      [Подписать →]  │
│ • Загрузить паспорт (СНИЛС, диплом)  [Загрузить] │
│ • Договор на обучение «Группа 24-Б»  [Открыть →] │  ← новое: из inbox
└────────────────────────────────────────────────┘

┌─ Готово ───────────────────────────────────── ▾ ┐  ← свёрнуто по умолчанию
│ ✓ Видеоидентификация (пройдена 14.04.2026)     │
│ ✓ Согласие ПД (подписано 14.04.2026)           │
└────────────────────────────────────────────────┘

┌─ Архив документов ─────────────────────────── ▾ ┐  ← подписанные/загруженные
│ • Договор-оферта (подписан 12.03.2026)         │
│ • Удостоверение о повышении квалификации       │
│ • Скачать копию персональных данных            │
└────────────────────────────────────────────────┘
```

**Логика приоритизации**: всё, что `pendingReasons` отдаёт как незавершённое, рендерится сверху одной строкой с CTA-кнопкой. Полные карточки `<VideoIdentification embedded>`, `<StudentConsentForm embedded>`, `<StudentDocumentsUpload embedded>` открываются модалкой/раскрывашкой по клику на CTA, а не на всю страницу сразу.

**Видеоидентификация** уезжает либо в раздел «Готово» (когда уже пройдена), либо отображается компактной строкой «Требуется идентификация» с кнопкой «Пройти» — клик открывает её в Dialog (он уже умеет в `embedded=false`).

### 2. Inbox: документы на подпись от организации

**Без новых таблиц** — используем существующий `document_signatures`. Добавляем хук `useStudentSignatureInbox`:

```ts
supabase.from("document_signatures")
  .select("id, document_title, document_type, status, sender_name, expires_at, signature_token, organization_id, created_at, signed_at, viewed_at")
  .eq("recipient_user_id", userId)
  .in("status", ["sent", "viewed", "signed", "rejected"])
  .order("created_at", { ascending: false })
```

Раздел в новой вкладке «Документы»:
- **Pending** (`status in ('sent','viewed')`) → попадает в «Требуют действия». Кнопка «Открыть» ведёт на `/sign/:token` (та же страница, что и из письма; если уже залогинен — пропускает шаг identity).
- **Signed/rejected** → в «Архив документов» с датой подписания и кнопкой «Скачать PDF» (`signed_document_path` уже есть в таблице).

**Realtime**: подписываемся на `postgres_changes` по `document_signatures` с фильтром `recipient_user_id=eq.${userId}`. При вставке/обновлении — обновляем счётчик и показываем тост «Новый документ от организации».

**Бейдж**: `pendingDocsCount` в `useStudentProfile` начинает учитывать pending-входящие. Бейдж на табе «Документы» и около аватарки сразу показывает реальную цифру (это уже работает с прошлой итерации).

### 3. Кнопка «Отправить документ ученику» в кабинете организации

Сейчас `SendForSigningDialog` принимает email. Расширяем: при выборе получателя из списка студентов организации заполняем `recipient_user_id` (для inbox), плюс `recipient_email` (для дублирования письмом). На странице студента (`OrgStudentDetail` или `StudentDetailDialog`) добавляем кнопку «Отправить на подпись» — открывает `SendForSigningDialog` с предзаполненными данными ученика.

Это закрывает «двустороннее» направление: организация → ученик. Существующая страница `/sign/:token` уже обрабатывает приём подписи и сохраняет `signed_document_path`.

### 4. Обратное направление: ученик → организация (минимум, без раздувания scope)

Для отправки от ученика в организацию переиспользуем уже существующий механизм **«Уроки типа feedback» + загрузку файлов в `student_documents`**. То есть ученик может:
- **Прикрепить файлы** к своему профилю через `StudentDocumentsUpload` (это работает) → организация видит их в карточке студента (это тоже работает).
- **Отправить заявление/обращение** через раздел «Запросы по ПД» (`StudentDataSubjectRequests` уже есть и работает).

Полноценный «чат документов» (ученик инициирует подписание со своей стороны) — НЕ делаем в этой итерации, это отдельный продукт.

### 5. Состояние «всё в порядке»

Если `pendingReasons.length === 0` и нет входящих документов — наверху вкладки показываем зелёный баннер:
> ✓ Все документы в порядке. Видеоидентификация пройдена, согласия подписаны, документы загружены.

И раздел «Готово» открыт по умолчанию, чтобы пользователь видел, что у него есть.

## Что НЕ делаем

- Не делаем чат-мессенджер «ученик ↔ организация» — для документов хватает inbox + загрузка.
- Не трогаем `/sign/:token` страницу — она уже корректно работает и для писем, и для inbox.
- Не добавляем новых таблиц — `document_signatures` уже всё умеет.
- Не меняем RLS — на `document_signatures` уже есть политика «recipient видит свои» (через token и `recipient_user_id`).

## Риски

- Если студент не залогинен с тем же `user_id`, что в `recipient_user_id` (например, организация отправила на email до создания профиля) — inbox его не покажет, но письмо со ссылкой сработает. Это приемлемо.
- Realtime-подписка на `document_signatures` потребует включения публикации (`ALTER PUBLICATION supabase_realtime ADD TABLE document_signatures`) — это миграция, делается в режиме default.
