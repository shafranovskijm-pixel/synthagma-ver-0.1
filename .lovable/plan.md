

# План: адаптация интерфейса «Продажи» под мобильные

## Проблемы (видны на скриншоте)
1. **Сайдбар продаж** (224px) рендерится на мобиле бок-о-бок с контентом → контент сжат до полоски «Ср» и нечитаем.
2. На самом скриншоте всё ещё видно «Сравнение» — это устаревшая версия в браузере; в коде уже удалено. Дополнительно сделаю принудительный сброс сохранённого `section`, если он невалидный, чтобы при будущих чистках меню пользователь не залипал на удалённой вкладке.
3. Та же проблема в **админ-кабинете продаж** (`SalesSidebar.tsx`) — адаптируем за компанию.
4. Sticky-боковое меню (admin) с `max-h-[calc(100vh-1rem)]` на мобиле тоже мешает.

## Что делаю

### 1. `src/components/organization/sales/OrgSalesManager.tsx`
- Заменяю layout `flex gap-4` + `w-56` сайдбар на адаптивный:
  - **Desktop (md+):** как сейчас — сайдбар слева 224px, контент справа.
  - **Mobile (<md):** сайдбар прячется в выезжающую панель (Sheet из shadcn), сверху появляется кнопка-триггер «Меню разделов» с иконкой текущего раздела и его названием.
- При выборе раздела на мобиле — Sheet автоматически закрывается.
- Защита: если сохранённый/переданный `section` не входит в `AVAILABLE_SECTIONS`, сбрасываю на `overview` (на случай удалённых вкладок типа `comparison`).
- Карточка-баннер «Кабинет менеджера продаж — Beta» делается компактнее на мобиле (меньше padding, текст в 2 строки нормально переносится).
- Баннер «SMTP не настроен» — кнопка «Настроить» уезжает под текст на узких экранах (`flex-col sm:flex-row`).

### 2. `src/components/admin/sales/SalesSidebar.tsx` + место использования
- Аналогичная адаптация: Desktop — sticky-сайдбар, Mobile — Sheet с триггером.
- Уберу `sticky top-2 max-h-[...] overflow-y-auto` на мобиле, оставлю только для md+.
- Найду компонент-родитель (`SalesManager` или похожий в админке), где сайдбар используется внутри `flex`, и добавлю кнопку-триггер для мобилы аналогично.

### 3. Общий компонент-кнопка «Меню разделов»
Внутри `OrgSalesManager` и админ-родителя — одинаковый паттерн: `<Button variant="outline" className="md:hidden w-full justify-between">` с иконкой текущего раздела + chevron. Открывает `<Sheet side="left">` с тем же списком групп/пунктов, что и desktop-сайдбар. Чтобы не дублировать разметку, выношу отрисовку списка пунктов в локальный sub-компонент `SidebarMenu` внутри файла (или общий `SalesSidebarContent`).

### 4. QA на мобильных размерах
После правок проверю в браузере на 375×812 (iPhone), что:
- Контент занимает всю ширину;
- Кнопка «Меню разделов» хорошо видна и кликабельна;
- Sheet корректно выезжает, разделы переключаются и Sheet закрывается;
- Баннеры (Beta, SMTP) корректно переносятся;
- Внутренние страницы (`Обзор`, `КП`, `Канбан`) не уезжают за край — где увижу горизонтальный скролл, поправлю в той же итерации (минимально: `min-w-0` + `overflow-x-auto` для таблиц).

## Файлы

### Правки
- `src/components/organization/sales/OrgSalesManager.tsx` — Sheet-навигация для мобилы, защита от невалидной секции, адаптивные баннеры.
- `src/components/admin/sales/SalesSidebar.tsx` — экспорт внутреннего `SalesSidebarContent`, адаптивные классы.
- Родитель админ-сайдбара (вероятно `src/components/admin/sales/SalesManager.tsx` или аналог — найду точное имя при реализации) — добавить мобильный триггер Sheet.
- При обнаружении горизонтального переполнения внутри секций (Канбан, таблицы КП) — точечный `overflow-x-auto` / `min-w-0` на контейнерах.

### Без изменений
- Логика разделов, данных, RLS, edge-функций — не трогаю.
- Десктоп-вид остаётся идентичным (только классы становятся `hidden md:block` / `md:flex`).

## Что НЕ делаю
- Не переделываю сайдбар на полностью drawer-нав (нижняя таб-навигация и т.п.) — это большая отдельная UX-задача.
- Не правлю общий сайдбар организации (он уже адаптивен через `mem://features/organization/dashboard-navigation-ux`) — только внутренний сайдбар модуля «Продажи».
- Не меняю названия и порядок пунктов меню.
