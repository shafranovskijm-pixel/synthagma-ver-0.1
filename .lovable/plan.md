

# Исправление загрузки курсов: убрать перегрузку базы

## Корневая причина

Индексы уже на месте, но база всё равно таймаутится. Причина — **две параллельные системы загрузки** одновременно бьют по БД:

1. **`useOrganizationDataLoader`** — загружает ВСЁ: курсы (`select *, lessons(count)`), все профили, расшифровку паролей, все зачисления, роли, документы, ФРДО — **8+ тяжёлых запросов** с ретраями (до 3 попыток каждый = до 24 запросов при сбоях)
2. **`useCourses`** — CoursesTab отдельно загружает курсы ещё раз + затем студентов

Итого при открытии страницы `/organization` запускается до **30+ запросов** одновременно, каждый из которых триггерит RLS-функцию `current_organization_id()` (подзапрос к `profiles`) для каждой строки. На маленьком инстансе это вызывает каскадные таймауты.

## Решение

### 1. Оптимизировать `useOrganizationDataLoader` — главный загрузчик
- Заменить `select(*, lessons(count))` на конкретные столбцы (как уже сделано в `fetchCourses`)
- Перенести `get_decrypted_student_passwords` из GROUP 1 в отложенную загрузку (после основного рендера) — это тяжёлый RPC с расшифровкой
- Загружать enrollments + GROUP 2 (roles, docs, frdo) **последовательно после** основных данных, а не в один `Promise.all`

### 2. Убрать дублирование загрузки курсов
- `CoursesTab` использует `useCourses` который делает свой `fetchCourses()` — это **дубль** запроса из `useOrganizationDataLoader`
- Передавать данные курсов из `dataLoader` в `CoursesTab` вместо повторной загрузки, либо наоборот — убрать загрузку курсов из `useOrganizationDataLoader` и полагаться на `useCourses`

### 3. Снизить агрессивность ретраев
- Увеличить задержку между ретраями с 1.5с до 3с
- Уменьшить количество параллельных ретраев — не ретраить всё одновременно

## Файлы
- `src/hooks/useOrganizationDataLoader.ts` — основные изменения: конкретные столбцы, последовательная загрузка тяжёлых данных, отложенная расшифровка паролей
- `src/hooks/useCourses.ts` — возможно убрать дубль или синхронизировать с dataLoader
- `src/api/courses.ts` — без изменений (уже оптимизирован)

## Ожидаемый результат
- При открытии страницы — максимум 3-4 лёгких запроса одновременно вместо 8+
- Курсы появляются за 1-2 секунды
- Тяжёлые данные (пароли, документы, ФРДО) догружаются в фоне
- При таймауте паролей/документов — курсы и студенты всё равно видны
