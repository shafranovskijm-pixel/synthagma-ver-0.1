## Что сделаем сейчас

Свежая база компаний по 3 регионам в CRM менеджера + готовая «телефонно-комментарная» обвязка, чтобы можно было работать прямо сейчас (без живой телефонии — её прикрутим позже, как договаривались).

## 1. Импорт 3 xlsx → `sales_leads`

Файлы `Компании (3/4/5).xlsx` содержат одинаковую структуру: `Название, ИНН, КПП, Адрес, ФИО руководителя, Телефоны, email, Сайт, ОГРН` и т.д.

Шаги (одной server-side операцией, чтобы не зависеть от UI-импортёра):
1. На моей стороне читаю xlsx → CSV (нормализую).
2. Из колонки `Адрес` парсю регион по правилам (в скобках — рабочие примеры):
   - `Новосибирская обл.` → **Новосибирская область**
   - `Самарская обл.` → **Самарская область**
   - `г. Хабаровск` → **Хабаровский край**
   - `Камчатский край`, `Приморский край`, `Республика …` — берём явно.
   - Города-исключения: `г. Москва`, `г. Санкт-Петербург`, `г. Севастополь` — как есть.
3. Из `Телефоны` оставляем **первый** номер (остальные в `notes`), нормализую к `+7XXXXXXXXXX`.
4. Из `email` — первый адрес (остальные в notes).
5. INSERT в `sales_leads`: `org_name, inn, ogrn, region, city, address, phone, email, website, notes, source='excel_import', status='new'`.
6. Дедуп по ИНН (`ON CONFLICT (inn) DO NOTHING`, если индекс есть; иначе предварительный SELECT). Уже имеющиеся ИНН не трогаем.

## 2. UI: разбивка и фильтры по регионам в `/sales`

Правлю `src/components/admin/sales/LeadsManager.tsx`:
- **Чипы регионов** над таблицей: лента кнопок с количеством `Все · Новосибирская область (222) · Хабаровский край (52) · Самарская область (179) · …`. Клик — фильтр. Сейчас селект «Регион» оставлю как fallback для длинных списков.
- **Группировка по регионам**: добавляю переключатель «Список / По регионам». В режиме «По регионам» — аккордеоны по регионам, отсортированные по числу лидов.
- **Видимая кнопка «Позвонить»** в каждой строке + рядом «Комментарий». Никаких изменений в кнопках при наведении — всегда видны.

## 3. Звонок без телефонии (заглушка под будущий API)

Новый компонент `CallActionButton.tsx`:
- Клик → открывает диалог `LogActivityDialog` (он уже есть) с `defaultType='call'`, преф填лит номер.
- Параллельно открывает `tel:+7...` (системный набор номера) — менеджер может звонить с телефона/мобильного, а карточка в CRM сразу готова под итог разговора.
- После сохранения — пишется запись в `sales_lead_activities` с типом `call`, текстом и временем; обновляется `last_contact_at` лида.
- Когда подключим Exolve (план уже одобрен), эта же кнопка будет вызывать WebRTC-звонок — поменяем только `onClick`, контракт `LogActivityDialog` не меняется.

## 4. Комментарии / лиды / задачи — что уже есть, что усиливаем

Сейчас в карточке лида (`LeadsManager → detailLead`) активность сохраняется только если у пользователя есть запись в `sales_managers`. Это и есть причина, почему «комментарий не сохраняется». Правим:
- В `handleAddActivity` для роли `admin` или `sales_manager` — `manager_id = current_user_sales_manager_id ?? auth.uid()`-ассоциированный менеджер. Авто-создаём запись в `sales_managers` для текущего пользователя при первом действии, если её нет (через RPC `ensure_sales_manager_for_current_user`).
- На каждое сохранение активности — обновление `sales_leads.last_contact_at = now()` и, если задана дата следующего контакта, `next_contact_date`.

## 5. Технические детали (для разработчика)

- Импорт делаю через `supabase--insert` пачкой по 500 строк (CSV → JS-объекты), без edge-функции.
- Парсер региона — отдельная утилита `src/utils/parseRussianRegion.ts` (+ юнит-тест на 10–15 кейсов), чтобы UI-импорт `LeadsImportDialog` тоже мог её использовать.
- Регион-чипы: shadcn `Badge` + flex-wrap, активный — primary, остальные — outline. Считаем `count` по `leads`, мемоизирую.
- Кнопка «Позвонить» в строке: `size="sm" variant="ghost"`, `Phone` icon + номер укороченный. `stopPropagation`, чтобы не открывался diff-диалог.
- RPC `ensure_sales_manager_for_current_user()` — SECURITY DEFINER, проверяет роль (`admin` или `sales_manager`), создаёт запись в `sales_managers` с `is_active=true`, возвращает id.

## Что НЕ делаем

- Не подключаю Exolve API (как просили — позже). План `mem://integrations/exolve` уже одобрен.
- Не трогаю «холодную базу» / `sales_companies_db` — импорт сразу в `sales_leads`, чтобы менеджеры видели работу сразу.
- Не создаю новые таблицы — пользуемся существующими.
