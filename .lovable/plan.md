
## Задача
Добавить в админку (раздел «Настройки») пункт **«Медиатека»** с глобальным просмотром всех медиафайлов **по всем организациям** + точное определение «не используется», чтобы можно было безопасно удалять без переспросов.

## Что значит «446 не используется»
Сейчас в `MediaLibraryDialog` (организационный) флаг `isUsed` ставится по простой проверке: ищется ли URL/path файла в полях уроков (`lessons.content`, `lessons.video_url`, `course_documents.file_url` и т.п.) **в рамках одной организации**. Если файл лежит в `course-files/{orgId}/...` и нигде не «вшит» — считается неиспользуемым. Для админки нужна более строгая проверка по **всем таблицам и всем организациям**.

## План

### 1. Новый пункт меню в админке
**Файл:** `src/components/admin/AdminSettingsTab.tsx` (или там, где формируется боковое меню «Настройки» — Тема, Сотрудники, Статистика БД, …).
- Добавить новый пункт **«Медиатека»** с иконкой `FolderOpen` / `Film`, между «Статистика БД» и «Сброс кеша».

### 2. Новая страница/компонент
**Файл (новый):** `src/components/admin/AdminMediaLibrary.tsx`
- Список всех файлов из бакетов `course-files`, `course-videos` (внешний), `presentations`.
- Колонки: миниатюра/иконка, имя, размер, бакет, **организация** (название + ИНН), дата загрузки, бейдж «Используется / Не используется», кнопка «Удалить».
- Фильтры:
  - По организации (select).
  - По типу (видео / документ / изображение).
  - Только неиспользуемые (toggle).
  - Поиск по имени.
- Сортировка: по размеру (по убыв.), по дате, по организации.
- Сводка сверху: «Всего файлов: N · Размер: X ГБ · Не используется: M (Y ГБ можно освободить)».
- Bulk-выбор + кнопка «Удалить выбранные» с подтверждением.

### 3. Edge-функция для строгого аудита использования
**Файл (новый):** `supabase/functions/admin-media-audit/index.ts` (verify_jwt = true, проверка `has_role('admin')`).

Шаги внутри функции:
1. Листинг всех объектов всех бакетов (`course-files`, `presentations`) рекурсивно через storage API + внешний `course-videos` через `get-external-storage-config`.
2. Для каждого файла строит **полный набор «маркеров»**: `path`, `publicUrl`, имя без расширения, UUID из имени.
3. Один SQL-проход (RPC `admin_check_media_usage`, см. п.4) собирает **все ссылки** из:
   - `lessons.content` (JSON-блоки: `video`, `image`, `audio`, `pdf`, `file`, `document`)
   - `lessons.video_url`, `lessons.audio_url`, `lessons.image_url`
   - `course_documents.file_url`
   - `courses.cover_image`, `courses.intro_video_url`
   - `organizations.logo_url`, `organizations.cover_url`
   - `homework_submissions.attachments`
   - `chat_messages.attachments`
   - `webinars.cover_url`, `webinars.recording_url`
4. Для каждого файла → `isUsed = true`, если хоть один маркер найден в этих полях.
5. Возвращает массив `{ path, bucket, size, organizationId, organizationName, isUsed, usedIn: [{ table, id, title }] }`.

### 4. RPC для централизованной проверки
**Миграция:** функция `admin_collect_media_references()` (SECURITY DEFINER, только для `admin`).
- Возвращает плоский набор всех «ссылок на файлы» из перечисленных выше таблиц с `organization_id` и `entity_type/id/title`.
- Edge-функция один раз получает этот набор, строит in-memory индекс и быстро сверяет со списком файлов из Storage — это сильно дешевле, чем десятки SQL-запросов на файл.

### 5. Удаление
- Внутренние бакеты — `supabase.storage.from(bucket).remove([path])` через client админа (RLS уже даёт админу полный доступ).
- Внешний `course-videos` — через ту же логику, что в `useStorageManager` (с `extClient`).
- При удалении неиспользуемого — без warning. Если по какой-то причине помечен как «используется» (защита) — модалка с перечнем мест использования и кнопкой «Всё равно удалить».
- После удаления — локально убрать из списка + обновить сводку.

### 6. Где НЕ трогаем
- `useAuth.tsx`, `OrgDashboardContext`, `CourseDetailsModal` — **не трогаем** (по прошлой договорённости).
- Организационная медиатека (`MediaLibraryDialog`) — без изменений, она уже работает.

## Технически
- Миграция: одна RPC `admin_collect_media_references()`.
- Edge: одна функция `admin-media-audit`.
- UI: один новый компонент + пункт меню.
- Без изменений в auth/RLS, без рисков для входа клиентов.
- Производительность: всё за 1 проход RPC + 1 листинг бакетов; для очень больших объёмов — пагинация по 200 файлов.
