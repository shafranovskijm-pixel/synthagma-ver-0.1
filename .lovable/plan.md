

# План: разделить «Документы» и «Продажи» окончательно + горизонтальная навигация

## Что я увидел в коде

**Дублирование, которое сбивает с толку:**
- В сайдбаре «Документы» сейчас живёт целая группа «Продажи»: КП, Договоры (продажи), Подписания.
- В сайдбаре организации УЖЕ есть отдельная вкладка **«Продажи»** (`OrgSalesManager`), где лежит полноценный CRM-кабинет: Обзор, Задачи, Сделки 360°, Компании, КП, Договоры, Каталог услуг, Шаблоны писем, Рассылки, SMTP.
- Получается, КП и договоры дублируются в двух местах — это и создавало впечатление «всё свалено в кучу».

**Ваше пожелание:** разделить чисто — продажи отдельно (инструменты воронки), документы отдельно (артефакты).

---

## 1. Горизонтальная навигация в «Документах» (вместо длинного вертикального списка)

Меняем сайдбар на **двухуровневую горизонтальную навигацию**:

```text
[ Сводка ] [ Контрагенты ] [ Входящие ] | [ Документы организации ▾ ] [ Подписания ] | [ Конструктор ] [ Корзина ]
                                                    │
                                                    ▼ (под-меню второго уровня появляется только при клике)
                                            [ Программы ] [ Журналы ] [ ФИС ФРДО ]
                                            [ Свидетельства ] [ Дипломы ] [ Удостоверения ]
                                            [ Протоколы АК ] [ Приказы ] [ Документы орг. ] [ Запросы ПД ]
```

- Верхний ряд — **6 крупных корневых пунктов** (горизонтальные «pill»-кнопки).
- При выборе **«Документы организации»** под верхним рядом появляется второй ряд под-вкладок (тоже горизонтально, со скроллом на узких экранах).
- На мобильном — обе линейки горизонтальный скролл с fade-индикатором справа (как уже есть сейчас).
- Состояние выбранной под-вкладки сохраняем в `useDocumentsTab` — id вкладок не меняем, deep-link от KPI/Sales продолжает работать.

**Файлы:** только `DocumentsTab.tsx` — заменяем JSX сайдбара на горизонтальную панель + полосу под-меню для группы `org_docs`. Логика `useDocumentsTab` не трогается.

## 2. Окончательное разделение «Продажи» ↔ «Документы»

**Из «Документов» убираем дубли продаж:**
- Удаляем из `NAV_ITEMS` пункты `proposals` и `sales_contracts` (они и так есть в кабинете «Продажи»).
- **Оставляем «Подписания»** в верхнем ряду «Документов» — это юридический артефакт (журнал доказательств ПЭП), он по смыслу ближе к документам, чем к воронке.
- Из «Продажи» в `OrgSalesManager` КП и Договоры остаются (это рабочее место менеджера). Добавляем в карточках КП/Договоров кнопку «Открыть в Документах» — она уже есть через `documents.deepLink`.

Итого:
- **Продажи** = процесс (воронка, лиды, рассылки, шаблоны, SMTP, КП и договоры в работе).
- **Документы** = артефакты + юр.часть (контрагенты, входящие, журнал подписаний, документы об образовании, корзина).
