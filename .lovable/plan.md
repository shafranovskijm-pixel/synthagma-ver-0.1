## Что выяснил по документации Novofon

Текущий `401 Not authorized` почти наверняка не из-за номера телефона, а из-за авторизации Call API:

- Call API работает через JSON-RPC `https://callapi-jsonrpc.novofon.ru/v4.0`.
- В каждый метод звонка нужен `access_token`.
- `access_token` бывает:
  - постоянный ключ Call API, включённый в настройках пользователя АТС;
  - временный токен, полученный методом `login.user` по логину/паролю.
- IP сервера должен быть добавлен в белый список API, иначе Novofon вернёт ошибку доступа.
- Для звонка с купленного номера нужен именно виртуальный номер в формате `79675551383`, который Novofon должен видеть как ваш `virtual_phone_number`.
- Метод `start.simple_call` подходит для схемы: сначала звонок менеджеру/оператору, потом клиенту.
- `start.employee_call` требует `employee.id` из Data API, то есть сначала нужно подтянуть сотрудников/номера из Data API.

## План исправления

1. **Разделить Call API и старый callback API**
   - Убрать смешение `NOVOFON_API_KEY` как Call API access token.
   - Для Call API использовать отдельные секреты:
     - `NOVOFON_ACCESS_TOKEN` — постоянный Call API token, если он есть;
     - либо `NOVOFON_LOGIN` + `NOVOFON_PASSWORD` — для получения временного токена через `login.user`.
   - Старый `NOVOFON_API_KEY` / `NOVOFON_API_SECRET` оставить только для classic callback fallback.

2. **Добавить автоматическую диагностику Novofon**
   - Создать/доработать backend-функцию проверки настроек.
   - Она будет проверять:
     - есть ли Call API token или login/password;
     - проходит ли `login.user`;
     - виден ли купленный номер `79675551383` как виртуальный номер;
     - доступен ли метод звонка;
     - не заблокирован ли IP whitelist / компонент Call API.
   - Ошибки показывать в интерфейсе понятным текстом: «не добавлен IP», «не включён Call API», «неверный токен», «номер не найден».

3. **Исправить запуск звонка**
   - Для `novofon-call-start` сделать основной путь через `start.simple_call`:
     - `first_call: "operator"`
     - `switch_at_once: true`
     - `virtual_phone_number: "79675551383"`
     - `contact: номер клиента`
     - `operator: номер менеджера`
   - Для тестового звонка не звонить «на себя через себя» как сейчас, а явно использовать операторский номер и тестовый номер, чтобы не упираться в запрет звонка на собственный виртуальный номер.

4. **Добавить понятную панель настройки в продажах/админке**
   - Кнопка «Проверить Novofon» рядом с «Позвонить себе».
   - Показать статус:
     - API подключён / не подключён;
     - купленный номер найден / не найден;
     - что именно нужно включить в ЛК Novofon.
   - Не показывать секреты в интерфейсе.

5. **End-to-end проверка**
   - После реализации проверить вызов backend-функции диагностики.
   - Проверить тестовый звонок до фактического провайдера.
   - Если Novofon всё ещё вернёт `401`, сохранить точный ответ и вывести в интерфейсе конкретную причину для поддержки Novofon.

## Что может потребоваться от вас после внедрения

Если постоянного Call API token сейчас нет, нужно будет добавить один из вариантов:

- постоянный `NOVOFON_ACCESS_TOKEN` из настроек пользователя АТС;
- либо `NOVOFON_LOGIN` и `NOVOFON_PASSWORD` пользователя АТС, у которого включён Call API.

Также в ЛК Novofon нужно проверить whitelist IP: для теста можно добавить `0.0.0.0/0`, а потом заменить на фактический IP backend-функций, если Novofon его покажет в ошибке.
