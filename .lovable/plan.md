
Что нашёл:
- У ВЦОТ курсы в базе есть: 35 курсов, 555 уроков, 367 зачислений. То есть проблема не в данных.
- В логах видно реальную причину: запрос списка курсов иногда падает по таймауту `57014 canceling statement due to statement timeout`.
- Дополнительно есть UI-баг: вкладка курсов воспринимает пустой массив `[]` как «данные уже загружены», поэтому вместо лоадера показывает пустой экран/empty state.

Почему это выглядит нестабильно:
1. Основной запрос курсов слишком тяжёлый: он тянет `lessons(count)` прямо в списке курсов.
2. В `useCourses` проверка `!!initialCourses` считает пустой массив валидной предзагрузкой.
3. В итоге при первом таймауте пользователь видит «курсов нет», хотя они просто ещё не догрузились или пришли со второй попытки.

План исправления:
1. Облегчить загрузку списка курсов
- В `src/hooks/useOrganizationDataLoader.ts` убрать `lessons(count)` из основного запроса курсов.
- В `src/api/courses.ts` сделать то же самое для `fetchCourses`.
- Количество уроков загружать отдельным лёгким запросом по `lessons` и собирать map `course_id -> count`.
- Применять этот map после получения списка курсов, как уже сейчас отдельно догружаются счётчики студентов.

2. Исправить логику «предзагруженных» курсов
- В `src/hooks/useCourses.ts` добавить явный флаг вроде `preloadedReady`.
- Не считать `initialCourses: []` признаком готовых данных.
- Пока родительский загрузчик ещё работает, не показывать empty state и не пропускать fetch.

3. Передать корректный статус загрузки в CoursesTab
- Из `useOrganizationDataLoader` пробросить `isLoadingCourses` наружу через `useOrganizationDashboard`.
- В `src/components/organization/tabs/CoursesTab.tsx` вызывать `useCourses` с пониманием: данные либо действительно готовы, либо ещё грузятся.
- Показывать loader/skeleton, а не блок «Создайте первый курс», пока идёт первый запрос или retry.

4. Сделать поведение устойчивым при сбоях
- Если данные уже были показаны раньше, не затирать их пустым состоянием во время повторной загрузки.
- При ошибке показывать именно ошибку загрузки/повтор, а не empty state.
- Для таймаутов можно добавить более понятный текст вроде «Курсы загружаются дольше обычного, пробуем ещё раз».

Файлы, которые нужно менять:
- `src/hooks/useOrganizationDataLoader.ts`
- `src/api/courses.ts`
- `src/hooks/useCourses.ts`
- `src/hooks/useOrganizationDashboard.ts`
- `src/components/organization/tabs/CoursesTab.tsx`

Технически как реализую:
- Вынесу лёгкий helper для подсчёта уроков по массиву `courseIds`.
- Унифицирую загрузку курсов, чтобы и дашборд, и вкладка курсов работали по одной логике.
- Разделю состояния:
  - `loading` — первый запрос ещё идёт
  - `ready` — данные получены, даже если список пустой
  - `error` — ошибка после retry
- Empty state буду показывать только когда `ready && courses.length === 0`.

Как проверю:
- Холодная загрузка `/organization` для ВЦОТ.
- Несколько обновлений страницы подряд.
- Быстрый переход на вкладку «Курсы» сразу после входа.
- Проверка, что у организации с реально пустым каталогом empty state остаётся корректным.
- Проверка, что у ВЦОТ список стабильно появляется и не мигает пустым экраном.
