
## Проверка фоновой загрузки видео

Пользователь хочет убедиться, что:
1. Видео реально загружается в фоне, когда переключаешь урок;
2. Прогресс не сбрасывается;
3. Приходит уведомление о завершении (toast + звук + запись в `org_notifications`);
4. Можно свободно переключаться между уроками во время загрузки.

## Что проверю в коде

1. `src/contexts/BackgroundUploadsContext.tsx` — провайдер уже есть: глобальный стейт, `beforeunload`-гард, toast + `playUploadCompleteSound`, запись в `org_notifications`. Это база.
2. `src/hooks/useLessonEditor.ts` — текущий аплоад через `useExternalStorageWithProgress` живёт **внутри** хука редактора урока. Когда диалог редактирования закрывается или выбирается другой урок, хук размонтируется → `AbortController` срабатывает → загрузка падает. Это противоречит цели «фоновой загрузки».
3. Нужно проверить, кто вызывает `handleVideoUpload` и связан ли он с `BackgroundUploadsProvider` (`registerUpload` / `updateUpload` / `finishUpload`). Скорее всего — нет, поэтому при переключении урока загрузка прерывается, уведомления не приходят.
4. Проверить `useExternalStorageWithProgress` — где живёт `XHR`/TUS-инстанс, отменяется ли он при unmount.
5. Проверить, где монтируется `BackgroundUploadsProvider` (App.tsx / main.tsx) и есть ли UI-трей активных загрузок.

## Гипотеза (которую подтвержу чтением)

Текущая реализация **НЕ фоновая**: апдоад привязан к жизненному циклу `LessonEditorDialog`. Когда пользователь:
- закрывает диалог урока,
- кликает на другой урок,
- редактор размонтируется → `abortUpload` → загрузка прерывается → никакого toast’а и никакого уведомления.

`BackgroundUploadsProvider` существует, но `useLessonEditor.handleVideoUpload` им **не пользуется**.

## План работы

1. Прочитать `useLessonEditor.ts`, `useExternalStorageWithProgress.ts`, `App.tsx`, диалог редактора урока, UI-трей (если есть).
2. Подтвердить/опровергнуть гипотезу.
3. Если подтвердится — переписать `handleVideoUpload` так, чтобы:
   - старт загрузки регистрировался через `registerUpload(...)` глобального контекста;
   - сам XHR/TUS жил вне диалога (в синглтон-сервисе или в провайдере), чтобы не отменялся при unmount;
   - прогресс отдавался через `updateUpload`;
   - финал — через `finishUpload` (toast + звук + `org_notifications` уже встроены);
   - ошибка — через `failUpload`;
   - при успехе — записывать `videoUrl` в `lesson.content` напрямую через Supabase, не дожидаясь, пока пользователь снова откроет урок.
4. Добавить визуальный трей текущих загрузок (если его нет) в шапке кабинета организации, чтобы пользователь видел статус.
5. End-to-end проверка: открыть урок → выбрать видео → переключить на другой урок → дождаться завершения → убедиться, что:
   - toast пришёл,
   - звук сыграл,
   - запись в `org_notifications` создана,
   - в исходном уроке `content` обновился.
