# План исправления ошибок входа

## Что исправлю
1. Усилю перехват сетевых запросов в `src/utils/proxyFetch.ts`
   - считать сломанным не только прокси-ответ HTML, но и прямой ответ `522`/HTML от auth;
   - при таком ответе автоматически пробовать резервный канал вместо того, чтобы оставлять UI с ошибкой парсинга JSON;
   - аккуратно обработать случай, когда оба канала недоступны, чтобы не было циклов и «залипания» режима.

2. Нормализую сообщения об ошибках в `src/utils/handleSupabaseError.ts`
   - добавить отдельное распознавание HTML/Cloudflare/`522`/`Unexpected token '<'`;
   - возвращать понятные сообщения вроде «Сервис временно недоступен» или «Проблема с соединением, попробуйте резервный канал», а не сырой текст `json() on Response`.

3. Починю UX на странице логина `src/pages/Login.tsx`
   - не показывать пустой toast при невалидном HTML-ответе;
   - выводить человекочитаемую причину и подсказку, что можно открыть `/connection-check`;
   - при временной сетевой деградации не маскировать её под «неверный логин или пароль».

4. Дополнил бы экран диагностики `src/pages/ConnectionCheck.tsx`
   - показать явный статус канала для auth;
   - оставить быстрый сброс резервного канала и повторную проверку, чтобы пользователь мог восстановиться без ручной очистки storage.

## Ожидаемый результат
- Вход перестанет падать с `Unexpected token '<'`.
- При сетевых сбоях auth запросы будут мягко переключаться на рабочий канал, если он доступен.
- Если сервис недоступен с обеих сторон, пользователь увидит нормальное сообщение об ошибке вместо сырого технического текста.
- Ошибки «не видно базы данных / не могу войти как админ» будут диагностироваться и отображаться корректно.

## Технические детали
- Источник текущей ошибки уже подтверждён: запрос `POST /auth/v1/token?grant_type=password` получает HTML-страницу Cloudflare `522`, а клиент пытается распарсить её как JSON.
- Hosted backend со своей стороны доступен, значит проблема на транспортном уровне/маршрутизации канала, а не в правах доступа к данным.
- Кодовые точки изменения: `src/utils/proxyFetch.ts`, `src/utils/handleSupabaseError.ts`, `src/pages/Login.tsx`, при необходимости `src/pages/ConnectionCheck.tsx`.
