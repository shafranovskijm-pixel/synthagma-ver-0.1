

# План: «умное» автозаполнение в санитайзере ФРДО + быстрая выгрузка

## Проблема

На скриншоте — 58 строк помечены как «без обязательных полей», хотя ФИО, СНИЛС, паспортные данные в файле есть. Причина: в исходнике пуст **«Регистрационный номер»** (колонка 9), который в нашем коде помечен `required: true`. Из-за этого предупреждение пугает менеджера, хотя ФИС ФРДО спокойно принимает значение `"нет"` или порядковый номер строки в этом поле — ровно как в «Серия документа», где у нас уже стоит `defaultValue: "Нет"`.

## Что меняем

### 1. Автозаполнение «мягких» полей (`src/utils/frdoFileSanitizer.ts`)

В `DPO_META` и `PO_META`:

- **«Регистрационный номер»** (`DPO_HEADERS[8]` / `PO_HEADERS[8]`) — снимаем `required: true`, добавляем `defaultValue: "нет"` и новый kind `"auto_reg_number"`. Логика: если в источнике пусто — подставить `"нет"` (по аналогии с «Серия документа»). Опционально — порядковый номер строки, но клиенты ФРДО подтверждают, что строка `"нет"` принимается.
- **«Серия документа»** — уже работает, оставляем.
- **«Отчество»** — уже не required, оставляем.
- **«Программа / вид программы»** (DPO[9] / PO[9]) — добавляем `defaultValue` из строки заголовка типового документа («Программа повышения квалификации» для DPO, «Программа профессиональной подготовки …» для ПО), если пусто.
- **«Год начала / окончания обучения»** — если пусто, но есть «Дата выдачи» — берём год из неё (новый kind `"auto_year"` с источником-указателем).

### 2. «Обязательные по-настоящему» (остаются `required: true`)

Только то, без чего файл реально отклоняется ФИС ФРДО:
- ФИО (Фамилия + Имя)
- Дата рождения
- Пол
- СНИЛС
- Номер документа
- Дата выдачи документа
- Наименование программы

Этот список и будет отображаться в плашке «не хватает обязательных полей» — и счётчик упадёт с 58 строк до реальных проблемных (скорее всего 0).

### 3. Добавляем `auto_reg_number` в `sanitizeByKind`

```
case "auto_reg_number":
  const t = sanitizeText(raw);
  if (!t.value) return { value: "нет", fixed: true, reason: "Регистрационный номер не указан — подставлено 'нет'" };
  return t;
```

### 4. UI-улучшения (`FrdoFileSanitizerDialog.tsx`)

- **Автоскачивание + переход к шагу 3.** Если после обработки `missingRequiredRows === 0`, показываем большую зелёную плашку «Файл готов» и **крупную кнопку «Скачать чистый файл»** в центре (вместо двух мелких справа). Превью убираем под раскрывающийся блок «Показать превью первых 20 строк», чтобы кнопка скачивания была сразу на виду.
- **Превью: горизонтальный скролл по всем 35/41 колонкам.** Сейчас показываются только первые 12 колонок — поэтому пользователь не видит, что «Регистрационный номер» автозаполнен. Делаем `previewCols = headers.length` (показываем все), оставляя `overflow-x-auto` — пользователь сможет проскроллить и убедиться, что всё на месте.
- **Информер «что мы автозаполнили».** Маленькая бирюзовая плашка над превью: «Автозаполнено: Регистрационный номер → "нет" в 58 строках, Серия документа → "Нет" в 58 строках. Если у вас есть свои значения — они сохранены».

### 5. Автодетект «Свидетельство о профессии…»

В превью клиента видно, что «Вид документа» = «Свидетельство о профессии…» — значит auto-detect уже корректно сработал на ПО (`33/35` колонок распознано). Оставляем как есть.

## Технические детали

- **Файлы (правка):**
  - `src/utils/frdoFileSanitizer.ts` — новый kind `auto_reg_number`, изменение метаданных DPO_META/PO_META, расширение списка дефолтов.
  - `src/components/organization/FrdoFileSanitizerDialog.tsx` — крупная зелёная CTA при 0 пропусков, раскрывающееся превью, информер автозаполнений, показ всех колонок в превью.
  - `src/utils/__tests__/frdoFileSanitizer.test.ts` — добавляем тесты на `auto_reg_number` (пусто → "нет", своё значение → сохраняется).
- **Без изменений:** `frdoExcelExport.ts`, `FRDOManager.tsx`, `FeatureFRDO.tsx`, БД, схема.
- **Обратная совместимость:** существующие выгрузки по студентам не затрагиваются — изменения только в логике санитайзера-перепаковщика.

## Что НЕ делаем

- Не пытаемся восстановить ФИО/СНИЛС/дату рождения через ИИ — если этих полей реально нет, оставляем пустыми и предупреждаем.
- Не сохраняем загруженный файл в БД (как и было — обработка локально).
- Не меняем эталонный шаблон ФРДО.
