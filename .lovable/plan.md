
Проблема найдена: это не “случайный редирект”, а гонка между регистрацией и обновлением роли.

### Почему кидает в кабинет ученика

Сейчас поток такой:

```text
signUp
→ триггер handle_new_user создаёт роль student
→ create_organization
→ upgrade_to_organization_role
→ navigate("/organization")
```

Но параллельно `useAuth` успевает прочитать `user_roles` раньше, чем роль обновилась, и кэширует `student` в `localStorage`. После этого:

- `RegisterOrganization` делает `navigate("/organization")`
- `ProtectedRoute` видит `userRole === 'student'`
- и перекидывает на `/student`

Дополнительно проблему усиливает то, что `refreshUserRole()` в `useAuth` зависит от `user` из контекста. В момент сразу после `signUp` этот `user` может быть ещё не обновлён, и принудительное обновление роли фактически не срабатывает.

### Что нужно изменить

#### 1. Укрепить обновление роли в `src/hooks/useAuth.tsx`
- Изменить `refreshUserRole`, чтобы он принимал `userId` параметром, а не полагался только на `user` из контекста.
- В `fetchUserRole` убрать опасный fallback `setUserRole('student')` при временной ошибке чтения роли.
- Вместо этого:
  - сохранять текущую роль, если она уже есть, или
  - оставлять `null` и повторять чтение.
- По возможности читать роль через RPC `get_user_role`, а не через прямой `select`, чтобы убрать лишнюю зависимость от клиентского состояния.

#### 2. Исправить поток в `src/pages/RegisterOrganization.tsx`
После `upgrade_to_organization_role`:
- вызывать `refreshUserRole(authData.user.id)`;
- делать короткую ограниченную проверку, что роль реально стала `organization`;
- только после подтверждения роли выполнять `navigate("/organization", { replace: true })`.

То есть:

```text
upgrade role
→ force refresh by authData.user.id
→ confirm role === organization
→ navigate to /organization
```

А не просто “подождать 500 мс и надеяться”.

#### 3. Убрать неправильный fallback на student
Если роль сразу не прочиталась:
- не считать пользователя студентом по умолчанию;
- не давать `ProtectedRoute` мгновенно уводить его на `/student` в момент после регистрации организации.

Лучше кратко держать состояние “роль загружается”, чем отправлять человека в чужой интерфейс.

#### 4. Подправить авто-редирект на самой странице регистрации
В `RegisterOrganization.tsx` сейчас есть логика:

```ts
if (user && !loading && !isRegistering) navigate("/organization")
```

Её нужно сделать ролевой:
- organization → `/organization`
- admin → `/admin`
- company → `/company`
- student → `/student`

Иначе страница регистрации организации сама по себе ведёт себя слишком грубо для любого залогиненного пользователя.

### Файлы для правки

- `src/hooks/useAuth.tsx`
- `src/pages/RegisterOrganization.tsx`

### Ожидаемый результат

После исправления новый сценарий будет таким:

```text
Регистрация организации
→ создаётся аккаунт
→ создаётся организация
→ роль подтверждённо меняется на organization
→ только потом открывается /organization
```

И пользователя больше не будет кидать в кабинет ученика из-за промежуточной роли `student`.

### Что проверить после внедрения

1. Регистрация новой организации из чистой сессии.
2. Медленный сценарий: роль обновляется не мгновенно.
3. Повторный вход сразу после регистрации.
4. Обновление страницы после регистрации.
5. Что обычный студент больше не попадает в `/organization`, а организация — в `/student`.
