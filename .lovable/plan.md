
Подтверждаю: проблема не закрыта полностью.  
По коду и проверке видно, что актуальная версия уже содержит «глазок» и новые данные, но в предпросмотре редактора может подхватываться старый клиент.

Что уже установлено:
- В `src/pages/Login.tsx` «глазок» есть (UI актуальный).
- На опубликованном URL тоже рендерится актуальный экран.
- Слабое место — `src/main.tsx`: в preview-режиме есть ранний `return` после очистки кеша, из-за чего не проходит нормальный version-check и не делается контролируемый reload для новой сборки.

План исправления:

1) Переписать bootstrap обновления клиента в `src/main.tsx`
- Убрать ранний выход для preview.
- Для preview и production использовать единый сценарий:
  - проверка версии сборки,
  - очистка SW/cache,
  - одноразовый принудительный reload при смене версии.
- Добавить защиту от циклических перезагрузок через `sessionStorage` флаг с привязкой к версии.

2) Усилить принудительное обновление интерфейса (ручной фолбэк)
- Вынести общий helper (например `src/utils/forceClientRefresh.ts`) для:
  - unregister service workers,
  - очистки Cache Storage,
  - controlled hard reload.
- Подключить его в UI кнопках, чтобы можно было «обновить интерфейс сейчас» без админских SQL/ручных действий.

3) Добавить кнопку локального восстановления на экране входа
- В `src/pages/Login.tsx` добавить заметную кнопку/ссылку «Обновить интерфейс».
- Это позволит пользователю, который застрял на старом клиенте, сразу перейти на свежий UI.

4) Оставить централизованный массовый сброс кеша, но сделать его надежнее
- В `src/components/admin/AdminSettings.tsx` перевести кнопку «Сбросить кеш у всех» на тот же общий helper-подход и добавить понятный статус «обновление применится при следующем входе/перезагрузке».

Технические детали:
- Ключи версий: использовать `__BUILD_TIMESTAMP__` как основной источник версии клиента.
- Логика reload: только 1 раз на новую версию (чтобы не было бесконечного цикла).
- Preview-специфика: больше не пропускать version-check в ветке `isPreview`.

Проверка после внедрения:
1. Открыть проект в редакторе Lovable на `/login` и убедиться, что «глазок» отображается сразу.
2. Повторно открыть предпросмотр (новая вкладка/перезапуск) — должна загружаться та же актуальная версия.
3. Нажать «Обновить интерфейс» на login-странице и проверить, что UI после reload остается актуальным.
4. Проверить, что нет reload-loop (страница не перезагружается бесконечно).
