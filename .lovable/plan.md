
## Что нужно сделать

В карточке ученика (форма редактирования данных ФРДО) сейчас:
- Пол — только «Муж/Жен», без телефона.
- Гражданство — обычное текстовое поле, куда всегда «прибит» код `643` (Россия).
- Телефона нет вообще — а он нужен для связи и подстановки в документы.

Задача — добавить телефон и пол в карточку ученика, а гражданство сделать полноценным справочником (ОКСМ) с поиском.

## Что появится в интерфейсе

**Карточка ученика (диалог редактирования данных ФРДО, вкладка «Личные»):**

1. **Телефон** — новое поле `+7 ___ ___-__-__` с маской, сохраняется в `profiles.phone`. Показывается и в общей карточке ученика (диалог «Детали ученика»), редактируется в обоих местах.
2. **Пол** — остаётся селект «Мужской / Женский», но перестаёт молча оставаться пустым: если отчество есть — подставляется автоматически (уже работает), если нет — подсвечивается как «не указан».
3. **Гражданство** — вместо голого инпута с `643` появляется **комбобокс с поиском по всему справочнику ОКСМ** (~250 стран). Пользователь вводит «Каз…», видит «Казахстан (398)», выбирает → в базу пишется код `398`, в UI показывается «Казахстан». По умолчанию для новых записей остаётся Россия (643), но её теперь тоже видно как выбранное значение, а не как «магическое число».

## Классификатор ОКСМ

Скачаем официальный справочник ОКСМ (Общероссийский классификатор стран мира, действующая редакция) и положим в проект как статический JSON: `src/constants/oksm.ts`. Источник — открытые данные Росстандарта / classifikators.ru (проверенный CSV). Формат: `{ code: "643", nameShort: "Россия", nameFull: "Российская Федерация", alpha2: "RU", alpha3: "RUS" }`. ~250 записей, ~30 КБ — грузится один раз.

Отдельного справочника в БД не будет — это статичный список, он практически не меняется. Если Росстандарт когда-то обновит — просто обновим файл.

## Что меняется в коде

- **Новый файл** `src/constants/oksm.ts` — массив всех стран ОКСМ.
- **Новый компонент** `src/components/organization/CitizenshipCombobox.tsx` — на базе `Command` (shadcn), с поиском по имени/коду.
- **FRDOExportDialog.tsx** — заменить `Input` для гражданства на `CitizenshipCombobox`. Добавить рядом поле «Телефон» (с маской, читается/пишется в `profiles.phone`).
- **useFRDOManager.ts** — при загрузке подтягивать `profiles.phone`, при сохранении — обновлять его отдельным `update` по `profiles`.
- **StudentDetailsDialog** (общая карточка ученика) — добавить отображение телефона рядом с email, и кнопку «Редактировать» (или инлайн-редактирование), чтобы поле можно было править и без открытия формы ФРДО.
- **Проверки заполненности ФРДО** (`useFRDOManager` → `getFrdoStatus`) — телефон в обязательные поля ФРДО **не** добавляем (в шаблонах ФИС ФРДО его нет), но пустой пол и пустое гражданство считаем как «не заполнено» (пол уже так, гражданство добавим — сейчас проверки нет, потому что оно всегда «643»).

## Что НЕ меняется

- Схема таблиц не трогается: `profiles.phone` и `student_frdo_data.citizenship_code`/`gender` уже существуют.
- Логика генерации Excel для ФИС ФРДО не меняется — она уже пишет `citizenship_code` в нужную колонку. Просто теперь туда будет попадать не только `643`.
- Дизайн-система, стили, темы — без изменений (только новые поля в уже существующих формах).

## Технические детали

- Комбобокс использует существующие `Command`, `Popover` из shadcn, tailwind-токены проекта.
- Маска телефона — уже есть утилита `phoneParser.ts`, переиспользуем.
- Валидация: код ОКСМ = 3 цифры, `zod`-схема в форме сохранения.
- Обновление `profiles.phone` — отдельным `supabase.from('profiles').update({ phone }).eq('user_id', ...)`, RLS уже разрешает организации редактировать своих учеников.
