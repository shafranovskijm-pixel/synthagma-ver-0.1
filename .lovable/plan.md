
# Исправить падение `/student/profile` в режиме «Войти как ученик»

## Что реально сломано
Ошибка не в самом impersonation-режиме, а в порядке хуков внутри `src/pages/StudentProfile.tsx`.

Сейчас компонент:
1. вызывает часть хуков сверху,
2. потом делает ранний `return` при `isLoading`,
3. а уже ниже этого `return` объявляет ещё `useQuery` (`consentCount`, `docsNeeded`).

Из-за этого на одном рендере React видит один набор хуков, а на следующем — больше, поэтому и падает с:
`Rendered more hooks than during the previous render`.

## Что нужно изменить
### 1) Починить порядок хуков в `StudentProfile.tsx`
Перенести все хуки наверх компонента, до любых `return`:
- `useQuery` для `consentCount`
- `useQuery` для `docsNeeded`
- любые вычисления, завязанные на хуки, оставить после объявления всех хуков

То есть структура должна быть такой:
```text
state/useEffect/useCallback/useQuery
state/useEffect/useCallback/useQuery
state/useEffect/useCallback/useQuery
...
if (isLoading) return ...
return JSX
```

### 2) Оставить загрузку безопасной
Для нижних запросов оставить `enabled`, чтобы они не стреляли раньше времени:
- `enabled: !!effectiveUserId`
- при необходимости для орг-зависимых данных использовать `profile?.organization_id` внутри queryFn, как уже сделано

### 3) Доделать режим просмотра ученика админом
Раз уж эта страница открывается в режиме просмотра:
- заблокировать редактирование профиля в admin-view
- скрыть/disabled:
  - сохранение профиля
  - смену email
  - смену пароля
  - загрузку аватара
  - переключатели уведомлений

Сейчас часть этого логически задумана, но UI в `StudentProfile.tsx` ещё не полностью защищён.

После исправления:
