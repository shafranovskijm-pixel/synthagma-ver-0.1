# Откат AI-проверки и улучшение её UX

## Главное (можно успокоиться)

**AI-проверка НИЧЕГО не меняет в курсе.** Я проверил и хук `useCourseReview`, и edge-функцию `review-course` — она только **читает** уроки/тесты и возвращает текстовые рекомендации в диалог. Никаких записей в БД (`courses`, `lessons`, `test_questions`) она не делает. То есть откатывать нечего — курс не пострадал.

То, что вы видели после нажатия — это просто список найденных замечаний (законодательство / тесты / ошибки / предложения). Они отображаются в окне `CourseReviewDialog`, и единственные действия там — «Отклонить» / «Отклонить все», которые тоже только скрывают карточки в диалоге, а курс не трогают.

## Что хочется улучшить (предложение)

Сейчас неудобно две вещи:

1. После закрытия диалога замечания пропадают — непонятно, что AI «нашёл».
2. AI только советует словами, нельзя одной кнопкой применить правку (например, исправить формулировку вопроса теста).

И отдельно — у курса вообще нет истории версий, что страшно при любых массовых правках (не только AI).

## План (3 части, можно выбрать любые)

### Часть 1. Подтверждающий popup перед запуском AI-проверки
Маленькое окно «AI просто проанализирует курс, никаких изменений не вносится. Запустить?» — чтобы случайное нажатие не пугало. Плюс рядом с кнопкой подсказка-tooltip «Только анализ, курс не меняется».

### Часть 2. Применение замечаний по одному (главная фича)
В каждой карточке `FindingCard` рядом с «Отклонить» добавить кнопку **«Применить»** (только для замечаний типа `test` и `error`, где у AI есть конкретная правка):

- AI должен возвращать в `ReviewFinding` доп. поля `target` (id урока/вопроса) и `patch` (новое значение поля).
- При клике «Применить» — обновить запись в БД (`test_questions.question`, `test_questions.options`, `lessons.content` и т.п.) и пометить замечание как применённое (зелёная галочка).
- Для `legislation` и `suggestion` оставляем только текстовый совет (там нет однозначного машинного патча).

Edge-функция `review-course` дорабатывается так, чтобы через tool-calling возвращала структурированный `patch`.

### Часть 3. История версий курса (страховка от ЛЮБЫХ правок)
Добавить таблицу `course_snapshots` и автоматически делать снимок курса:
- перед массовыми операциями (AI-проверка с применением патчей, импорт, AI-генерация уроков),
- по кнопке «Сохранить версию» в шапке конструктора.

Снимок = JSON всех уроков + тестов + настроек. Хранится 30 дней (как корзина документов).

Новая вкладка в конструкторе **«История версий»** со списком:
```text
27 апр 14:32 · Перед AI-проверкой         [Просмотр] [Восстановить]
27 апр 12:10 · Ручное сохранение          [Просмотр] [Восстановить]
26 апр 09:45 · Перед AI-генерацией уроков [Просмотр] [Восстановить]
```
«Восстановить» откатывает уроки/тесты к выбранному снимку (с подтверждением).

## Технические детали

**БД (миграция):**
```sql
create table public.course_snapshots (
  id uuid primary key default gen_random_uuid(),
  course_id uuid not null references courses(id) on delete cascade,
  organization_id uuid not null,
  created_by uuid,
  reason text,           -- 'manual' | 'before_ai_review' | 'before_ai_generate' | 'before_import'
  payload jsonb not null, -- { course, lessons[], test_questions[], course_documents[] }
  created_at timestamptz default now()
);
-- RLS: organization members только своей организации; admins — все.
-- Cron daily: delete where created_at < now() - interval '30 days'.
```

**Frontend:**
- `useCourseSnapshots.ts` — `createSnapshot(reason)`, `listSnapshots(courseId)`, `restoreSnapshot(id)`.
- `CourseVersionsDialog.tsx` — таблица версий + просмотр diff (кратко: «Уроков 32 → 30, вопросов теста изменено: 4»).
- В `CourseBuilder.tsx` — пункт меню «История версий» рядом с «AI проверка».
- В `useCourseReview.ts` — поле `patch` в `ReviewFinding`, метод `applyFinding(id)`, перед первым применением вызывать `createSnapshot('before_ai_review')`.

**Edge-функция `review-course`:**
- Перевод GigaChat-вызова на tool-calling со схемой findings, где для типов `test`/`error` обязательны поля `target_id` и `patch`.
- Добавить серверный rate-limit (10/мин на пользователя) — у нас уже есть паттерн.

**Безопасность:**
- `restoreSnapshot` доступен только пользователям с правом `courses.manage` (через `useStaffPermissions`).
- Аудит-лог в `role_audit_log` или новой `course_audit_log`.

## Что НЕ входит в план
- Не делаем «отмену по Ctrl+Z» на каждое поле — слишком сложно; снимков по событиям достаточно.
- Не диффим JSON визуально построчно — только сводка.

## Вопрос к вам
Делаем все 3 части сразу или поэтапно? Я бы предложил порядок: **сначала Часть 3 (История версий)** — это страховка от любых катастроф, потом Часть 2 (применение замечаний), потом Часть 1 (popup-предупреждение).
