### Что найдено (по приоритету)

#### A. Критичные проблемы безопасности (Supabase Linter — 14 WARN)

1. **Permissive RLS policies (`USING (true)` или `WITH CHECK (true)`) на 6 таблицах для UPDATE/DELETE/INSERT.** Это потенциальный путь привилегий. Найду конкретные политики через `pg_policies` и переведу их на проверку `has_role` / `current_organization_id()`.
2. **4 публичных бакета storage позволяют листинг всех файлов** (broad SELECT на `storage.objects`). Это даёт возможность сторонним скачать список объектов. Сужу политику до `bucket_id IN (...)` + конкретный `name` префикс/owner.
3. **Расширение в схеме `public`** (вероятно `pg_trgm` судя по функциям). Перенесу в `extensions` схему.
4. **Function Search Path Mutable** — у части функций нет `SET search_path = public`. Добавлю.
5. **Leaked Password Protection выключен** — это инфраструктурная настройка Supabase Auth. Включу через `cloud--configure_auth`.

#### B. Архитектурные узкие места

6. **`src/_archived/` (29 файлов, 419 KB)** — мёртвый код в дереве. Может попадать в анализ типов/линт. Удалю папку целиком (она уже не используется маршрутизацией).
7. **Дубликат компонента `ProfileTab.tsx`** — два разных файла с одинаковым именем (`organization/tabs/` и `organization/student-detail/`). Это мина: легко импортировать не тот. Переименую `tabs/ProfileTab.tsx` → `tabs/OrgProfileTab.tsx` с обновлением импортов.
8. **`types.ts` — 7528 строк** (это нормально, генерируется), но ещё **15 файлов > 500 строк** — кандидаты на разбиение. В рамках этого прохода **не дроблю** (risky), а помечу в плане-памятке для будущих рефакторингов. Исключение — `RichTextEditor.tsx` (834) и `MediaLibraryDialog.tsx` (568): они активно меняются и достойны рефакторинга, но это отдельная задача.
9. **210 запросов `select('*')`** — раздувают трафик, особенно по `lessons.content` (jsonb) и `courses`. Сделаю **точечный фикс на 5 самых горячих местах** (списки курсов/уроков/студентов), где `*` тащит тяжёлые поля. Полный аудит 210 мест — отдельная большая задача.
10. **196 вызовов `.single()` против 112 `.maybeSingle()`.** `.single()` бросает ошибку при 0 строках и грязнит логи. Переведу на `.maybeSingle()` в местах, где «нет записи» — нормальная ситуация (lookup профиля, настройки, опциональные расширения). **Не везде** — там, где запись обязана быть, оставлю.

#### C. Качество кода

11. **606 `: any`** — высокая цифра. Не пытаюсь убрать всё (нереально за один проход). Уберу `: any` в **публичных интерфейсах хуков** (`useStudentDetailCard`, `useCourseBuilder`, `useOrgDashboard` и т. п.) — это сразу даст автодополнение и ловит ошибки.
12. **9 `useEffect(..., [])` с пустым массивом зависимостей** — обычно безопасно, но проверю: в 4 из них есть подписки на `supabase.channel` без cleanup → утечка каналов. Добавлю `return () => supabase.removeChannel(channel)`.
13. **`new Date()` в 92 местах внутри `src/components`** — потенциальные ре-рендеры. Точечно вынесу в `useMemo`/мемоизацию для топ-3 самых перерисовываемых компонентов (списки уроков, журналы, дашборд).

#### D. Производительность бандла

14. **Тяжёлые либы в общем чанке:** `ffmpeg/util` (~25 MB), `three.js + drei` (~5 MB), `pdfjs-dist` (~3 MB), `exceljs`, `mammoth`, `html2canvas`, `jspdf`, `livekit-client`, `docx-templates`. Многие уже под `lazyWithRetry` (81 место использует), но не все. Проверю и обеспечу **динамический импорт на уровне функции**, а не на уровне файла, для:
    - `ffmpeg` (только в видео-загрузке)
    - `pdfjs-dist` (только в просмотре PDF)
    - `html2canvas` + `jspdf` (только в экспорте)
    - `mammoth` (только в импорте Word)
    - `exceljs` (только в FRDO/импорт-экспорт)
15. **`public/` 24 MB** — пройду по содержимому, удалю неиспользуемое (старые превью/иконки), оптимизирую крупные PNG → WEBP.
16. **`vite.config.ts`** — добавлю `manualChunks` для разделения vendor-чанков (radix, three, pdf, supabase отдельно), чтобы один пуш не инвалидировал весь chunk.

#### E. UX / DevTools-вкладка «Здоровье»

17. Текущая вкладка «Здоровье» (`HealthTab.tsx`) показывает **захардкоженные** рекомендации из `CODE_RECOMMENDATIONS`. Это устарело. Переработаю её, чтобы:
    - Брать актуальный статус Supabase linter через RPC (или хотя бы кешировать последнюю проверку).
    - Реально считать таблицы > 1000 строк, пустые таблицы, размер бакетов.
    - Показывать «Permissive RLS», «Public bucket», «Mutable search_path» как живые карточки.

### План работ (этапами, с подтверждением между этапами)

**Этап 1. Безопасность БД (миграция + auth):**
- Найти и сузить 6 permissive RLS-политик (один SQL-аудит → миграция).
- Сузить SELECT на `storage.objects` для 4 публичных бакетов.
- Добавить `SET search_path` к функциям, где его нет.
- Перенести `pg_trgm` в `extensions`.
- Включить Leaked Password Protection.

**Этап 2. Чистка кода:**
- Удалить `src/_archived/`.
- Переименовать дубликат `ProfileTab.tsx` → `OrgProfileTab.tsx`.
- Перевести «горячие» `.single()` → `.maybeSingle()` (топ-15 мест).
- Заменить `select('*')` → точечные поля в 5 топ-местах списков.
- Добавить cleanup для 4 утечек `supabase.channel`.

**Этап 3. Бандл:**
- Перевести ffmpeg/pdfjs/html2canvas/jspdf/mammoth/exceljs на функционально-локальный `await import()`.
- Настроить `manualChunks` в `vite.config.ts`.
- Оптимизировать `public/` (удалить мусор, конвертировать тяжёлые PNG → WEBP).

**Этап 4. Типизация (опционально, на отдельный заход):**
- Заменить `: any` в публичных API хуков на нормальные типы.
- Разбить `RichTextEditor.tsx` и `MediaLibraryDialog.tsx`.

**Этап 5. Живая вкладка «Здоровье»:**
- Сделать `HealthTab` динамической: реальный размер таблиц, реальные warnings.
