## Что сейчас есть

- **Звонок**: `LogActivityDialog` пишет `call_logs` + `sales_lead_activities`, но не предлагает действий после («Отправить КП», «Назначить встречу»).
- **КП**: в `commercial_proposals` всего 3 записи `scope=platform` (старые), готовых шаблонов под отправку с кабинета менеджера нет. Есть 6 `proposal_presets` и платформенный email-шаблон «Отправка КП» (`d98ee5a8…`).
- **Почта**: `org_smtp_settings` пусто, но платформенный SMTP (Timeweb через `_shared/smtp-sender.ts` + `send-campaign-email`) уже работает — именно через него уходят рассылки и КП с админки. То есть для отправки от лица «Синтагма» инфраструктура готова.
- **Deals360**: компонент-карточка одной компании, куда собирается история (звонки / КП / договоры / акты). Полезен как «карточка сделки», но из звонка туда нет быстрого перехода и нет действия «отправить КП».

## Зачем «Сделки 360»

Это не дубль «Компаний», а **сводный таймлайн по одной компании** — ИНН, контакты, все КП / договоры / счета / звонки / задачи в хронологии. Используется когда менеджер «провалился» в клиента, чтобы видеть всю историю работы в одном экране. Уберём упоминание из основного меню (оставим как «Открыть карточку» из карточки компании / лида) — чтобы не путать с «Компаниями».

## План

### 1. Кнопка «Отправить КП» прямо из звонка

В `LogActivityDialog.tsx` после выбора результата `interested` / `callback`:
- Селект «Готовое КП» (тянем из `commercial_proposals` где `scope='platform'` и новый флаг `is_template=true`).
- Кнопка **«Сохранить и отправить КП»** — закрывает звонок, дергает `send-campaign-email` (`purpose: proposal`, готовый платформенный template `d98ee5a8…`), пишет в `sales_lead_activities` запись `proposal_sent` + ссылку на КП, ставит лиду `status='proposal'`.
- Если у лида нет email — поле «E-mail для отправки» прямо в диалоге.

### 2. Готовые КП Синтагмы (платформенные шаблоны)

Миграция: добавить `commercial_proposals.is_template boolean default false` и засеять 5 готовых КП с реальными ценами/услугами (берём из `proposal_presets` + `pricingFeatureRows`):

1. **СДО под ключ за 7 дней** — базовый комплект (35 000 ₽/мес × 12)
2. **Корпоративное обучение группы 10–50 чел.** — тариф Бизнес
3. **Готовый каталог 300+ курсов** — лицензия на пакет
4. **ФИС ФРДО + проверка ошибок** — модуль документооборота
5. **Коробочная версия / on-premise** — индивидуальное КП

Каждое — с заполненным `intro_html` / `outro_html` (со стандартным блоком «ИП Шафрановский М.М. + печать»), `total_amount`, `valid_until = +14 дней`. Видны менеджеру в селекте «Готовое КП», можно дублировать под клиента (кнопка «Создать на основе» → копирует, подставляет company_name/email из лида).

В сайдбаре нового раздела «КП-шаблоны Синтагмы» под иконкой «Sparkles» — список этих шаблонов с кнопками **Просмотр / Отправить / Дублировать**.

### 3. Проверка почты + тестовое письмо

- Edge-функция `send-email` (платформенный Timeweb SMTP) уже задеплоена. Из админки добавлю в `SalesDashboardHeader` кнопку «Проверить почту» (видна только для роли `sales_manager`/`admin`) → шлёт тестовое HTML-письмо на email текущего пользователя через `send-email`, показывает тост с результатом.
- В этом же тесте проверю, что письмо реально доходит (отправлю на ваш email — нужно подтвердить, на какой именно: профильный sales@… или иной).

### 4. End-to-end проверка через Playwright

Сценарий на `/sales`:
1. Войти как `sales_manager` (сессия уже инжектится).
2. Открыть «Компании» → взять в работу первый лид из пула.
3. Открыть «Позвонить» → выбрать результат «Заинтересован», выбрать готовое КП «СДО под ключ», нажать «Сохранить и отправить КП».
4. Проверить:
   - в `call_logs` появилась запись,
   - в `sales_lead_activities` запись `proposal_sent` с ссылкой,
   - статус лида = `proposal`,
   - в `email_send_log` (или ответе edge-функции) есть успешный send,
   - письмо пришло на тестовый адрес.
5. Скриншот «До/После», отчёт в чат.

### 5. Что может не хватать к завтрашнему API (анализ)

- **MTS Exolve SIP**: ни одного `exolve_sip_accounts` не заведено → нужно подключить хотя бы 1 тестовый SIP, иначе кнопка «Позвонить» останется логом.
- **WebRTC permissions**: в `/sales` HTTPS уже есть, но нет UI разрешения микрофона до первого звонка — добавлю «Проверка микрофона» рядом с «Проверить почту».
- **Webhook логирования звонков** (Exolve → `call_logs`): edge-функция `exolve-webhook` ещё не создана. Без неё статус «answered/no_answer/duration» придётся писать вручную.
- **Номер для исходящих**: нужно поле в `exolve_sip_accounts.outbound_number` (есть). Уточнить, какой номер привязываем.
- **Запись разговоров**: storage bucket `call-recordings` и подпиcка на запись от Exolve.
