

## Что делаем

Три изменения в кабинете организации (`/organization` → «Профиль»).

### 1. Профиль организации в стиле админки (вертикальное меню слева)

Сейчас разделы «Профиль» — это горизонтальные табы наверху (Мой профиль / Брендирование / Бренд. страницы входа / Вход / Уведомления / Партнёрская программа). Переделываем в **вертикальное меню слева** + контент справа — точно так же, как в `AdminSettings.tsx`.

При этом «Тема оформления» **выносится отдельным пунктом меню** (а не внутри «Мой профиль», как сейчас), чтобы её было удобно найти. Структура меню:

- Мой профиль
- **Тема оформления** (новый отдельный раздел)
- Брендирование
- Бренд. страницы входа
- Вход
- Уведомления
- Партнёрская программа

Рефакторинг — внутри `ProfileTab.tsx`: меняем `<Tabs>` на ту же связку `nav + content`, что в `AdminSettings`. Сохраняем синхронизацию с URL (`?tab=profile&sub=theme`), чтобы сохранились существующие ссылки/`initialSubTab`.

### 2. Тумблер «Применять визуальную тему ко всем сотрудникам»

В разделе «Тема оформления» добавляем переключатель:
- **Включён** (по умолчанию для тех, кто уже сохранял тему): выбранная тема и режим (свет/тьма) грузятся из БД и применяются у всех сотрудников на любых устройствах. Текущее поведение `useOrgTheme` + `applyOrgTheme`.
- **Выключен**: тема не насаждается из БД — каждый сотрудник видит свой локальный выбор (`localStorage`). Управляющий блок «Визуальная тема организации» становится приглушённым (disabled).

Хранение: `organizations.branding.orgTheme.enforce: boolean` (новый флаг). Миграции БД не нужны — `branding` это `jsonb`.

Логика применения (правки в `useOrgTheme.ts` и местах, где вызывается `applyOrgTheme`):
- `applyOrgTheme` вызывается, только если `enforce === true`.
- Если `enforce === false` — хук просто возвращает значения для UI (чтобы редактор продолжал показывать выбор), но не записывает в `localStorage` и не диспатчит глобальные события.

### 3. Подсказки «где появится» для логотипа / значка / обложки / аватара

Сейчас в трёх местах есть загрузчики изображений с минимальными подписями. Добавляем понятные подсказки + мини-превью «вот тут это будет видно»:

- **Аватар (Мой профиль)** — текст «Виден в правом верхнем углу шапки личного кабинета вместо инициалов» + миниатюрная иконка-схема.
- **Значок организации (Тема оформления)** — «Появляется в левом боковом меню над названием организации (квадрат, ≥128×128, прозрачный PNG)» + мини-схема сайдбара.
- **Логотип (Брендирование)** — «Появляется в шапке и на странице входа вместо стандартного логотипа Синтагма» + мини-схема.
- **Обложка (Брендирование)** — «Большое изображение в верхней части кабинета (1920×400)» + мини-схема шапки.

Реализация: маленький SVG-схемы (контур сайдбара/шапки с подсвеченным местом) рядом с каждой загрузкой + одна-две строки текстовой подсказки. Без новых картинок-ассетов — рисуем чистым SVG/CSS.

## Этапы

1. Расширить `useOrgTheme.ts` (`enforce` + условное применение).
2. Перевёрстка `ProfileTab.tsx`: `nav + content`, новый раздел «Тема оформления», тумблер «Применять ко всем сотрудникам», правильные подсказки у аватара/значка.
3. Подсказки и мини-схемы у логотипа/обложки в `ProfileBrandingTab.tsx`.
4. Учесть `enforce` в `OrganizationDashboard.tsx` / `OrgPageLayout.tsx`.
5. End-to-end проверка:
   - Меню «Профиль» вертикально слева, переключение разделов, сохранение URL.
   - Включён тумблер → второй сотрудник в другом браузере видит ту же тему.
   - Выключен тумблер → сотрудники видят свой локальный выбор.
   - У всех загрузчиков изображений видна понятная подсказка «где появится».
