
Проблема подтверждена: курсы у ВЦОТ в базе есть, но на клиенте загрузка иногда падает по таймауту SQL (`57014 canceling statement due to statement timeout`), после чего `fetchCourses()` возвращает пустой массив, а `CoursesTab` показывает empty state “Начните обучение прямо сейчас”. То есть это не пропажа данных, а деградация запроса/обработки.

Что нужно сделать:
1. Упростить загрузку курсов в `src/api/courses.ts`
   - убрать тяжёлую цепочку из трёх запросов для списка курсов (`courses` + `enrollments` + `user_roles`) из основного пути рендера;
   - для списка курсов сначала загружать только сами курсы и `lessons(count)`;
   - `studentsCount` временно считать отдельно более лёгким способом или отложенно, чтобы сам список не блокировался.

2. Сделать `fetchCourses()` устойчивым
   - если дополнительная загрузка счётчиков студентов падает/таймаутится, не возвращать пустой список курсов;
   - возвращать курсы сразу, а счётчики заполнять `0` или догружать позже;
   - логировать ошибку счётчиков отдельно, без обнуления всего каталога.

3. Проверить сортировку по `catalog_order`
   - сейчас в сетевых логах виден запрос только с `order=created_at.desc`, хотя код уже сортирует и по `catalog_order`;
   - нужно привести вызов к стабильной сортировке и убедиться, что свежая версия действительно используется;
   - если текущий SDK/REST-генерация даёт нестабильный запрос, упростить order до одного безопасного варианта на время фикса.

4. Исправить UX в `CoursesTab.tsx`
   - empty state показывать только когда точно завершилась успешная загрузка и `courses.length === 0`;
   - при ошибке загрузки показывать отдельное сообщение “Не удалось загрузить курсы, попробуйте обновить”, а не экран создания первого курса;
   - при частичной деградации показывать курсы даже без статистики.

5. Опционально ускорить базу миграцией
   - добавить недостающие индексы для часто используемых связок, прежде всего на поля выборки/связей курсов и зачислений;
   - это делать только после быстрой правки клиента, чтобы сразу восстановить видимость курсов.

Что проверю после внедрения:
- у ВЦОТ на `/organization` вкладка “Курсы” больше не показывает empty state при существующих курсах;
- даже если счётчики студентов не загрузились, карточки/таблица курсов всё равно видны;
- при ошибке запроса отображается именно ошибка загрузки, а не “Создайте свой первый курс”;
- сортировка и переключение видов не ломают список.

Файлы:
- `src/api/courses.ts`
- `src/components/organization/tabs/CoursesTab.tsx`
- возможно `src/hooks/useCourses.ts`
- при необходимости миграция для индексов в `supabase/migrations`

Техническая причина:
данные существуют и даже приходят в сетевых запросах, но клиентский путь загрузки курса слишком хрупкий: при таймауте дополнительной части запроса функция деградирует в `[]`, а UI трактует это как “у организации нет курсов”. Исправление должно разделить “нет данных” и “не удалось догрузить статистику”.
