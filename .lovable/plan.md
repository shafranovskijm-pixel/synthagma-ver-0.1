
# Исправление: студент не создаётся из-за дублирующегося email + no_login не работает

## Обнаруженные проблемы

### Проблема 1: Дублирование email блокирует создание нового студента
Организация пытается добавить "Фролова Наталия Игоревна" с email `evgenmel89@yandex.ru`, но этот email уже принадлежит "Красавина Анастасия Сергеевна". Edge-функция `register-student` находит существующий профиль по email и возвращает "уже существует" вместо создания нового студента.

### Проблема 2: Флаг `no_login` не обрабатывается
Параметр `no_login: true` принимается функцией, но полностью игнорируется. Студент всегда создаётся с auth-аккаунтом.

## План исправления

### Шаг 1: Обработка `no_login` в edge-функции `register-student`
Когда `no_login: true`:
- НЕ создавать auth-пользователя
- Генерировать случайный UUID для `user_id`
- Создать только запись в `profiles` без auth-аккаунта
- Пропустить проверку дублирования по email (у no_login студентов email -- контактный, не уникальный идентификатор)

### Шаг 2: Изменить логику проверки дублирования
Если `no_login: true`:
- Проверять дублирование по ФИО + organization_id вместо email
- Если ФИО совпадает в той же организации -- предупредить, но всё равно создать (т.к. ФИО могут совпадать)
- Если `no_login: false` -- оставить текущую проверку по email

### Шаг 3: Загрузка данных -- увеличить лимит запроса
Добавить `.limit(10000)` в запрос профилей в `useOrganizationDataLoader.ts` (строка 125-128), чтобы гарантировать загрузку всех студентов для крупных организаций (Supabase по умолчанию возвращает максимум 1000 строк).
