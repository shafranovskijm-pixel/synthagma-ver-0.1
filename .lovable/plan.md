

# Аудит системы вебинаров: слабые места и план улучшений

## Что я проверил

40 полей в `webinars`, 5 связанных таблиц (`webinar_participants`, `webinar_chat_messages`, `webinar_questions`, `webinar_polls`, `webinar_poll_votes`), 7 edge-функций (`livekit-issue-token`, `livekit-create-room`, `livekit-start/stop/copy-recording`, `livekit-moderate`, `webinar-reminders-cron`, `webinar-public-info`), 9 UI-компонентов, страница `/w/<token>` и хост-страница `/webinar/:id/live`, RLS-политики и cron.

## 🔴 Критические дыры безопасности (исправить срочно)

### 1. Открытые INSERT-политики для anon
Все три гостевые INSERT-политики (`webinar_chat_messages`, `webinar_questions`, `webinar_poll_votes`) имеют **пустой `WITH CHECK`** = `true`. Любой анонимный пользователь, знающий любой `webinar_id`, может:
- спамить чат **любого** вебинара (даже с `allow_guests=false`);
- создавать вопросы и голоса в произвольных опросах;
- подделывать `author_identity` под другого участника.

**Фикс:** переписать `WITH CHECK` так, чтобы:
- `webinar_id` существовал и `allow_guests=true`;
- для голосов: `poll_id` принадлежал вебинару с `allow_guests=true` и опрос `is_open=true`.

### 2. Дублирование голосов в опросах
`webinar_poll_votes` не имеет `UNIQUE(poll_id, voter_identity)`. Гость может проголосовать N раз, пересоздавая identity. Нужен уникальный индекс + проверка в RLS.

### 3. `webinars.guest_password` хранится в открытом виде
Нарушение нашего стандарта `pgp_sym_encrypt`. Сравнение в `livekit-issue-token` идёт по plain-text. Зашифровать через `encrypt_password()` + добавить триггер + проверка через `decrypt_password()` в edge-функции.

### 4. Чат LiveKit не сохраняется
LiveKit DataChannel-сообщения **не пишутся** в `webinar_chat_messages` — таблица создана, но webhook не подключён. После эфира чат потерян. В записи (когда сделаем) — тоже пусто.

### 5. `livekit-issue-token` для гостя пускает в комнату даже если `status != 'live'`
Гость может «зайти» в запланированный или завершённый вебинар. Добавить проверку `status === 'live'`.

## 🟠 Функциональные пробелы (важно для UX)

### 6. Нет авто-старта записи при `auto_record=true`
Поле `auto_record` есть, но никто не вызывает `livekit-start-recording` автоматически при переходе вебинара в `live`. Решение: триггер БД → `pg_net` POST на edge-функцию, ИЛИ кнопка «В эфир» в UI вызывает старт записи.

### 7. Авто-копирование записи в Lovable Cloud не работает
`livekit-copy-recording` создан, но запускается только вручную. Нужен LiveKit Egress-webhook (`livekit-egress-webhook`), который при событии `EGRESS_ENDED` автоматически копирует файл с LiveKit Cloud в наш бакет `webinar-recordings/`.

### 8. Отметка о посещении не превращается в запись на курс
`webinar_participants` пишется, но не интегрировано с `enrollments` / `AutoDocumentRegistrationJournal`. Если вебинар привязан к курсу — посещение должно засчитываться как пройденный «урок-вебинар» с временем просмотра.

### 9. Нет аналитики посещения
Не пишутся `joined_at`, `left_at`, `watch_seconds` для участников. Из-за этого:
- нельзя выдавать сертификат за «80% просмотра»;
- нельзя показать пик одновременных, среднее время, отсев;
- организация не видит, кто реально слушал.

**Фикс:** добавить `webinar_attendance_log (webinar_id, identity, user_id, joined_at, left_at, duration_sec)` + LiveKit webhook на `participant_joined/left`.

### 10. Нет регистрации на вебинар (лид-форма)
Анонс вебинара = просто `/w/<token>` со входом во время эфира. Нет:
- формы «оставить email и получить напоминание»;
- таблицы `webinar_registrations`;
- авто-рассылки приглашения с iCal до начала.

Сейчас `webinar-reminders-cron` шлёт только зачисленным студентам — лидам с публичной страницы письма не приходят.

### 11. Нет NPS / обратной связи после эфира
При выходе из комнаты у гостя нет окна «оцените эфир (1–5) + комментарий». Метрика для организации отсутствует.

### 12. Нет демо-экрана с превью камеры/микрофона ДО входа
Гость нажимает «Войти в эфир» и сразу попадает в комнату с включённым звуком/видео. Стандарт индустрии (Zoom, Whereby) — pre-join screen с выбором устройств и тестом.

### 13. Нет «зала ожидания» (waiting room)
Все, кто открыл ссылку, попадают сразу. Хост не может «впустить вручную» или отсеять подозрительных.

### 14. Нет дашборда минут LiveKit
Free tier = 5000 минут/мес. Сейчас узнаём об исчерпании только когда упадём. Нужен виджет в админке через LiveKit Analytics API или собственный счётчик `webinar_attendance_log`.

### 15. Список вебинаров у студента слабый
`StudentWebinarsList` показывает только список. Нет:
- календарной сетки;
- кнопки «Добавить в календарь» (.ics);
- индикатора «До начала: 2д 4ч»;
- архива записей.

### 16. Нет возможности «поднять руку»
Стандарт вебинаров. Сейчас у гостя только чат — нет визуального сигнала хосту «хочу высказаться».

### 17. Нет повторяющихся вебинаров (RRULE)
Серии «каждый вторник 19:00» приходится создавать вручную.

## 🟢 Премиум-функции (отдельный спринт)

- **Сертификат участника** при просмотре ≥80% — генерация через `document-printing-system`.
- **Запись = автоматический урок** в привязанном курсе (`lesson_type=video`).
- **RTMP-ретрансляция** в YouTube/VK через LiveKit Egress.
- **Брендирование комнаты** (лого организации, цвет, кастомный welcome-текст в `player_settings`).
- **Платные вебинары** через интеграцию с T-Bank (есть `tbank-init`).
- **Сегментация рассылок**: напоминание гостям, у кого есть регистрация, но ещё не зашёл.
- **Email-отчёт хосту после эфира** («50 уникальных, средний просмотр 38 мин, 12 вопросов, 2 опроса»).

## Архитектурные риски

- **`livekit-issue-token` всегда `roomAdmin: true`** для любого члена организации. Помощник ведущего (преподаватель) получает права кикать всех. Нужна отдельная роль `moderator` без `roomDelete`.
- **Cron `webinar-reminders-cron` без идемпотентности по адресату.** Если функция упадёт после отправки части писем и перезапустится — кто-то получит дубль. `reminders_sent` сохраняется только после полной обработки вебинара.
- **`webinar_chat_messages` не в `supabase_realtime` publication** (нужно проверить — UI использует Realtime).
- **Нет лимита частоты сообщений в чате/Q&A** — anon может заспамить таблицу.

## Что предлагаю сделать в **Спринт 2** (≈ 4 итерации)

### Итерация 1 — Закрыть дыры безопасности
- Переписать INSERT-политики для anon с реальным `WITH CHECK` (allow_guests + status=live).
- `UNIQUE(poll_id, voter_identity)` + проверка `is_open` в RLS.
- Зашифровать `webinars.guest_password` через `pgp_sym_encrypt` + триггер + RPC `verify_webinar_guest_password`.
- В `livekit-issue-token` гостевой ветке проверять `status === 'live'`.
- Rate-limit на чат/Q&A через таблицу `webinar_rate_limits` или edge-функцию.

### Итерация 2 — Авто-запись end-to-end
- Edge-функция `livekit-egress-webhook` (без JWT, валидация по `LIVEKIT_WEBHOOK_KEY`).
- При `EGRESS_ENDED` → запись `recording_external_url` + автозапуск `livekit-copy-recording`.
- Триггер: при `webinars.status` `scheduled→live` и `auto_record=true` → `pg_net` POST на `livekit-start-recording`.
- При завершении эфира → авто-stop.
- LiveKit chat-webhook → запись в `webinar_chat_messages` (история чата в записи).

### Итерация 3 — Лиды и аналитика
- Таблица `webinar_registrations (webinar_id, full_name, email, consent, created_at)` + RLS.
- Лендинг `/w/<token>/register` с формой «оставить email» + iCal-приглашение.
- Таблица `webinar_attendance_log` + LiveKit webhook `participant_joined/left`.
- Виджет «Аналитика вебинара» в `WebinarsManager` (уникальные, среднее время, пик, отсев).
- Виджет «Использовано минут LiveKit» в `AdminWebinarsOverview`.

### Итерация 4 — UX-полировка
- Pre-join screen с выбором камеры/микрофона.
- «Поднять руку» (LiveKit metadata + индикатор у хоста).
- NPS-окно после `Покинуть эфир` → таблица `webinar_feedback`.
- Кнопка «Добавить в календарь .ics» в публичном анонсе и у студента.
- Отметка посещения → авто-завершение урока-вебинара в курсе.

## Чего НЕ делаю

- Waiting room — по статистике сейчас не нужен (нет жалоб на «случайных гостей»). Отложу до спроса.
- RRULE / серии вебинаров — отложу в Спринт 3.
- Платные вебинары через T-Bank — отдельная большая задача, после стабилизации основы.
- Сертификаты участникам и автоконвертация записи в урок — Спринт 3 (зависит от готового `webinar_attendance_log`).
