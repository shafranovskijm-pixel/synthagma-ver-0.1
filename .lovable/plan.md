

# Аудит-2: что ещё стоит улучшить и доработать

Прошёлся по проекту повторно — нашёл **12 точек роста**, разделил на «незаконченное из прошлых раундов», «голые/недоделанные функции» и «инфраструктурные пробелы».

---

## 🔴 А. Незаконченное из прошлых раундов

### 1. `getErrorMessage` — мигрировано всего 10 файлов из ~92
По коду осталось **92 голых** `toast.error("Ошибка")` / `toast.error("Произошла ошибка")`. Утилиту сделали — но реально пользуются ей единицы. Студент/менеджер видит «Ошибка» без причины — звонит в поддержку.
**Действие:** пройтись по top-30 файлам (хуки `use*`, диалоги, формы) и заменить на `getErrorMessage(e)`. Дать пользователю текст «Превышен лимит запросов» / «Файл больше 50 МБ» вместо «Ошибка».

### 2. `queryKeys (qk.*)` — используется только в 2 местах
Файл `src/lib/queryKeys.ts` создан, но из 55+ `useQuery` его подключили только в `RequiresAttentionWidget` и одном хуке. Остальные продолжают писать `["org", id, "webinars"]` строкой — пропадает type-safety и единообразие invalidate.
**Действие:** мигрировать топ-15 ключей (organizations, courses, students, webinars, billing, documents). После — устаревшие `invalidateQueries(["org-..."])` начнут отлавливаться TS.

### 3. `_shared/handler.ts` и `_shared/logger.ts` — 0 функций мигрировано
Создали обвязку для edge — но **121 функция продолжает писать собственный CORS, парсить JWT и логировать через 167 голых `console.log` без контекста**. При проблеме у конкретного пользователя дебаг возможен только перебором.
**Действие:** мигрировать 5 самых «горячих» функций: `generate-course-content`, `gigachat`, `grade-test`, `html-to-pdf`, `tbank-init-payment`. Они дают 80% объёма логов.

### 4. Storage utility (`src/lib/storage.ts`) — обещали, не сделали
65 мест с `supabase.storage.from(...)` разбросаны по коду — каждое формирует signed URL вручную, обрабатывает квоту, ловит CORS. После переноса печатей в private-bucket пришлось править 5 файлов.
**Действие:** создать `src/lib/storage.ts` с `getPublicUrl/getSignedUrl/uploadWithProgress/getOrgStampUrl(1y)`; мигрировать ContractReviewBody, BulkDocumentGenerator, StampSignatureUploader.

## 🟡 Б. «Голые» функции, которые есть, но недоделаны

### 5. `RequiresAttentionWidget` — данные есть, действий нет
Виджет показывает «5 заявок ждут» — но при клике уходит в общий список. Не видно: у какого студента, на какой курс, как давно.
**Действие:** добавить **inline-разворот** карточки — превью первых 3 элементов с именами и кнопками «Одобрить»/«Отклонить» прямо в виджете. Минус 2 клика на каждое действие.

### 6. `OrgNotifications` — нет realtime, нет «отметить все», нет фильтра по дате
Есть Popover с уведомлениями (299 строк), но:
- Не подписан на `postgres_changes` — новые события появляются только при перезагрузке;
- Кнопки «Отметить все прочитанным» нет — ручная очистка по одной;
- Накапливается 200+ записей — нет автоархива/пагинации.

**Действие:** realtime-подписка на `org_notifications` для текущей орг; кнопка «Отметить всё»; автоархив >30 дней; счётчик непрочитанных в `OrgDashboardHeader`.

### 7. `CourseGenerationProgress` — прогресс есть, но устойчивости нет
Подключили в `AIGenerateDialog`, но если пользователь **закрыл вкладку** — не видит, что генерация идёт. И при ошибке (`step: 'error'`) — просто красная плашка без «Повторить» и без логов.
**Действие:** при возврате на страницу курса автоматически показывать прогресс-бар, если `generation_progress.step !== 'done'`; добавить кнопку «Повторить с шага N»; показать `progress.error_message` человечески.

### 8. `AnnouncementsBell` — есть бейдж, нет пуша
Реализована иконка в шапке организации, но:
- В кабинете студента — её нет (а у них тоже бывают объявления);
- В кабинете компании — её нет;
- При получении нового — не realtime-сигнал.

**Действие:** вынести `AnnouncementsBell` в `src/components/shared/`, подключить в `StudentDashboardHeader` и `CompanyDashboardHeader`; realtime через `postgres_changes` на `platform_announcements`.

### 9. Поиск в Cmd+K — индексирует курсы и вебинары, но нет студентов/документов
Расширили палитру — но самые востребованные сущности (студенты по ФИО, документы по номеру) до сих пор не ищутся. На орг с 200+ студентами — поиск через Cmd+K не помогает.
**Действие:** добавить параллельный поиск по `profiles.full_name` (через `org_members`), `org_documents.title`, `enrollments.full_name` (студенты-без-аккаунта). Дебаунс 250ms, лимит 5 в группе.

## 🟢 В. Инфраструктурные пробелы (важно для роста)

### 10. Нет ErrorBoundary на роутах — белый экран при крэше
Один глобальный `ErrorBoundary` в `App.tsx` — при крэше любого компонента **весь дашборд белеет**. На сложных страницах (CourseBuilder, BulkDocumentGenerator) — это часто.
**Действие:** обернуть отдельные роуты (`/organization/*`, `/student/*`, `/c/*`) в локальные ErrorBoundary с кнопкой «Перезагрузить раздел» — остальные части дашборда остаются живы.

### 11. Только 6 EmptyState и 8 Skeleton на 72 страницы
В большинстве таблиц пустое состояние — это «—» или просто пустой блок. Skeleton-загрузки практически нет (только спиннеры). Воспринимается как «висит».
**Действие:** создать 2 переиспользуемых компонента:
- `<EmptyState icon title description action />` — стандарт во всех таблицах;
- `<TableSkeleton rows={5} cols={4} />` — заменить спиннеры в курсах/студентах/документах.

### 12. Нет «Активность за день» и метрик нагрузки на ИИ
Админ не видит: сколько генераций сегодня, какая орг сожгла больше всего токенов, есть ли подозрительные пики. Лимит на ИИ контролируется только постфактум.
**Действие:** в `AdminDashboard` добавить виджет «Сегодня»: число генераций / всего токенов / топ-3 организаций по нагрузке за 24 часа. Источник — таблица аудит-логов и `ai_usage`.
