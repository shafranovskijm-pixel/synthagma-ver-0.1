## Что произошло у клиента

ФИС ФРДО отбраковал пакет с двумя видами ошибок:

1. **L2–L5 «значение отсутствует в классификаторе»** — в файле, который мы сформировали, в строке записано «…персональных услуг,&nbsp;услуги гостеприимства…» с **одним пробелом**, а официальный классификатор Рособрнадзора требует **два пробела** перед «услуги гостеприимства». Наш текущий fuzzy-match сравнивает строки с нормализацией пробелов, и при exact-сравнении (`indexOf`) до нормализации не находит совпадения, поэтому отдаёт оригинал без перезаписи на каноническое значение.
2. **Строка 6 пустая** — в исходнике у клиента строка содержала только пару значений по умолчанию (B6=Оригинал, C6–E6=Нет, F6=нет, H6='.', I6=нет, S6/T6/U6=0, AE6=643), без ФИО/даты/программы. Наш «пустая строка» детектор (`hasAny`) видит, что хоть что-то есть, и пропускает её в выгрузку → 11 ошибок по ячейкам A6/H6/K6/N6/V6–Z6.

## Что меняем (только `src/utils/frdoFileSanitizer.ts`)

### 1. Колонка L — всегда подставляем каноническое значение

В `sanitizeProfessionalArea`:
- Перед fuzzyMatch прогонять входное значение через нормализацию (двойные пробелы / невидимые символы / пунктуация) и сравнивать с нормализованным dict, **но возвращать строку из dict как есть** (с двойным пробелом). Сейчас это уже делает `fuzzyMatch`, но без шага «срезать хвостовые точки/скобки», поэтому строки вида «…и пр.» / «…и пр.)» иногда мимо. Добавим:
  - снятие невидимых, схлопывание пробелов, удаление концевых `.`/`)`/`,` перед сравнением;
  - сравнение по «префиксу» (первые 40 значимых символов) — если значение из файла начинается так же, как канон, считаем матч и возвращаем канон.
- Расширить `PROFESSIONAL_AREA_LEGACY_ALIASES`: добавить вариант с одним пробелом и без хвостовой скобки.

Результат: любой более-менее похожий текст в L всегда переписывается в каноническое значение с правильным двойным пробелом → ошибка «значение отсутствует в классификаторе» уходит.

### 2. Пустые строки — выбрасываем

В `parseFrdoXlsx` после `sanitizeByKind` ввести понятие «значимо заполненная строка». Сейчас `hasAny` смотрит только на сырой источник; добавим второй фильтр уже после очистки:

```
const isMeaningful = (cells) => {
  // считаем заполненными только НЕ-дефолтные значения
  const meaningfulIdx = type === "dpo"
    ? [0, 6, 10, 21, 22, 24, 26]   // вид док, номер, программа, фамилия, имя, ДР, СНИЛС
    : [0, 6, 10, 11, 16, 17, 19, 21];
  return meaningfulIdx.some(i => String(cells[i].value).trim() !== "");
};
```

Если строка не «meaningful» — `continue`, не добавляем в `rows`. То же поведение применить и к источнику: если в `src` нет ни одного значения в этих же колонках источника (через `columnMap`), сразу пропускаем без логирования.

Дополнительно: в статистике (`SanitizeStats`) добавить `droppedEmptyRows` и показать это число в диалоге (`FrdoFileSanitizerDialog`) под «Пропущено пустых строк: N».

### 3. Тесты

В `src/utils/__tests__/frdoFileSanitizer.test.ts` добавить два теста:
- L-колонка: вход «Сервис, оказание услуг населению (торговля, … персональных услуг, услуги гостеприимства, общественное питание и пр.)» (один пробел, без хвостовой скобки/с ней) → выход строго равен `FRDO_PROFESSIONAL_AREAS[31]`.
- Пустая строка: только B6=Оригинал, C6=Нет, H6=«.» → строка отсутствует в `parse.rows`, `stats.droppedEmptyRows === 1`.
