
## Что просит пользователь
На странице просмотра договора (со стороны клиента, по ссылке `/sign/...`) сейчас:
1. Кнопка "Согласовать и подписать" открывает **новое окно/вкладку** — нужно подписывать **прямо здесь**, без перехода.
2. На каждую правку клиент может только добавить комментарий поштучно — нет общей кнопки "Отправить все правки разом" с ответами/решениями клиента по каждой правке.

Нужно: единый поток в одной странице — клиент проходит по правкам, по каждой ставит "принял / не согласен / комментарий", внизу одна кнопка **"Отправить все правки отправителю"**, и отдельно кнопка **"Подписать здесь"** (инлайн-подписание без нового окна).

## Решение

### 1. Инлайн-подписание (без нового окна)
- Сейчас "Согласовать и подписать" делает `window.open` на отдельную страницу подписи. Заменить на инлайн-флоу прямо в `ContractReviewBody` (клиентский режим):
  - Кнопка "Подписать здесь" разворачивает встроенную панель ПЭП (ввод кода / подтверждение).
  - После подписи статус документа сразу обновляется, страница показывает "Подписано", без редиректа.
- Использовать существующую edge-функцию подписания (ту же, что вызывалась на отдельной странице) — просто вызвать её из текущего компонента.

### 2. Пакетная отправка правок клиентом
- Каждая карточка правки получает мини-управление **для клиента-рецензента**:
  - "Оставить как предложил" (по умолчанию)
  - "Изменить текст ответа" (короткое поле — клиент может уточнить свою правку)
  - "Отозвать" (правка не уйдёт)
- Локально хранить состояние всех правок до отправки (без записи в БД на каждое действие).
- Внизу единый блок:
  - Поле "Общий комментарий отправителю" (необязательно).
  - Кнопка **"Отправить все правки"** — одним вызовом сохраняет финальный набор правок + меняет статус на `changes_requested` + триггер уже шлёт одно агрегированное уведомление организации (это мы уже сделали ранее).
- Кнопка "+ Добавить" на отдельной правке остаётся для добавления новых комментариев в режиме редактирования, но финализация — только через общую кнопку.

### 3. UI-структура нижнего блока "Что дальше?"
Заменить текущий блок на 3 чёткие зоны:
1. **Сводка правок**: "Вы внесли N правок" + список с пометками (принять / отозвать).
2. **Запросить правки**: общий комментарий + кнопка "Отправить все правки отправителю".
3. **Подписать здесь**: инлайн-блок ПЭП с кнопкой "Подписать".

### 4. Backend
- RPC уже есть: `request_signature_changes(token, summary)` — переводит в `changes_requested`. Используем как есть, передавая общий комментарий.
- Для инлайн-подписания — использовать существующую edge-функцию подписания по токену (найти на этапе реализации, посмотреть страницу `/sign/:token`).
- Дополнительно: при отправке правок убедиться, что все локально добавленные комментарии успели сохраниться (батч-сохранение перед сменой статуса), либо отправлять их одним вызовом новой RPC `submit_signature_review_batch(token, comments[], summary)`.

## Файлы (предварительно)

- Страница `/sign/:token` (найти) — посмотреть текущую логику подписания, перенести в инлайн.
- Возможна новая RPC `submit_signature_review_batch` для атомарной отправки набора правок + смены статуса.

## Этапы
1. Найти текущую страницу/edge-функцию подписания по токену и понять API ПЭП.
2. Добавить в `ContractReviewBody` (клиентский режим) локальное состояние "решений" по правкам.
3. Заменить блок "Что дальше?" на сводку + единый комментарий + кнопку "Отправить все правки".
4. Реализовать инлайн-подписание прямо в этой же странице (без нового окна).
5. Опциональная RPC `submit_signature_review_batch` для атомарной отправки.
6. Проверить флоу: клиент добавляет несколько правок → жмёт одну кнопку → организация получает одно уведомление; либо клиент жмёт "Подписать здесь" → подпись без редиректа.
