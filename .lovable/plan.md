### 🔴 Критичные баги (поломают опыт сразу)

**1. Runtime error: «Component is not a function»**
В консоли уже падает при рендере. Скорее всего — следствие циклической зависимости: `BlockRenderer.tsx` импортирует из `./blocks/EmbedBlock` и `./blocks/FormulaBlock`, а `BlockContent.tsx` (внутри `blocks/`) импортирует обратно из `../types`. При HMR/код-сплите React получает `undefined` вместо компонента. Чинить — переносом `getEmbedSrc` и `FormulaRender` в чистый `utils`-модуль, без обратных импортов.

**2. RichTextEditor: первая загрузка контента ломается при медленной загрузке**
В `useEffect` на строке 81 контент ставится один раз при монтировании. Если `value` прилетает позже (после загрузки урока), он попадает во второй эффект на строке 90, но условие `value !== lastEmittedHtml.current` иногда не срабатывает — текст в редакторе остаётся пустой, хотя в БД уже сохранён. Заказчик увидит «пропавший текст». Фикс — единый эффект с правильной защитой от рекурсии.

**3. Списки теряют пункты при сохранении**
В `BlockContent.tsx` строка 72: `(block.content || "").replace(/<\/?li>/gi, "")` — стрипает теги перед вставкой в редактор, но список хранится по `\n`. При вводе с переносом через Enter браузер вставляет `<div>`/`<br>`, нормализатор частично их склеивает — пользователь видит «один длинный пункт» вместо нескольких. Нужна явная нормализация под `\n` для списков.

**4. Линкификация ломает текст со словом «www.» внутри**
`linkify` в `utils.ts` срабатывает на любое `www.` — даже внутри `<a href="...">`-href атрибута DOMPurify пропустит, а внутри текста парсер заменит. Если в строке две ссылки рядом без пробела — первый `<a>` закроется неправильно. Нужно протестировать и заменить regex на более строгий + использовать DOMParser, а не split.

### 🟡 Узкие места (будут жалобы в первые дни)

**5. Нет автосохранения внутри `LessonEditor` (диалог урока)**
В `useCourseBuilder.ts` есть глобальный autosave курса, но **внутри открытого диалога редактирования урока** изменения текста не сохраняются до клика «Сохранить». Если автор закроет вкладку или у него отключится интернет — потеряет всё. Заказчик скажет: «Я печатал час, нажал крестик, всё пропало». Нужен либо локальный draft в `localStorage`, либо предупреждение `beforeunload`.

**6. Ctrl+Z работает на уровне блоков, но не внутри текста**
`BlockEditor.tsx` строки 38-50: undo/redo сохраняет всю историю блоков, но клавиша Ctrl+Z в `RichTextEditor` сначала отменяет ввод браузера, а затем — наш глобальный обработчик — целиком откатит блок. Конфликт: пользователь нажимает Ctrl+Z для удаления буквы, а получает откат на 5 действий назад. Нужно `e.target` проверять — если внутри contentEditable, не перехватывать.

**7. `RichTextEditor` использует `document.execCommand` (deprecated)**
Это работает, но в Firefox и Safari всё чаще даёт сбои:
- `cycleSize` (font-size цикл) вставляет `<font size="7">` который потом конвертится — на Safari часто остаётся «съеденная» вёрстка
- `createLink` без выделения молча игнорируется, пользователь думает что всё ок
- Под iPad клавиатура съедает selection при попапе toolbar'а

Долгосрочно нужна миграция на TipTap или Lexical. Краткосрочно — добавить toast «Выделите текст для применения стиля», валидация selection до execCommand.

**8. Картинка: загрузка >10МБ молча ничего не делает**
`MediaBlocks.tsx` строка 73: `if (file.size > 10 * 1024 * 1024) return;` — без toast'а. Пользователь нажимает «загрузить», ничего не происходит. Нужен `toast.error("Файл больше 10 МБ. Сожмите изображение.")` + лимит сделать настраиваемым по тарифу.

**9. Видео из ссылки: нет валидации**
В `LessonEditor.tsx` строка 220 — Textarea принимает любой текст. Если автор вставит обычный URL который не распознан (ни YouTube, ни VK, ни прямой mp4) — на стороне студента просто будет пустое место. Нужен превью «Не удалось распознать ссылку» с ссылкой на список поддерживаемых.

**10. Таблица: нет undo для удаления колонки/строки**
`TableBlock.tsx`: нажал крестик — потерял колонку. История блоков спасёт от этого, но только если пользователь успел триггернуть autosave. Стоит добавить `confirm()` для удаления непустой колонки/строки.

### 🟢 Недоработки и предсказуемые запросы заказчика

**11. Превью урока студентским взглядом — нет в редакторе**
Сейчас, чтобы посмотреть, как урок выглядит у ученика, надо выйти из конструктора и зайти на курс. Заказчик 100% попросит кнопку «Превью» (eye-icon) — открывает диалог с `<BlockRenderer />` и стилями студенческого плеера.

**12. Импорт из Word/.docx**
Сейчас в конструкторе есть: PPTX, Excel/TXT (для тестов), GitHub, Markdown, JSON. Нет .docx — а это формат №1 для авторов курсов в России. Нужен `mammoth.js` → HTML → `htmlToBlocks`.

**13. Поиск/замена внутри урока**
При длинных уроках (10+ блоков) нет Ctrl+F по содержимому. Нужна простая панель поиска с подсветкой совпадений.

**14. Подсчёт слов / времени чтения**
Заказчики в LMS традиционно просят: «сколько минут урок будет читаться». Простой счётчик в шапке: `~250 слов/мин`.

**15. Drag&drop файлов прямо в редактор**
Сейчас изображение можно вставить только через диалог «Загрузить файл». Естественный UX — перетащить картинку в любое место → автоматически создаётся `image`-блок. Аналогично для видео/PDF.

**16. Колл-аут «info/warning/tip/success/danger» — нельзя отредактировать заголовок**
В отличие от accordion, у callout'ов нет заголовка вообще, только тело. Заказчик попросит: «хочу написать **ВНИМАНИЕ:** жирным первой строкой». Нужен опциональный `calloutTitle`.

**17. Изображение: нет alt-текста по умолчанию**
Для SEO и доступности — критично. Сейчас можно ввести вручную, но 99% авторов забудут. ИИ может сгенерировать alt по содержимому через `generate-image-alt`.

**18. Нет копирования блока (duplicate)**
Только перетаскивание/удаление. Простейшая иконка «дублировать» в меню `...` сэкономит заказчику кучу времени при создании похожих секций (например, серия callout'ов).

**19. Embed: список разрешённых доменов не показан**
`EmbedBlock` принимает любой URL, но `getEmbedSrc` парсит только конкретные паттерны. Пользователь вставляет ссылку на CodePen — либо работает, либо нет, без объяснений. Нужен список «Поддерживается: YouTube, Vimeo, Figma, Miro, CodePen, Loom...».

**20. Пресеты стилей хранятся в localStorage без названия от пользователя**
`describeStyle` генерирует название автоматически («Жирный, По центру, Фон: yellow») — но это не запоминается. Пользователь сохранил 5 пресетов — все называются похоже. Нужен prompt при сохранении: «Введите название пресета».

Разнести: `ImageBlock.tsx`, `VideoBlock.tsx`, `AudioBlock.tsx`, `DocumentBlock.tsx`, `DirectVideoBlock.tsx`.

**23. `BlockRenderer.tsx` — switch на 23 case'а в одном компоненте (300 строк)**
Унести в map: `const blockRenderers: Record<BlockType, FC<...>> = { paragraph: ParagraphRender, ... }`. Облегчит добавление новых блоков и tree-shaking.

**24. `useLessonEditor.ts` `parseContent` — дублирует логику `markdownToBlocks`**
Зачем-то парсит markdown сам (строки 69-79). Должен использовать существующий парсер из `parsers.ts`.

**25. AI-кнопки в каждом блоке — дублирующаяся логика**
В каждом из `ParagraphBlock`, `QuoteBlock`, `CalloutBlock`, `HighlightBlock`, `AccordionBlock`, `QuizBlock` — почти одинаковый `handleGenerate` (вызов `generate-course-content` + checkAiLimit + toast errors). Вынести в хук `useBlockAIGenerate(block, contentType)`.
