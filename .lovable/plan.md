## Проблема

Корпоративные firewall (Kaspersky Endpoint, McAfee, Cisco Umbrella, Континент) блокируют домены `*.supabase.co` целиком. Текущая защита (`safeInvoke` retry 3×, IndexedDB-кеш) тут не работает: запросы не «временно падают», а **никогда не доходят**. Особенно страдают тесты — они грузятся через edge-функции `get-test-results` / `grade-test` (отдельный поддомен `*.functions.supabase.co`), которые блокируются ещё чаще, чем сам REST API.

## Что предлагаю — три уровня защиты

### Уровень 1. Диагностика для пользователя и менеджера (быстро, ~1 час)

Сейчас человек видит просто «не загружается» и не понимает что делать. Нужно:

**1.1. Страница `/connection-check`** — кнопка «Проверить соединение». Делает 4 теста:
- Базовый интернет (`https://www.google.com/generate_204`)
- Главный API Sintagma (`/auth/v1/health`)
- Edge-функции (`/functions/v1/health-check` — новая лёгкая функция)
- Storage (`/storage/v1/object/public/...`)

Показывает зелёный/красный по каждому пункту + понятный текст: *«Ваш антивирус/firewall блокирует функции платформы. Покажите эту страницу системному администратору и попросите добавить в исключения: `sintagma.com.ru`, `*.supabase.co`».*

Кнопка «Скачать отчёт» — текстовый файл с результатами + User-Agent + временем, который ученик отправляет своему IT-отделу или нашей поддержке.

**1.2. Автоматический баннер при детекции блока** — `safeInvoke` уже умеет ловить блок, но сейчас показывает только toast. Добавим стойкую плашку сверху страницы со ссылкой на `/connection-check` и инструкцией.

**1.3. Кнопка «Проверить соединение» в окне логина** — если человек не может войти, у него нет доступа к ученику, а проверку запустить сможет.

### Уровень 2. Обход блокировок через собственный поддомен (главное решение, требует DNS)

Большинство firewall блокируют по доменному списку, а не по содержимому. Если backend идёт через **наш собственный поддомен**, а не через `*.supabase.co`, блокировки исчезают почти у всех корпоратов.

**2.1. Настроить кастомный домен Supabase:**
- `api.sintagma.com.ru` → проксирует REST/Auth/Storage на текущий Supabase
- `fn.sintagma.com.ru` → проксирует edge-функции

Это делается через Cloudflare Worker или через built-in Custom Domains в Supabase (но он платный — $10/мес/проект). Cloudflare Worker — бесплатно для нашего объёма.

**2.2. Переключатель endpoint в клиенте** — если основной домен `*.supabase.co` упал, автоматически переключаемся на `api.sintagma.com.ru`. Хранится флаг в `localStorage`, чтобы при следующем заходе сразу использовать рабочий endpoint.

**2.3. Настроить Cloudflare Worker** (~50 строк кода) — простой reverse-proxy, который форвардит запросы на supabase. Один раз настроить — работает у всех заблокированных пользователей.

### Уровень 3. Тесты — особый случай (предзагрузка + офлайн-сдача)

Тесты — самое больное: студент уже на уроке, начал, и тут падает. Нужно:

**3.1. Предзагрузка теста при открытии курса** — когда ученик открывает курс, в фоне через тот же `courseCache` (IndexedDB) сохраняем все вопросы тестов курса. Уже есть инфраструктура — добавим `testQuestions` в схему кеша.

**3.2. Серверная проверка через очередь** — если `grade-test` упал, ответы складываются в IndexedDB-очередь и отправляются:
- При восстановлении соединения (online event)
- При следующем заходе на сайт
- Через `navigator.sendBeacon` (он часто проходит там, где fetch падает — у него отдельный сетевой стек в браузере)

Студент видит «Тест отправлен, оценка появится после синхронизации» и не теряет результат.

**3.3. Резервная синхронизация ответов через image-pixel hack** — если sendBeacon тоже не проходит, делаем `<img src="https://api.sintagma.com.ru/sync.gif?data=...">`. GET-запросы на изображения firewall пропускают почти всегда. На сервере — отдельный лёгкий endpoint, который принимает данные через query-string. Подходит только для маленьких пейлоадов (ответы теста — как раз).

## Что делаем в этом спринте (приоритет)

Предлагаю начать с **Уровня 1 + п.3.1**, потому что они самые быстрые и сразу дают пользу:

1. Страница `/connection-check` + edge-функция `health-check`
2. Кнопка «Проверить соединение» в Login
3. Стойкий баннер при детекции блокировки (вместо тоста)
4. Предзагрузка тестов в IndexedDB при открытии курса
5. Очередь отправки ответов теста через sendBeacon

**Уровень 2** (кастомный домен) — отдельной задачей: требует настройки Cloudflare Worker, нужен ваш доступ к DNS. Это даст радикальный эффект, но не сегодня.

**Уровень 3.3** (image-pixel) — оставляем как backup на случай, если sendBeacon не справится. Добавим, если после 1+3.1+3.2 жалобы продолжатся.

## Технические детали (для разработки)

- `supabase/functions/health-check/index.ts` — отдаёт `{ ok: true, ts }` без auth
- `src/pages/ConnectionCheck.tsx` — UI с 4 тестами, кнопка «Скачать отчёт»
- `src/components/NetworkBlockBanner.tsx` — глобальный баннер в `App.tsx`
- `src/utils/courseCache.ts` — добавить `testQuestions` в `CachedCourseData`
- `src/utils/testAnswerQueue.ts` — IndexedDB-очередь, методы `enqueue/flush`
- `src/hooks/course-learning/useLessonTest.ts` — при submit → `safeInvoke('grade-test')` → fallback на `sendBeacon` → fallback на queue
- В `Login.tsx` — кнопка-ссылка на `/connection-check`
- Перед запуском Уровня 2 — **обсудить отдельно**: купить ли Supabase Custom Domain ($10/мес) или поднимать Cloudflare Worker самим

## Что НЕ делаем

- Не пытаемся «обходить» антивирус — это бесполезно и небезопасно
- Не делаем полный офлайн-режим для всей платформы (только для тестов и кеша курса)
- Не отказываемся от Supabase — меняем только точку входа
