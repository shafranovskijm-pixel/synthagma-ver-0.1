

## Проблема

Когда организация включает «применять тему для всех сотрудников» (`enforce: true`), тема не применяется автоматически у других сотрудников при входе:
- Нужно жать Ctrl+Shift+R, чтобы увидеть новую тему
- С другого компьютера открывается индивидуальная тема, а не общая

## Корневая причина

В `useOrgTheme.ts` есть кэш в `sessionStorage` (`org-theme-cache:${orgId}`). При следующем входе:
1. Хук читает старую тему из sessionStorage и применяет её
2. Параллельно делает запрос в БД — но если `enforce` уже сменили или баннер обновили, кэш уже «победил» визуально
3. Кроме того, локальные настройки темы пользователя (localStorage `theme`, `__asset_id` и др.) **перебивают** общеорганизационную, потому что у пользователя могут быть свои индивидуальные `localStorage`-ключи, которые применяются `ThemePersonalization` раньше, чем приходит ответ из БД
4. Реалтайм-обновлений нет — даже если другой сотрудник в этот момент онлайн, он узнает о смене темы только при перезагрузке страницы (и то — благодаря sessionStorage, иногда не сразу)

## План решения

### 1. Приоритет «enforce» над индивидуальными настройками
- В `useOrgTheme.ts`: при `enforce: true` всегда применять org-тему **поверх** локальных пользовательских настроек, причём СРАЗУ после загрузки из БД, не дожидаясь следующего рендера.
- В `ThemePersonalization` (хук, инициализирующий тему): если у организации `enforce: true`, **игнорировать** индивидуальные `localStorage`-настройки пользователя для темы/баннера/анимации.

### 2. Свежие данные при каждом входе
- Убрать «оптимистичное» применение из sessionStorage при `enforce`-режиме (или применять только как мгновенный плейсхолдер, но обязательно перезатереть данными из БД).
- Делать запрос к `organizations.branding` с `cache: 'no-store'` для гарантии свежего ответа (уже и так маловероятно кэшируется, но добавим явно).

### 3. Realtime-подписка на изменения темы организации
- Включить Realtime для таблицы `organizations` (`ALTER PUBLICATION supabase_realtime ADD TABLE public.organizations`).
- В `useOrgTheme.ts` подписаться на `postgres_changes` для текущей `organization_id`. При апдейте `branding`:
  - Перечитать тему
  - Если `enforce: true` → немедленно применить через `applyOrgTheme(...)` без перезагрузки страницы
  - Обновить sessionStorage-кэш

### 4. Без Ctrl+Shift+R — мягкое применение «на лету»
- `applyOrgTheme` уже диспатчит события `visual-theme-change` и `theme`, на которые подписаны `OrganizationDashboard`, `OrgPageLayout`, `OrgSidebar`, `HeroBannerSwiper`, `ThemePersonalization`.
- Убедимся, что эти подписчики корректно перерисовываются (баннер, цвета, анимация) — без необходимости очищать Cache Storage / Service Worker.

### 5. Технические детали
- **Файлы:**
  - `src/hooks/useOrgTheme.ts` — добавить realtime + приоритет enforce
  - `src/components/ui/ThemePersonalization.tsx` (или `useThemePersonalization`) — учитывать enforce-флаг
  - `src/main.tsx` — НЕ трогаем (это про PWA-кеши, не про тему)
  - SQL-миграция: включить Realtime для `organizations`
- **Без изменений RLS** — таблица `organizations` уже доступна сотрудникам своей организации.
- **Безопасность:** изменение темы — не критичная операция, RLS уже защищает.

### 6. Что НЕ делаем
- Не трогаем PWA cache invalidation (`forceClientRefresh`, `remoteCacheCheck`) — это отдельный механизм для глобального обновления приложения, к теме отношения не имеет.
- Не делаем `window.location.reload()` при смене темы — применяем через события без перезагрузки.

```text
[Org-admin меняет тему]
        ↓
   UPDATE organizations.branding
        ↓
   Postgres Realtime push
        ↓
[Все сотрудники, у кого открыто приложение]
        ↓
   useOrgTheme получает событие
        ↓
   if enforce → applyOrgTheme() мгновенно
        ↓
   Баннер/цвета/анимация перерисовываются
   (без Ctrl+Shift+R, без перезагрузки)
```
