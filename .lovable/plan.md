

# Что можно улучшить в проекте — приоритизированный аудит

Прошёлся по всему коду (72 страницы, 120 edge-функций, 143 хука, 767 RLS-политик, ~28k строк только в `components/organization`). Ниже — **15 находок**, разбитых на 3 группы по приоритету. Реализуем по вашему выбору — целиком или частями.

---

## 🔴 Критично (стабильность и UX)

### 1. 766 использований `: any` — ловушки на проде
В типизированном проекте 766 мест с `any`. Особенно опасно в `WebinarsManager.tsx`, `StudentDashboard.tsx`, edge-инвокациях. Вы уже сталкивались с багом `room_name` именно потому, что типы не подсвечивали проблему.
**Действие:** ввести правило ESLint `no-explicit-any: warn`, починить top-20 файлов через `Database['public']['Tables'][...]['Row']`.

### 2. 45 из 55 `useQuery` без `staleTime`
Каждое монтирование компонента — лишний запрос к Supabase. На дашборде организации это 8–12 запросов при каждом переключении вкладок. Замедляет UX и грузит БД.
**Действие:** в `App.tsx` поднять `defaultOptions.queries.staleTime = 30_000`; для редко меняющихся (оргданные, тариф) — 5 мин.

### 3. `WebinarsManager.tsx` (574 строки) — монолит, в нём 14 useState
Любое изменение чревато регрессией. Аналогично `BulkDocumentGenerator.tsx` (849 строк), `OrgSidebar.tsx` (658), `IncomingDocumentsManager.tsx` (513).
**Действие:** разбить `WebinarsManager` на `WebinarsList` + `WebinarRow` + `useWebinarActions` (хук с handleStop/handleDelete/handleDuplicate); вынести интерфейс `Webinar` в `src/types/webinar.ts` (пока он продублирован в 3 местах).

### 4. `StudentDashboard.tsx` (506 строк) — `CatalogContent` принимает `props: any`
Внутренний компонент `CatalogContent` без типизации, всё через `any`. В нём же inline-загрузка T-Bank SDK через `<script>` — глобальный side-effect в JSX.
**Действие:** вынести `CatalogContent` в `src/components/student/CatalogContent.tsx` с явными props; `loadTBankSdk()` — в `src/utils/tbankSdk.ts`.

### 5. 1153 разрозненных вызова `toast({...})` / `toast.error(...)`
126 раз встречается просто строка «Ошибка» / «Произошла ошибка» — пользователь не понимает, что произошло. Edge-ошибки (rate limit, CORS, timeout) обрабатываются по-разному в каждом компоненте.
**Действие:** утилита `src/utils/handleSupabaseError.ts` — нормализует FunctionsHttpError/PostgrestError, показывает понятный текст; всем «голым» catch заменить `toast.error(getErrorMessage(e))`.

## 🟡 Заметные улучшения UX

### 6. Глобальный «Что нового» (changelog) — есть, но без push'а в кабинетах
Страница `/whats-new` существует, но организация не узнаёт, что вышло обновление, пока сама не зайдёт. Колокольчик «N новых» отсутствует.
**Действие:** в `OrgDashboardHeader` бейдж на иконке колокольчика по `platform_announcements` + `last_seen_announcement_at` в profile.

### 7. Нет сквозного поиска по сущностям внутри кабинета
`GlobalCommandPalette` (Cmd+K) есть, но он индексирует только разделы/вкладки. Найти курс/студента/документ по названию — нельзя. На 200+ студентах боль.
**Действие:** расширить палитру: при вводе ≥2 символов параллельно искать по `courses.title`, `profiles.full_name`, `org_documents.title` (с дебаунсом 250ms, лимит 5 каждой группы).

### 8. Нет «недавних элементов» в сайдбаре
Открыл курс → закрыл → ищешь снова в списке из 50. История взаимодействий не сохраняется.
**Действие:** localStorage-кеш «последние 5 курсов / 5 студентов» → секция «Недавнее» в верхней части сайдбара (как Notion / Linear).

### 9. Прогресс генерации ИИ-курса — без ETA
`generate-course-content` крутится 2–5 минут, пользователь видит спиннер без процента. Часто закрывают вкладку.
**Действие:** edge функция уже пишет промежуточные шаги в БД (видно по логам) — добавить realtime-подписку на `courses.generation_progress` (новое поле jsonb `{step, current, total, message}`) + прогресс-бар «Урок 7 из 35».

### 10. Дашборд организации не показывает «что требует внимания сегодня»
Сейчас сразу — список курсов. А заявки на зачисление, домашки на проверку, неоплаченные счета, истекающие подписи — спрятаны по разным вкладкам. У организации с 100+ студентами это десятки незамеченных событий в день.
**Действие:** виджет «Требует действия» сверху дашборда: 4 карточки с числами + «Перейти». Источники: `enrollment_requests` (статус pending), `homework` (pending review), `org_billing_documents` (unpaid >7д), `signatures` (expires in 3д).

## 🟢 Качество кода и инфраструктура

### 11. 120 edge-функций без общей обвязки CORS / auth / errors
Каждая функция дублирует CORS headers и парсит JWT. При смене формата ошибок — править 120 файлов.
**Действие:** в `_shared/` уже есть `cors.ts`; добавить `_shared/handler.ts` — `withAuth(req, async (user) => ...)` + автоматический CORS + единый формат `{ ok: true, data }` / `{ ok: false, code, message }`. Постепенно мигрировать новые функции.

### 12. Нет `staleTime` + invalidate-моменты не унифицированы
Некоторые мутации вызывают `qc.invalidateQueries(["org", id, "webinars"])`, другие просто `refetch()`. Иногда забыты — пользователь видит устаревшие данные до hard-refresh.
**Действие:** ввести `src/lib/queryKeys.ts` с типизированными ключами (`qk.org.webinars(id)`, `qk.org.courses(id)`); все invalidate — через них.

### 13. Утилита-обёртка для Supabase Storage с размером
В коде 30+ мест ручного формирования signed URL и обработки квоты. При смене bucket'а (org-stamps в private — недавно) — пришлось править 5 файлов.
**Действие:** `src/lib/storage.ts` с методами `getPublicUrl()`, `getSignedUrl()`, `uploadWithProgress()`; сюда же перенести логику отслеживания квоты (`useStorageMetrics`).

### 14. Логирование на проде
3 `console.log` в коде — это норма. Но edge-функции пишут в `console.log` без контекста (request_id, user_id), что усложняет дебаг проблем у конкретного пользователя.
**Действие:** в `_shared/logger.ts` функция `log({ level, fn, userId, requestId, ...meta })`; в новых функциях использовать вместо `console.log`.

### 15. Performance: `index.css` 1104 строки
Много кастомных классов и переопределений LiveKit. Часть наверняка не используется.
**Действие:** `npx purgecss` против `index.css` → отчёт по неиспользованному; вынести LiveKit-стили в отдельный `src/styles/livekit.css`, импортировать только в `EmbeddedWebinarPlayer`.

## Что предлагаю сделать в первую очередь

Если выберете «сделать самое полезное за один раунд», я бы сгруппировал так:

**Пакет А — «Заметный UX за день»** (пп. 6, 7, 10)
Колокольчик новостей + поиск по сущностям в Cmd+K + виджет «Требует внимания». Пользователь сразу почувствует разницу.

**Пакет Б — «Чистка под капотом»** (пп. 2, 5, 11)
`staleTime` глобально + `handleSupabaseError` + `_shared/handler.ts`. Невидимо для пользователя, но снижает нагрузку на БД и единообразит ошибки.

**Пакет В — «Прогресс ИИ + типизация»** (пп. 1, 9)
Прогресс-бар генерации курса + `Webinar` тип в `src/types/` + ESLint `no-explicit-any` warn.
