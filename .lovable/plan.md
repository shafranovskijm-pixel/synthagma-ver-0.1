

## Исправление: курсы маркетплейса не видны на бесплатном тарифе

### Проблема
При создании организации вызывается функция `apply_free_plan_features()`, которая **не включает** категорию `services` в список разрешённых:
```sql
enabled_cats TEXT[] := ARRAY['courses', 'students', 'settings', 'student_cabinet'];
-- 'services' отсутствует!
```

В коде клиента (`useOrgFeatures.ts`, строки 280-291) подписка является "финальным авторитетом" и должна перезаписывать значения из БД, используя `enabledCategories` из `subscriptionPlans.ts` (где `services` включён для всех тарифов). Однако:
1. В таблице `organization_feature_categories` для бесплатных организаций `services` = `false`
2. Если клиентский override не срабатывает (например, ошибка загрузки плана), то вкладка "Магазин курсов" блокируется в `OrgSidebar.handleTabClick`

### Решение (два шага)

**1. Миграция БД** — исправить функцию `apply_free_plan_features` и обновить существующие данные:
```sql
-- Обновить функцию: добавить 'services' в enabled_cats
-- Обновить все существующие бесплатные организации: SET is_enabled = true WHERE category_id = 'services'
```

**2. Исправить триггер `apply_plan_features_on_change`** — добавить `'services'` в массив free-плана (уже есть, но для надёжности проверим все пути).

### Файлы
| Изменение | Описание |
|-----------|----------|
| Миграция БД | Обновить `apply_free_plan_features()`: добавить `'services'` в `enabled_cats`. Обновить все записи `organization_feature_categories` для `services` на `true` для всех организаций |

Изменений в клиентском коде не требуется — клиент уже правильно переопределяет значения из БД на основе тарифа. Нужно только починить серверную сторону для консистентности.
