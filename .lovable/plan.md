## Что уже работает

- **Несколько шаблонов на организацию уже поддерживаются**: таблица `org_contract_templates` хранит любое количество шаблонов, кнопка «Загрузить шаблон» (`UploadTemplateDialog`) добавляет ещё один. В `GenerateContractDialog` все шаблоны организации подгружаются и доступны в выпадающем списке «Шаблон договора».
- Значит функциональность «несколько шаблонов + выбор при генерации» уже есть — не хватает **пошагового UX** и небольших доработок вокруг него.

## Что не так с текущей генерацией (анализ)

1. **Всё на одном экране** — тип контрагента, шаблон, ученик, мультивыбор, номер, дата, программа, часы, форма, цена, доп. переменные, предпросмотр. На маленьких экранах поля уходят вниз, кнопка «Сгенерировать» отключена, а почему — не видно (нужно прокручивать).
2. **Дубли выбора ученика**: сверху «Ученик (основной)» + отдельный блок «Список обучающихся». Пользователь путается, какой из них главный.
3. **Нет валидации по шагам** — можно долистать до конца и получить ошибку toast'ом.
4. **Предпросмотр всегда справа** — на первом шаге он пустой и занимает пол-экрана.
5. **«Дополнительные переменные шаблона»** появляются в общей простыне — их легко пропустить.
6. **Номер договора и дата** визуально тяжелее, чем должны быть для типового случая (Авто + сегодня).
7. **Программа обучения не обязательна**, но и не подсвечена — часто её забывают, а без неё пустые `{{course_title}}` / `{{program_title}}`.
8. **Выбор шаблона без превью** — не видно, что за шаблон, пока не выберешь.

## Что делаем

### 1. Пошаговый мастер генерации (Wizard)

Разбиваем `GenerateContractDialog` на 5 шагов с прогресс-индикатором сверху и кнопками «Назад / Далее / Сгенерировать» снизу. Каждый шаг валидируется — «Далее» неактивен, пока шаг не заполнен.

```text
[1 Контрагент] → [2 Шаблон] → [3 Стороны] → [4 Программа и цена] → [5 Номер, дата, проверка]
```

- **Шаг 1. Тип контрагента** — только 2 большие карточки «Физлицо / Юрлицо». Ничего лишнего.
- **Шаг 2. Шаблон договора** — список шаблонов организации карточками (название + дата, бейдж «по умолчанию»), под выбранным — мини-превью на 200px и краткая сводка «в шаблоне N переменных: …». Если шаблонов нет — CTA «Загрузить шаблон» прямо тут.
- **Шаг 3. Стороны договора**
  - Для физлица: **один блок** — мультивыбор учеников группы. Если выбран 1 — он же идёт в `{{individual_name}}`; если несколько — идут в `{{students_table}}`, а «основным» назначается первый в списке (можно перетащить/пометить звездой). Убираем дублирующее поле «Ученик (основной)».
  - Для юрлица: селект компании + опционально мультивыбор учеников (для `students_table` в договоре с юрлицом).
- **Шаг 4. Программа и цена** — курс, часы, форма, стоимость. Кнопка «Учебный план» тут же. Если в шаблоне нет `{{course_*}}` / `{{price}}` — шаг помечен «не требуется» и его можно пропустить.
- **Шаг 5. Номер, дата, финальная проверка** — режим номера (Авто / Ручной / Без), префикс, дата, дополнительные переменные шаблона (если есть), список незаполненных полей и **большой предпросмотр** на всю ширину. Кнопка «Сгенерировать и сохранить».

### 2. Улучшения выбора шаблона

- В `useOrgContractTemplates` уже есть флаг `is_default`. Показываем бейдж «По умолчанию» и при открытии мастера предвыбираем такой шаблон.
- Добавляем в карточку шаблона кнопку «Сделать шаблоном по умолчанию» (updates `is_default` — снимает флаг у остальных). *(Небольшая RPC или UPDATE двумя запросами в hook `upsert`.)*
- В `ContractsFolder` список загруженных шаблонов дополняем действием «Дублировать» — быстрый способ сделать вариацию (например, «для юрлиц» vs «для физлиц»).

### 3. Мелкие UX-починки в кнопке «Загрузить шаблон»

Кнопка `NewTemplateDialog` (старая) сейчас выглядит одинаково с «Загрузить шаблон» и путает — оставляем только `UploadTemplateDialog`, а «Новый шаблон с нуля» скрываем в меню «…» рядом (не удаляем, но убираем с главного места).

### 4. Прочее (без изменения бизнес-логики)

- Прогресс-бар сверху с кликабельными шагами (можно вернуться назад).
- На каждом шаге — «почему нельзя дальше» под кнопкой «Далее» человеческим языком.
- Сохраняем черновик в `sessionStorage` на случай случайного закрытия.

## Технические детали

- **Файлы для правок:**
  - `src/components/organization/group-folder/GenerateContractDialog.tsx` — рефакторинг в wizard: локальный `step` (1..5), функции `canProceed(step)`, разбиение JSX на 5 внутренних компонентов `Step1..Step5` в этом же файле.
  - `src/components/organization/group-folder/ContractsFolder.tsx` — кнопка «По умолчанию» / «Дублировать» на карточках шаблонов, скрытие «Новый шаблон» под меню.
  - `src/hooks/useOrgContracts.ts` — метод `setDefault(id)` (UPDATE `is_default=false` для всех + `true` для выбранного).
- **Схема БД не меняется** — `org_contract_templates.is_default` уже есть, множественность шаблонов уже поддерживается.
- **Логика подстановки переменных, генерации PDF, сохранения `org_contracts`** остаётся ровно такой же — меняется только оболочка ввода.

## Что специально НЕ делаем

- Не трогаем `templateRenderer`, `html-to-pdf`, RLS, RPC `get_next_document_number` — они работают и в этот тикет не входят.
- Не меняем `UploadTemplateDialog` (импорт шаблона) — по нему были отдельные улучшения ранее.
