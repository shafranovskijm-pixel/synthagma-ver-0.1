5. Проверю и при необходимости доправлю доступы к данным для чтения/просмотра ПЭП, ПД, документов и видеоидентификации для трёх ролей: ученик, организация, админ.

## Что уже нашёл

- В `StudentDocumentsTab` кнопки действий сейчас явно отключаются через `disabled={isAdminView}`. Поэтому в режиме просмотра из админки открыть ПЭП/ПД нельзя даже при корректном рендере.
- В `StudentDashboard.tsx` в режиме «войти как ученик» в `StudentProfileContent` и в верхние модалки местами передаётся `user.id` текущего пользователя, а не `effectiveUserId`/`targetUserId` выбранного ученика. Из-за этого часть запросов смотрит не в того пользователя.
- Верхние модалки (`showConsentForm`, `showDocumentsUpload`, `showVideoIdentification`) тоже привязаны к `user.id`, из-за чего админ/организация могут открывать не тот контент или не открывать его корректно.
- Политики доступа для чтения уже в целом есть:
  - `pep_agreements`: ученик видит свои, организация — свои по `organization_id`, админ — все.
  - `student_consents`: ученик видит свои, организация и админ видят по организации.
  - `student_identity_documents`: ученик видит свои, организация/админ могут управлять документами по организации.
  - `video_identifications`: ученик видит свои, организация видит записи своей организации.
- Значит основная поломка сейчас в UI-логике и в передаче идентификатора пользователя, а не только в RLS.

## План реализации

### 1. Исправить «режим просмотра ученика»
- В `StudentDashboard.tsx` заменить передачу `user.id` на целевой идентификатор ученика везде, где открываются профиль, ПЭП/ПД, загрузка документов и видеоидентификация.
- Вынести единый `effectiveUserId`/`effectiveUserEmail`/`effectiveUserName` в использование страницы, чтобы все дочерние компоненты работали согласованно.

### 2. Сделать блоки ПЭП и ПД всегда рендерящимися
- В `StudentDocumentsTab.tsx` убрать условия, из-за которых блоки могут не появиться при пустом `organizationId` на первом рендере.
- Оставить карточку/действие согласия видимой всегда.
- Внутри `StudentConsentForm.tsx` показывать ПЭП-секцию всегда, но с корректным состоянием:
  - loading
  - организация определяется
  - соглашение ПЭП ещё не принято
  - соглашение принято, можно подписать ПД
  - ПД уже подписано

### 3. Разблокировать действия для админа и организации
- Убрать глобальное `disabled={isAdminView}` у action-кнопок в `StudentDocumentsTab`.
- Разделить режимы:
  - ученик: может подписывать/загружать;
  - организация/админ: может открыть и посмотреть состояние, а записи менять только там, где это разрешено бизнес-логикой.
- Если для конкретного действия нужен read-only режим, передавать это явно пропсом (`readOnly`, `viewerRole`), а не выключать весь UI целиком.

### 4. Сделать ПЭП/ПД открываемыми из любых входов
- Привести к одному поведению открытие из:
  - вкладки «Документы»;
  - бейджа/хедера;
  - режима «войти как ученик».
- Убедиться, что при открытии модалки используется профиль именно просматриваемого ученика.

### 5. Проверить доступы и точечно доправить backend при необходимости
- После фикса UI сверить, не упираются ли чтение/просмотр в RLS для сценариев:
  - ученик смотрит свои ПЭП/ПД;
  - организация открывает кабинет ученика;
  - админ открывает кабинет ученика.
- Если найдётся пробел, добавить узкую корректировку политик только для нужных таблиц, без ослабления доступа к PII.

### 6. Проверка после внедрения
- Проверю 3 сценария:
  1. ученик — видит блоки, открывает ПЭП/ПД, загружает документы;
  2. организация — заходит как ученик, видит блоки и может открыть их для просмотра;
  3. админ — заходит как ученик, видит блоки и может открыть их для просмотра.
- Отдельно проверю, что кнопки реально отображаются и не disabled.
