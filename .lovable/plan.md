### Часть 2. Аудит шаблонной системы — слабые места

**2.1. Критичные баги (исправлю сразу)**

| # | Проблема | Где |
|---|---|---|
| A | `BenefitsBlueprintList` импортирует `safety-inline.png` — 1 PNG среди webp | `BenefitsBlueprintList.tsx` |
| B | `aurora-inline.png` и `aurora-inline-v2.jpg` — старые версии в репозитории | `assets/landing-templates/decor` |
| C | `aurora-cta-banner.jpg` и `aurora-pricing-orb.jpg` — дубли webp-версий | то же |
| D | `ReviewsCommitLog`: `String(11 - i)` даёт «00» и отрицательные при i≥11 | компонент |
| E | Нет проверки максимума элементов в audience/learn/benefits — UI ломается на 9+ | секции |
| F | При `applied_template_id`, но удалённом шаблоне → нет визуальной индикации | Gallery |

**2.2. UX-провалы, которые найдёт заказчик**

1. **Нельзя «отменить применение»** — после клика «Применить» содержимое заменяется без бэкапа. Решение: сохранять последние 3 версии `landing_content` в `course_landing_history` (новая таблица) с кнопкой «Откатить».
2. **Нельзя превьюить шаблон без курса** — гость с маркетинга не может оценить шаблоны. Решение: публичная страница `/landing-templates` с галереей.
3. **Нет «сравнения до/после»** — пользователь не видит, что именно поменяется. Решение: split-view в диалоге подтверждения (текущая страница слева, шаблон справа).
4. **Картинки фона нельзя поменять из UI** — только дефолтные. Решение: кнопка «Сменить декор» в LandingThemePanel с библиотекой webp.
5. **Аналитика применений не собирается** — не знаем, какой шаблон популярнее. Решение: лог в `analytics_events` при apply.
6. **Нет фильтров по категориям** в галерее — будет 10+ шаблонов и пользователь утонет. Решение: чипы Бизнес/IT/Бьюти/Языки/Охрана.
7. **Tier-метки `pro`/`premium` нигде не блокируются** — пользователь на free-тарифе нажмёт и применит. Решение: проверка плана в `handleApply` + замок на карточке.
8. **Применяется при пустом курсе и заголовок «Название курса»** — выглядит как баг. Решение: warning в диалоге «Сначала задайте название курса».

**2.3. Производительность**

- `LandingTemplateMiniPreview` рендерит **полный лендинг 1280px** для каждой карточки — на 5 шаблонах это 5 React-деревьев в DOM. На 10+ шаблонах будет лаг открытия модалки настроек. Решение: статичные PNG-снэпшоты (генерируются скриптом раз в релиз) + рендер живого превью только в полноэкранном диалоге.
- Все 5 шаблонов и их декор-webp импортируются eager-ом → попадают в основной чанк. Решение: `import.meta.glob('./templates/*', { eager: false })` с `React.lazy` per template.
- **APP_VERSION** в key каждого превью пересоздаёт всё дерево при любом релизе — лишние перерендеры. Достаточно `template.id`.

**2.4. Контентные пробелы**

- Шаблонов всего 5, заявлено покрытие «любая ниша». Не хватает: **Дети/Школа** (мягкий, дружелюбный), **Корпоратив/B2B** (графики, ROI), **Wellness/Психология** (пастель, плавные формы), **Финансы/Инвестиции** (графики, доверие), **Кулинария/Хобби** (фуд-фото).
- В каждом шаблоне `teachers` скрыт через `sections_hidden`. Нужно сделать варианты `teachers_layout` (карусель/grid/полароиды) хотя бы для 3 шаблонов, чтобы школа могла показать преподавателей.
- Нет варианта Pricing с **рассрочкой** — критично для образовательных продуктов.
- Нет блока **«Программа курса»** вариантов под шаблоны (сейчас один общий).

**2.5. Безопасность и совместимость**

- При apply шаблона **полностью переписывается** `landing_content`, но теряются кастомные поля, которых я не знаю в `existing` (защищены только seo/analytics/enrollment_form/external_url). Решение: deep-merge с whitelist «системных» ключей + сохранение всех неизвестных под капотом.
- Шаблоны не валидируются Zod — поломанный JSON в `data` отрендерит сломанный лендинг. Решение: `zod.parse` при загрузке, fallback на дефолт при ошибке.

### Технические детали

**Новая таблица:**
```sql
create table public.course_landing_history (
  id uuid primary key default gen_random_uuid(),
  course_id uuid references courses(id) on delete cascade,
  organization_id uuid not null,
  snapshot jsonb not null,
  source text, -- 'template:lab' | 'manual' | 'ai'
  created_by uuid references auth.users(id),
  created_at timestamptz default now()
);
-- RLS: organization owners + global admins
-- Триггер: перед update courses.landing_content → insert старого в history (макс 10 на курс)
```

**Tier-блокировка:**
В `handleApply` проверять `organizations.subscription_plan` против `template.tier` через RPC `can_use_template(plan, tier)`.
