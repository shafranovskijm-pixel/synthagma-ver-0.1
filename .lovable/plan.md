

# План: «Перепаковщик» файлов ФРДО — импорт чужого Excel → чистый шаблон

## Идея

В разделе ФРДО появится новая кнопка **«Очистить чужой файл»**. Менеджер загружает любой Excel, который ФИС ФРДО отклоняет (с невидимыми символами, лишними табуляциями, кривыми форматами СНИЛС/дат, без валидаций), а Синтагма автоматически:

1. Распознаёт структуру (DPO 41 колонок или ПО 35 колонок).
2. Извлекает данные построчно.
3. Чистит каждую ячейку (убирает невидимые пробелы, табуляции, ZWSP, NBSP, control-символы; нормализует СНИЛС, даты, пол, формы обучения).
4. Перекладывает в **наш эталонный шаблон** через существующие `buildDPORow`/`buildPORow` + `exportFRDOExcel` — с валидациями-выпадашками и `numFmt='@'` для СНИЛС.
5. Выдаёт чистый `.xlsx`, готовый к загрузке в ФИС ФРДО, и показывает **отчёт** — какие строки/ячейки были исправлены и какие требуют ручного ввода (отсутствует СНИЛС, не определён пол и т.п.).

## UI

В `FRDOManager.tsx` рядом с существующими кнопками («Выгрузить шаблон», «Загрузить подписанный») добавляется кнопка **«Перепроверить файл»** с иконкой `Wand2`.

По клику открывается диалог `FrdoFileSanitizerDialog`:

- **Шаг 1 — Загрузка.** Drop-zone (drag-n-drop или file picker), принимает `.xlsx`. Авто-определение типа (DPO/ПО) по заголовкам или ручной выбор переключателем.
- **Шаг 2 — Превью.** Таблица первых 20 строк с подсветкой исправленных ячеек (мягкий тёмно-бирюзовый фон) и красным — пустых обязательных. Внизу счётчик «Исправлено: 47 ячеек в 12 строках · Пустые обязательные: 3 строки».
- **Шаг 3 — Выгрузка.** Кнопка «Скачать чистый файл» — вызывает `exportFRDOExcel(rows, type, "очищено-DD-MM-YYYY")`. Опционально: «Скачать отчёт об исправлениях» (CSV — строка / колонка / было / стало).

Стиль — Teal/Cyan, скруглённые углы, анимация `framer-motion fadeUp`.

## Логика очистки (новый модуль `src/utils/frdoFileSanitizer.ts`)

```
parseFrdoXlsx(file: File) → { type: 'dpo'|'po', rows: RawRow[] }
  ↓ читаем через ExcelJS (уже в зависимостях)
  ↓ ищем header-строку по совпадению ≥6 эталонных заголовков
  ↓ маппим колонки источника → индексы наших DPO/PO_HEADERS

sanitizeCell(value, columnMeta) → { value, fixed: boolean, reason?: string }
  • убираем \u00A0, \u200B, \u200C, \u200D, \uFEFF, \t
  • trim + collapse whitespace
  • для СНИЛС: оставить цифры → форматировать "XXX-XXX-XXX YY"
  • для дат: распознать ISO/dd.MM.yyyy/Excel serial → "dd.MM.yyyy"
  • для пола: "М"/"мужской"/"male" → "Муж" (по словарю)
  • для формы обучения / финансирования / образования — fuzzy-match по списку из FRDO_VALIDATIONS
  • для гражданства — если число → 643 по умолчанию, иначе из словаря

buildCleanRows(rawRows, type) → (string|number)[][]
  • вызывает существующие buildDPORow/buildPORow → гарантия 41/35 колонок
  • возвращает массив для exportFRDOExcel
```

## Технические детали

- **Парсинг Excel:** `ExcelJS.Workbook().xlsx.load(arrayBuffer)`, читаем первый лист, ищем header-строку в первых 5 строках по эвристике (совпадение хотя бы 6 ожидаемых заголовков, без учёта регистра и невидимых символов).
- **Маппинг колонок:** строим словарь `{нормализованный_заголовок_источника → индекс_в_наших_HEADERS}`. Если в источнике колонка отсутствует — заполняем дефолтом (для статических полей: "Оригинал", "Нет", "643", "Очная", "Платное обучение", "в образовательной организации").
- **Auto-detect DPO/PO:** если в заголовках встречается «Программа профессионального обучения» / «профессий рабочих» — это ПО, иначе DPO.
- **Excel serial date:** числа 30000-60000 трактуем как Excel-даты (`new Date(Date.UTC(1899,11,30) + n*86400000)`).
- **Обязательные поля для отчёта:** ФИО, дата рождения, пол, СНИЛС, номер документа, дата выдачи, наименование программы. Если пусто — строка попадает в «требует ручного ввода», но всё равно экспортируется (пустая ячейка).
- **Без бэкенда:** вся обработка в браузере, файл клиента не уходит на сервер (важно для ПД).

## Что НЕ делаем

- Не меняем логику существующего экспорта по студентам.
- Не сохраняем загруженный файл в БД (только локально в памяти).
- Не пытаемся восстановить отсутствующие данные через ИИ — только очистка и переформатирование.
