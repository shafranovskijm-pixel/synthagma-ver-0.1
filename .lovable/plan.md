

# План: «боль ФИС ФРДО» на лендинге + продающий шаблон рассылки

## Идея

Использовать реальный скриншот ошибок ФИС ФРДО как наглядную «боль» — доказательство, что Синтагма закрывает реальную ежедневную проблему методистов (десятки строк «недопустимый символ», мучительная ручная чистка Excel перед загрузкой). Применить этот же приём в email-шаблоне для холодной рассылки — пусть письмо «бьёт в больное место» с первого экрана.

## 1. Лендинг `/feature/frdo` — добавить «Pain block»

Между блоками **«Сроки и штрафы»** и **«Типы программ»** вставить новую секцию:

```text
┌──────────────────────────────────────────────────────────┐
│  Знакомо?                                                │
│  Десятки строк "недопустимый символ" перед каждой        │
│  загрузкой в ФИС ФРДО — и так каждый месяц.              │
│                                                          │
│  ┌──────────── Скриншот ошибок (тот, что прислали) ──┐  │
│  │  Строка: 3 — К3 недопустимый символ...             │  │
│  │  Строка: 16 — К16 недопустимый символ...           │  │
│  │  Строка: 17 — К17 недопустимый символ...           │  │
│  │  ... ещё 8 строк ...                               │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  С Синтагмой — ноль ошибок:                              │
│  ✓ Авто-форматирование СНИЛС, дат, ФИО                   │
│  ✓ Очистка скрытых пробелов и табуляций                  │
│  ✓ Проверка полноты данных ДО выгрузки                   │
```

**Реализация:**
- Скопировать скриншот пользователя в `src/assets/features/frdo-errors-pain.png`
- Создать секцию `<section className="py-16 bg-destructive/5 border-y border-destructive/10">` с двумя колонками: слева — текст боли + чек-лист решений, справа — скриншот в рамке-«браузере» с лёгким наклоном/тенью.
- Вынести 4 чек-пункта решения с иконками (`Sparkles`, `ShieldCheck`, `CheckCircle2`, `FileSpreadsheet`).

## 2. Новый email-шаблон `frdoPain`

Добавить **8-й шаблон** `frdo_pain` в `src/components/admin/broadcast/emailTemplates.ts`:

**Структура письма:**
1. Шапка-плашка: «Знакомо?» (красно-янтарный градиент, эмодзи ⚠️)
2. Заголовок: *«Сколько часов в месяц вы тратите на чистку ФИС ФРДО?»*
3. Краткий рассказ боли (2 предложения): «Каждый месяц одно и то же — десятки строк "недопустимый символ", невидимые пробелы в СНИЛС, неправильные даты. Вы знаете эту картину…»
4. Цитата-картинка: HTML-блок с примерами реальных ошибок (стилизованный «скриншот» через таблицу + красный фон), чтобы не зависеть от блокировки внешних картинок в почтовых клиентах.
5. Секция «С Синтагмой это выглядит так»: 4 пункта-фичи (auto-СНИЛС, авто-даты, валидация до выгрузки, шаблоны 35/41).
6. Бонус-блок «А ещё мы автоматизируем»:
   - Авто-выпуск удостоверений при 100% прогресса
   - Электронную подпись (63-ФЗ)
   - Договоры/КП/счета из реквизитов
   - Журналы регистрации и корзину документов
7. CTA: **«Посмотреть, как это работает»** → `/feature/frdo`
8. Подпись + футер «СТОП».

**Тема письма:** *«Устали от ошибок ФИС ФРДО? Мы их убрали»*

## 3. Подключить шаблон в редактор рассылки

- Добавить `"frdo_pain"` в `BroadcastTemplate` union-тип
- Расширить `getEmailHtml` и `getEmailSubject`
- В `CampaignEditor.tsx` (или там, где список шаблонов) добавить опцию **«Боль ФИС ФРДО»** с пометкой 🔥 «Продающий».

## 4. Карточка шаблона в БД

Через миграцию вставить системный шаблон в `email_templates`:
- `key: 'frdo_pain'`
- `name: 'Боль ФИС ФРДО (продающий)'`
- `category: 'sales'`
- `subject` + `html_body` из новой функции
- Флаг `is_system = true`

## Что получим

- **Лендинг ФРДО** — теперь сразу «бьёт» в реальную боль методиста, конверсия выше за счёт узнавания.
- **Холодная рассылка** — новый шаблон «Боль ФРДО», который продаёт через узнаваемый кейс: получатель видит свой ежедневный ад в первом экране письма и сразу понимает выгоду.
- **Сквозная история «боль → решение → автоматизация»** — после ФРДО письмо ведёт к остальным закрываемым процессам (документы, подпись, договоры), что повышает воспринимаемую ценность платформы.
