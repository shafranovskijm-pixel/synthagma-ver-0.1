## Проблема

В проверщике файла ФРДО колонка L (`Наименование профессий рабочих, должностей служащих` для PO / `Наименование присвоенной квалификации` для DPO) на выходе идёт вида `Водитель Автомобиля` — с заглавной буквы **каждого** слова. Валидатор ФИС ФРДО сравнивает значение с классификатором ОКПДТР посимвольно, а канонические записи там в sentence-case: `Водитель автомобиля`. Из-за этого вся колонка L помечается как ошибка.

Причина в `sanitizeProfessionName` (`src/utils/frdoFileSanitizer.ts:353-364`):
```ts
const titled = cleaned.toLowerCase()
  .replace(/(^|[\s\-])([а-яёa-z])/gu, (_m, sep, ch) => sep + ch.toUpperCase());
```
Регулярка капитализирует первую букву **каждого** слова, а не только первого.

Плюс сейчас нет сверки со справочником — если клиент написал «водитель автомашины», мы не подскажем каноническое «Водитель автомобиля».

## Что делаю

### 1. Справочник профессий из шаблона
Внутри `src/assets/frdo/template-po.xlsx` уже лежит официальный список ОКПДТР — лист «Проверки», диапазон `L2:L5616` (defined name `Квалиф`), **5615 канонических наименований**. Извлекаю его в `src/constants/frdoProfessions.ts` как замороженный массив строк (одноразовая генерация Python-скриптом при билде плана; в рантайме — просто импорт JSON/TS).

### 2. Sentence-case + матч по справочнику
Переписываю `sanitizeProfessionName(raw)`:
1. Чистка невидимых/двойных пробелов (как сейчас).
2. Точный матч по канонической форме (сравнение через `deepNormalize`: lower + strip invisibles + collapse spaces + `ё→е`) — если совпало, возвращаю каноническое значение из справочника, `fixed: true`, `reason: "Подставлено каноническое значение классификатора ОКПДТР"`.
3. Если точного совпадения нет — sentence-case (заглавная только у первого символа), `reason: "Наименование не найдено в классификаторе ОКПДТР — проверьте вручную"` (уже помечается как «требует внимания» в UI ошибок).

Логика та же, что в `sanitizeProfessionalArea` для колонки области деятельности.

### 3. Применение
`sanitizeProfessionName` уже подключён через `kind: "profession"` для:
- PO, колонка L (index 11) — `Наименование профессий рабочих, должностей служащих`
- DPO, колонка N (index 13) — `Наименование квалификации/профессии/специальности`

Изменение автоматически применится к обоим листам. Отдельно проверю, что fallback-текст в `sanitizeByKind` не портит канонический ответ.

### 4. Тесты
В `src/utils/__tests__/frdoFileSanitizer.test.ts` добавляю кейсы:
- `"водитель автомобиля"` → `"Водитель автомобиля"` (не `"Водитель Автомобиля"`).
- `"ВОДИТЕЛЬ  АВТОМОБИЛЯ"` (двойной пробел, капс) → `"Водитель автомобиля"`.
- `"охранник"` → `"Охранник"`.
- Неизвестное `"водитель НЛО"` → `"Водитель нло"` + `reason` о том, что нет в классификаторе.

## Что НЕ трогаю

- Экспорт файла (`buildPORow`/`buildDPORow`), донор-шаблон, layout колонок — они уже правильно кладут значение в L.
- Резервный канал / SW / manifest — вне запроса.
- Другие колонки (СНИЛС/даты/пол/гражданство) — работают корректно.

## Технические детали

- Файл справочника весит ~150 КБ текстом. Импорт через прямой `import { FRDO_PROFESSIONS } from "@/constants/frdoProfessions"` — попадает в бандл только тем чанком, где используется санитайзер (диалог `FrdoFileSanitizerDialog`, лениво). Итоговый рост бандла на этом чанке ≈ 60 КБ gzip — приемлемо.
- Для быстрого lookup соберу `Map<normalizedKey, canonical>` один раз при первом вызове (module-level lazy).
- Совместимость: `sanitizeProfessionName` уже экспортируется и тестируется — сигнатура не меняется.
