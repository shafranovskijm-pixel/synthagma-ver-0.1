

## Проблемы

1. **Нестабильная валидация**: каждый раз при нажатии «Проверить все» результаты разные, потому что:
   - «Подозрительные» тесты (все одинаковые ответы + нет пояснений) — после частичного авто-фикса пояснения добавляются, и при следующей проверке эти вопросы уже не считаются подозрительными
   - Авто-фикс может частично провалиться (402 — нет кредитов), и курс остаётся в промежуточном состоянии
   - `is_validated` обновляется при каждой проверке, курсы «прыгают» между папками «Готово» и «В работе»

2. **Нет видимости**: непонятно, что именно не так с каждым курсом — только тост с текстом, который исчезает

## План улучшений

### 1. Панель результатов валидации (вместо тостов)

Добавить состояние `validationReport` — массив `{ courseId, title, issues[], status }`. После «Проверить все» показывать **сводную карточку** прямо в UI:

```text
┌─────────────────────────────────────────────┐
│ Результаты проверки           ✕ Закрыть     │
│                                             │
│ ✅ 198 курсов готово                        │
│ ❌ 3 курса с проблемами:                    │
│                                             │
│  • Б.1.1 — 2 урока без контента             │
│  • Б.2.3 — 5 вопросов без ответа            │
│  • Б.4.1 — Дубликаты заголовков             │
│                                             │
│ [🔧 Исправить все (3)]                      │
└─────────────────────────────────────────────┘
```

### 2. Стабилизация валидации

Убрать «подозрительную» эвристику (все одинаковые ответы) — она ненадёжна и даёт разные результаты. Оставить только чёткие критерии:
- `correct_answer === null` — вопрос без ответа
- Контент < 50 символов — пустой урок
- < 3 уроков, нет текстовых, нет тестов

Это сделает результаты **детерминированными**: проверяй хоть 10 раз — результат один.

### 3. Счётчики в заголовках групп

В каждой папке показывать мини-статистику: `✅ 198 / ❌ 3` рядом с названием группы, чтобы без раскрытия было видно состояние.

### 4. Не запускать авто-фикс автоматически

Вернуть ручной запуск фикса — сейчас после проверки сразу вызывается `handleBulkAutoFix`, что путает (не видно результатов проверки, сразу начинается исправление). Показать отчёт → пользователь нажимает «Исправить» если нужно.
