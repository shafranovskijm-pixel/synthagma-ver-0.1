
Цель: сделать так, чтобы у организаций меню всегда отображалось корректно (включая «Ученики»), даже при кеше/старой сессии.

Что уже проверено:
- В базе у всех организаций `menu_settings` уже содержит `showStudents=true` (и остальные ключевые пункты тоже `true`).
- В `organization_feature_categories` категория `students` включена.
- Для «АВРОРА» настройки корректны.
Вывод: проблема вероятнее всего в клиентском состоянии/кеше/устаревшей версии интерфейса, а не в текущих значениях таблиц.

План исправления (устойчивое решение):

1) Нормализация меню на уровне БД (для 100% консистентности)
- Миграция: принудительно обновить `organizations.menu_settings` у всех организаций до полного объекта с ключевыми разделами `true`.
- Это уберёт риск «битых»/неполных JSON в будущем.

2) Жёсткая защита в фронтенде для критичных пунктов
- В `useDashboardSettings` добавить нормализацию: даже если в БД пришло некорректное значение, критичные пункты (`courses`, `companies`, `students`, `journals`, `frdo`, `library`, `services`) приводятся к `true`.
- Таким образом «Ученики» и другие ключевые разделы нельзя случайно скрыть.

3) Кнопка «Обновить меню» для пользователя
- В `SettingsTab` добавить кнопку «Обновить меню»:
  - перечитывает `menu_settings` из базы,
  - обновляет состояние без перезахода.
- Рядом добавить «Восстановить меню по умолчанию» (сохранение дефолта в базу).

4) Автосинхронизация между устройствами
- В `useDashboardSettings` добавить realtime-подписку на строку организации:
  - при изменении `menu_settings` обновлять меню сразу у активных пользователей.

5) Антикеш-фолбэк для «вижу старый интерфейс»
- Добавить пользовательскую кнопку «Принудительно обновить интерфейс» (очистка SW/cache + reload).
- Для массового случая оставить админский «Сброс кеша у всех» как централизованный механизм.

Технические изменения:
- `supabase/migrations/*.sql`
  - `UPDATE organizations SET menu_settings = ...` (полный валидный JSON для меню).
- `src/hooks/useDashboardSettings.ts`
  - функция нормализации `normalizeMenuSettings()`,
  - `reloadMenuSettings()`,
  - `resetMenuSettings()`,
  - realtime-подписка на `organizations`.
- `src/components/organization/tabs/SettingsTab.tsx`
  - кнопки «Обновить меню» и «Восстановить меню».
- (опционально) `src/components/organization/OrgSidebar.tsx`
  - финальный safeguard, чтобы критичные пункты не скрывались при повреждённых данных.

Результат после внедрения:
- Во всех организациях ключевые пункты меню всегда отображаются.
- Пользователь может сам нажать «Обновить меню» и получить актуальные данные сразу.
- Проблемы из-за старого кеша перестают ломать видимость меню.
