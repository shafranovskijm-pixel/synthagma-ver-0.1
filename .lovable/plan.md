
## Что просит пользователь

1. **В карточке каждой организации** (админка) — учитывать в индикаторе «Хранилище» ещё и видео из Kinescope этой организации.
2. **В админке под «Настройками системы»** добавить раздел «Хранилище / Kinescope» — сколько занято в Kinescope, и если есть API — сколько это стоит (как на скриншоте Kinescope Billing: Доставка контента, Подготовка, Трансляции, Хранение, Итого).
3. Если Kinescope API отдаёт стоимость — подтягивать и её, чтобы видеть ориентировочные расходы.

## Что уже есть
- Индикатор хранилища организации в `useOrgDetailsView` / `useSubscriptionLimits` — считает только бакеты Lovable Cloud (`course-files`, `presentations`, ...). Видео Kinescope туда не попадают.
- Интеграция с Kinescope уже работает через edge-функции (TUS-загрузка, вебинары) — ключ Kinescope API уже хранится как секрет в edge-функциях.
- Каждый загруженный в Kinescope ролик имеет `kinescope_video_id`. В БД мы где-то храним эти ID (нужно подтвердить — скорее всего `lessons.video_url` / поле `kinescope_id` или в отдельной таблице). Это нужно, чтобы привязать видео к организации.

## Что нужно проверить на этапе реализации
1. Какие endpoint'ы Kinescope API доступны:
   - `GET /v1/videos` (с фильтром по folder/parent) — размер каждого видео (`size`/`duration`).
   - `GET /v1/projects` или `folders` — для группировки по организации (если используем структуру папок «папка = организация»).
   - Billing API — если у Kinescope есть `/v1/billing/usage` или аналог, подтягиваем стоимость. Если нет публичного — только размер хранилища, расчёт денег делаем по их публичному прайсу (или показываем пустую колонку).
2. Как сейчас в нашем коде хранятся `kinescope_video_id` и привязка к организации (поиск по `kinescope` в кодовой базе).

## Решение

### A. Edge-функция `kinescope-storage-stats`
Новая edge-функция (Lovable Cloud), которая:
- Принимает `organization_id` (опционально). Если не передан — собирает агрегат по всей платформе (для админ-панели).
- Идёт в Kinescope API с серверным ключом (секрет `KINESCOPE_API_KEY`), листает видео с пагинацией.
- Маппит видео на организацию через нашу БД: вытаскиваем все `kinescope_video_id`, привязанные к курсам/урокам/вебинарам этой организации, и суммируем размер только этих.
- Возвращает: `{ totalBytes, totalSeconds, videosCount, byOrg?: [...], billing?: { storage_rub, delivery_rub, ... } }`.
- Кеширует ответ в таблице `kinescope_usage_cache` на ~30 минут (Kinescope rate limits + не дёргать API на каждый просмотр карточки).

### B. Учёт Kinescope в индикаторе организации
- В `useOrgDetailsView` / `useSubscriptionLimits` после подсчёта бакетов вызывать `kinescope-storage-stats?org=…` и **прибавлять** `totalBytes` к `storageUsedBytes`.
- В UI (`OrgStatsPanel`, прогресс-бар) добавить разбивку: «Файлы Lovable Cloud: X МБ • Видео Kinescope: Y МБ • Всего: Z МБ».
- Подписку/лимит «∞» оставить как есть.

### C. Раздел в админке: «Хранилище и Kinescope»
- Новая вкладка/раздел в `AdminDashboard` (под «Настройки системы») — `AdminStorageOverview`.
- Показывает:
  - **Сводка по платформе**: общий объём Lovable Cloud (по бакетам), общий объём Kinescope (видео + часы), число роликов.
  - **Таблица по организациям**: имя орг → файлы (МБ) → Kinescope (МБ) → Kinescope (часы) → ориентировочная стоимость в ₽/мес.
  - **Расходы Kinescope текущего периода** — если API отдаёт billing, рендерим как на скриншоте: Доставка / Подготовка / Трансляции / Хранение / Итого. Если нет — показываем расчёт по публичному прайсу + бейдж «Оценка».
  - Кнопка «Обновить сейчас» (force refresh кеша).
- В карточке каждой организации тоже добавить мини-блок «Kinescope этой организации» (объём + ориентировочная стоимость).

### D. БД
- Таблица `kinescope_usage_cache (organization_id uuid null pk, total_bytes bigint, total_seconds bigint, videos_count int, billing_json jsonb, fetched_at timestamptz)`.
- `null` org_id = глобальный агрегат.
- RLS: чтение только админам; запись — только service role (edge-функция).

### E. Секреты
- Нужен `KINESCOPE_API_KEY` (Personal Access Token из Kinescope). Скорее всего уже есть для загрузки видео — переиспользуем. Если нет — запросим через `add_secret`.

## Этапы (после approve)
1. Найти в коде, где хранятся `kinescope_video_id` и как они связаны с организацией (поиск `kinescope`).
2. Уточнить у Kinescope API: endpoints для списка видео и billing (через `web_code_search` / их доку).
3. Создать таблицу `kinescope_usage_cache` + RLS.
4. Создать edge-функцию `kinescope-storage-stats` (агрегат по орг и по платформе, с кешем).
5. Подцепить вызов в `useOrgDetailsView` и `useSubscriptionLimits` — прибавить к `storageUsedBytes` и показать разбивку в `OrgStatsPanel`.
6. Создать `AdminStorageOverview` (новый раздел под «Настройки системы» в `AdminDashboard`) — сводка по платформе + таблица по орг + блок расходов Kinescope.
7. Проверить: открыть карточку орг — видно объём Kinescope; открыть админ-раздел «Хранилище» — видно общую сводку и расчёт стоимости.

## Открытый вопрос
Если у Kinescope **нет публичного billing API** (часто доступно только в их личном кабинете) — рассчитывать стоимость по их публичному прайсу (₽/ГБ/мес хранения, ₽/ГБ доставки) и показывать как «Ориентировочно». Это уточню в реализации; если совсем недоступно — оставим только объёмы хранилища и часы, а блок «Расходы» помечу «Доступно в Kinescope LK».
