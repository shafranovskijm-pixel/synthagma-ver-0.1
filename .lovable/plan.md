## Что происходит

При клике «Войти как» в списке организаций админку выкидывает в `/organization`, но:

- баннер «Режим просмотра: …» сверху не появляется,
- в шапке имя не подставляется («Организация» по умолчанию),
- сайдбар и данные соответствуют «пустой»/дефолтной оргe, а не целевой.

Это значит, что флаг `localStorage.adminViewAsOrg` **удаляется** до того, как режим успевает активироваться.

## Корневая причина

В коде две независимые точки читают `adminViewAsOrg` и обе делают одинаковую проверку `supabase.rpc('has_role', { _role: 'admin' })`:

- `src/hooks/useOrganization.ts` (строки 104–128)
- `src/hooks/useOrganizationDataLoader.ts` (строки 112–141)

Обе после проверки:

```ts
if (adminViewData && !isVerifiedAdmin) {
  localStorage.removeItem("adminViewAsOrg");
}
```

Проблемы:

1. **Транзиентная ошибка `has_role` = удаление флага.** Любой сетевой сбой/таймаут RPC даёт `data: null`, `!!isAdmin === false` — и флаг стирается, хотя пользователь реальный админ. После этого второй хук читает пустоту и падает в обычный флоу (профиль админа → нет `organization_id` → пустой дашборд без баннера).
2. **Гонка между двумя хуками.** Первый успевший «нeадмин»-ответ удаляет флаг; второй хук уже не видит его и активирует обычный режим — даже если у первого просто задержался ответ.
3. **Дубликат логики.** Два места решают один и тот же вопрос и могут разойтись.

Симптомы на скриншоте (нет админ-баннера, имя «Организация», пустая вкладка «Ученики») совпадают именно с этим сценарием: `adminViewAsOrg` был установлен `viewAsOrganization`, но стёрт до применения.

## Исправление

Мининвазивно, только фронт:

1. **Единый резолвер режима админ-просмотра** — новый утилитарный модуль `src/utils/adminViewOrg.ts` с функциями:
   - `readAdminViewOrg()` — синхронное чтение `{ id, name } | null`.
   - `resolveAdminViewOrg(userId)` — асинхронная проверка `has_role('admin')` с корректной обработкой ошибок:
     - при **ошибке** RPC или `null` → **не трогать** localStorage, вернуть `{ status: 'unknown' }` и относиться как «нет админ-режима на этот рендер» (но флаг не удалять — следующая попытка сможет активироваться);
     - при явном `false` → удалить флаг и вернуть `{ status: 'not_admin' }`;
     - при `true` → вернуть `{ status: 'admin', view: { id, name } }`.
   - `clearAdminViewOrg()` — для явного выхода (кнопка «Выйти» уже есть в `OrganizationDashboard.tsx`).
2. **Заменить дублирующие блоки** в `src/hooks/useOrganization.ts` (94–140) и `src/hooks/useOrganizationDataLoader.ts` (101–160) вызовом единого резолвера. Гонка исчезает: удаление флага возможно только при подтверждённом `false`.
3. **Проверка**: `bunx tsgo --noEmit` и `bun run build`, ручная проверка «Войти как» на организации «Центр охраны труда» — должен появиться баннер и корректно загрузиться дашборд целевой организации.

## Что не трогаем

- SQL/RPC (`can_access_organization`, `get_organization_students_page` и т.п.) — они уже корректно пропускают админа.
- NGINX/прокси, серверная пагинация StudentsTab, RLS.
- Логика `adminViewAsStudent` — она про учеников, не про организации.
