

## Корень проблемы

Сейчас HTML-договор для PDF собирается через самописный парсер `htmlToBlocks` + `pdf-lib` (`appendHtmlAsPages` в `pdfStampDrawer.ts`). Он:
- разбивает HTML на «блоки» регуляркой и теряет вложенные `<p>`, нумерацию пунктов «1.1», «1.1.1», переносы строк, отступы, выравнивание;
- склеивает текст в один поток без межабзацных интервалов → получается «простыня».

При этом в проекте уже есть проверенный паттерн для счетов/актов: **HTML-шаблон с inline-стилями → `window.print()` в браузере** (см. `useAdminBilling.ts`, `InvoiceView.tsx`, `useLaborSafetyManager.ts`). Он рендерит документ красиво, потому что использует реальный браузерный движок.

## Что меняем

### 1. Рендер тела договора через браузер, не через pdf-lib
Делаем единый рендер HTML → PNG-страницы → `pdf-lib` через `html2canvas` (он уже есть в зависимостях, используется на платформе).

Алгоритм в новой утилите `src/lib/htmlToPdfPages.ts`:
- создаём скрытый offscreen-контейнер `width = 794px` (A4 при 96dpi), `padding = 56px`, шрифт PT Sans, line-height 1.5;
- вставляем туда `documentHtml` с минимальным стилем (заголовок, отступы у `<p>`, нумерация `<ol>`, выделение `<ins>` зелёным фоном);
- через `html2canvas(scale: 2)` снимаем canvas всей высоты;
- режем canvas по высоте A4-страницы и каждый кусок embed'им в `pdf-lib` как PNG-страницу A4.
Это даст «как в счетах/актах» — со всеми отступами, жирным шрифтом, нумерацией, кириллицей.

### 2. Подпись на каждой странице
В `pdfStampDrawer.ts` добавляем `drawSignatureWatermark(page, party, opts)`:
- маленький блок ~180×80 в правом нижнем углу страницы (отступ 24pt от краёв);
- цвет — синий «как чернила» (`rgb(0.10, 0.30, 0.75)`), полупрозрачная рамка;
- содержимое: «Подписано · ПЭП», ФИО получателя/отправителя, дата подписи, последние 8 символов SHA-256;
- если подписали обе стороны — две полоски рядом, по 90px каждая.

После сборки тела договора проходим по **всем страницам** (`pdf.getPages()`) и наносим watermark — кроме финальной страницы со штампами и страницы «Принятые правки клиента» (там и так подпись большая).

### 3. Сохраняем сценарий PDF-вложения
Если оригинал — загруженный PDF, продолжаем брать его как есть, добавляем страницу «Принятые правки клиента» и финальный штамп — но **на каждой странице** оригинала тоже наносим тот же синий watermark.

### 4. Кеш
Хэш `computeBuildHash` уже зависит от `documentHtml` и подписей — пересборка после изменений сработает. Дополнительно подмешаем версию рендера (`renderer: "v2"`), чтобы старые кеш-файлы не отдавались.

## Файлы

- `src/lib/htmlToPdfPages.ts` — **новый**, html2canvas-рендер HTML в страницы PDF (offscreen iframe + slicing).
- `src/lib/pdfStampDrawer.ts`
  - удалить старый `appendHtmlAsPages` (или оставить как fallback для очень коротких текстов);
  - добавить `drawSignatureWatermark(page, sender, recipient, opts)`;
  - добавить `applyWatermarkToAllPages(pdf, sender, recipient, opts, skipPages)`.
- `src/lib/signedDocumentPdf.ts`
  - вызывать новый html2canvas-рендер вместо `appendHtmlAsPages` для HTML-договоров;
  - после сборки тела (HTML или вложенный PDF) вызывать `applyWatermarkToAllPages`;
  - в `computeBuildHash` добавить `renderer: "v2"`.

## Этапы

1. Реализовать `htmlToPdfPages.ts`: offscreen-контейнер с premium-стилями (PT Sans, отступы абзацев, `<ins>`-зелёный, нумерация), html2canvas, нарезка по высоте A4, добавление страниц в pdf-lib.
2. В `pdfStampDrawer.ts` добавить компактный синий watermark-блок и helper применения ко всем страницам с массивом исключений.
3. В `signedDocumentPdf.ts` переключить ветку HTML на новый рендер; после всей сборки наносить watermark на все страницы (исключая финальный штамп-разворот и список правок).
4. Обновить версию рендера в хэше → старые «уродливые» кеш-PDF будут пересобраны.
5. Проверка end-to-end:
   - HTML-договор → «Скачать подписанный PDF» → файл выглядит как полноценный документ (заголовки, абзацы, нумерация 1.1, 1.2, кириллица), на каждой странице справа внизу — синий мини-штамп ПЭП с ФИО и датой, в конце — большая страница со штампами обеих сторон.
   - PDF-вложение → каждая страница оригинала получает синий watermark, в конце — страница «Принятые правки клиента» + финальный штамп.
