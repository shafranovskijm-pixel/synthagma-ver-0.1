
## Что я уже подтвердил по коду

1. `BackgroundUploadsProvider` и трей загрузок реально подключены глобально (`src/App.tsx`), уведомления и запись в `org_notifications` уже есть.
2. Но в `src/hooks/useLessonMedia.ts` фоновая регистрация сделана не везде:
   - TUS-загрузка (`>100MB`) регистрируется в фоне;
   - обычная XHR-загрузка (`<=100MB`) не регистрируется как background task, поэтому для таких файлов нет нормального фонового поведения/уведомлений.
3. Поддержка `.ts` уже сделана кусками, но не везде:
   - есть `HlsVideoPlayer.tsx`;
   - в `VideoPlayerInline.tsx` у студентов уже есть логика для `.ts/.m2ts/.mts/.m3u8`;
   - но в редакторе и предпросмотре до сих пор много мест с обычным `<video>` и helper-логикой только для `.mp4/.webm/.mov`, поэтому `.ts` там не определяется и не проигрывается.
4. По скринам и текущему коду видно ещё одну проблему: загрузка `.ts` через «Видеосервис+» может падать на TUS (`500206 / failed to upload to storage`). Значит для TS нельзя опираться только на этот путь.

## Архитектурный вывод

Для `.TS` нужен не один “точечный фикс”, а единая стратегия:

- TS-загрузка должна идти в фоне всегда;
- TS-воспроизведение должно использовать один TS-aware player во всех местах;
- если загрузка через «Видеосервис+» для TS падает, нужен стабильный fallback на внутреннее хранилище, а не ошибка для пользователя.

## Что я предлагаю сделать

### 1) Починить настоящую фоновую загрузку для всех видео
В `src/hooks/useLessonMedia.ts`:
- вынести регистрацию background task до выбора способа загрузки;
- подключить `registerUpload / updateUpload / finishUpload / failUpload` и для XHR-пути, не только для TUS/Kinescope;
- сохранить текущую прямую запись URL в `lessons.content` после успешной загрузки;
- при переключении уроков загрузка продолжает идти, а уведомление приходит по завершении.

Результат: и `.ts`, и обычные видео будут грузиться в фоне одинаково.

### 2) Сделать единый TS-плеер для редактора, предпросмотра и студента
Заменить разрозненные raw `<video>`-превью на общий компонент:
- использовать `HlsVideoPlayer` либо унифицировать его с логикой `VideoPlayerInline`;
- подключить его в:
  - `src/components/course-builder/VideoPreviewInline.tsx`
  - `src/components/course-builder/SortableLessonItem.tsx`
  - `src/components/course-editor/LessonEditor.tsx`
  - `src/components/course-builder/block-editor/blocks/MediaBlocks.tsx`

Результат: `.ts/.m2ts/.mts/.m3u8` будет воспроизводиться одинаково в редакторе, предпросмотре и у студентов.

### 3) Доработать детекторы форматов
В helper-функциях сейчас рассинхрон:
- `courseBuilderHelpers.ts` знает про mp4/webm, но не про TS-family;
- `VideoPreviewInline.tsx` тоже режет поддержку по старому списку.

Нужно везде синхронизировать распознавание:
- `.ts`
- `.m2ts`
- `.mts`
- `.mpg`
- `.mpeg`
- `.m3u8`

Результат: TS будет не “непонятной ссылкой”, а нормальным direct video source.

### 4) Добавить fallback для TS, если «Видеосервис+» не принимает файл
Для TS-файлов:
- либо сразу отправлять их на внутреннюю загрузку по умолчанию;
- либо при ошибке Kinescope/TUS автоматически предлагать/запускать fallback на внутреннее хранилище.

Я бы сделал безопасный вариант:
- `.ts/.m2ts/.mts` по умолчанию грузить на внутреннее хранилище;
- «Видеосервис+» оставить рекомендуемым для MP4/MOV и обычных форматов.

Почему: по факту именно TS сейчас ломается на Kinescope-path, а внутренняя HLS-поддержка уже почти есть.

### 5) Не обещать конвертацию в MP4 на этом этапе
Сейчас в проекте нет готового фонового конвертера TS→MP4. Поэтому правильнее сначала сделать:
- стабильную фоновую загрузку;
- стабильное воспроизведение TS через HLS;
- fallback при ошибке внешнего видеосервиса.

Если потом захотите, отдельным этапом можно добавить backend-конвертацию в MP4, но это уже другая задача.

## Как перепроверю после правок

1. Загрузить `.ts` и сразу перейти к другому уроку.
2. Убедиться, что загрузка осталась в трее и не оборвалась.
3. Дождаться завершения и проверить:
   - toast,
   - звук,
   - запись уведомления,
   - сохранение URL у нужного урока.
4. Проверить воспроизведение одного и того же `.ts`:
   - в редакторе,
   - в предпросмотре,
   - у студента.
5. Проверить сценарий ошибки через «Видеосервис+»:
   - TS не должен “умирать без выхода”;
   - должен быть fallback или корректный безопасный путь загрузки.
