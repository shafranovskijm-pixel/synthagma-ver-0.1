

# Глобальная проверка на устойчивость при 2000 одновременных пользователях

## Обнаруженные проблемы

После анализа кодовой базы я выявил несколько узких мест, которые могут вызвать ошибки при 2000 одновременных пользователях:

### Проблема 1: Лимит 1000 строк в запросах
База данных по умолчанию возвращает максимум 1000 строк. В `fetchStudents()` запросы к `enrollments` и `profiles` НЕ используют пагинацию -- при >1000 записей данные обрезаются без ошибки.

### Проблема 2: Гонка состояний при сохранении прогресса видео
`useVideoProgress` сохраняет позицию через `upsert` каждую секунду (debounce). При 2000 пользователях одновременно -- тысячи конкурентных `upsert` запросов к `lesson_progress`.

### Проблема 3: Отсутствие retry-логики
Все запросы к БД в `CourseLearning.tsx` не имеют retry при временных ошибках (таймауты, лимиты соединений). Один сбой -- и ученик видит ошибку.

### Проблема 4: Синхронный XHR при закрытии страницы
В `useVideoProgress` используется синхронный `XMLHttpRequest` на `beforeunload` с анонным ключом вместо токена пользователя -- это и медленно, и может не пройти RLS.

### Проблема 5: Тяжёлые запросы при загрузке курса
`fetchCourseData()` делает 4 последовательных запроса вместо параллельных, что увеличивает время загрузки и нагрузку.

## Что будет сделано

### 1. Утилита retry с экспоненциальной задержкой
Создать `src/utils/retryFetch.ts` -- обёртку для Supabase-запросов с автоматическим повтором (до 3 попыток) при ошибках сети/таймаутах.

### 2. Пагинация для больших списков
Обновить `fetchStudents()` в `src/api/students.ts`: добавить цикл для загрузки всех записей порциями по 1000, чтобы не терять данные.

### 3. Оптимизация загрузки курса
В `CourseLearning.tsx` переделать `fetchCourseData()` -- запросы курса, уроков и зачисления запускать через `Promise.all` параллельно.

### 4. Увеличение debounce сохранения видео
В `useVideoProgress.ts`: увеличить минимальный интервал сохранения с 3 секунд/1сек-debounce до 10 секунд/3сек-debounce. Исправить `beforeunload` -- использовать `navigator.sendBeacon` вместо синхронного XHR.

### 5. Расширение системной диагностики
В `SystemDiagnostics.tsx` добавить новые проверки:
- **Нагрузочный тест БД** -- замер latency 10 последовательных запросов
- **Проверка лимита строк** -- предупреждение если enrollments/profiles >900 записей (близко к лимиту 1000)
- **Проверка конкурентных записей** -- тест upsert lesson_progress на конфликт
- **Проверка edge functions** -- пинг grade-test и get-test-results

### 6. Глобальный Error Boundary
Обновить `useErrorLogger.ts` -- добавить отправку критических ошибок в `system_diagnostics` для мониторинга. Добавить React Error Boundary компонент.

### Retry-утилита (пример)

```text
async function withRetry<T>(fn: () => Promise<T>, maxRetries = 3): Promise<T>
  - Попытка 1: немедленно
  - Попытка 2: через 1 сек
  - Попытка 3: через 3 сек
  - Если все попытки провалились -- бросает последнюю ошибку
```

### sendBeacon для сохранения прогресса

```text
navigator.sendBeacon(url, JSON.stringify(data))
  - Не блокирует закрытие вкладки
  - Гарантированно отправляется даже при unload
  - Работает с авторизацией через query-параметр apikey
```
