

## Анализ: что произойдёт при нажатии «Запустить все»

Код конвейера полностью готов и будет работать корректно. Вот что произойдёт для каждого из 16 курсов «В работе»:

### Порядок обработки каждого курса

1. **Решение тестов** — вопросы без ответов (`correct_answer = null`) отправляются в ИИ батчами по 60 шт.
2. **Верификация** (если включена) — перепроверка ответов второй моделью
3. **Генерация структуры** — если < 3 уроков, создаётся структура курса
4. **Заполнение контента** — для пустых уроков:
   - **Кэш** → если урок с таким же названием уже был заполнен в этой сессии — копируется мгновенно
   - **Поиск по БД** (`pg_trgm`, порог 0.4) → если похожий урок есть в базе — копируется без ИИ
   - **ИИ-генерация** → только если ничего не найдено; результат конвертируется через `markdownToBlocks()` в JSON
5. **Дедупликация** названий уроков
6. **Пометка курса как валидированного**

### Что уже исправлено

- ✅ `markdownToBlocks()` конвертирует Markdown → JSON-блоки перед записью в БД
- ✅ Поиск похожего контента (экономия токенов)
- ✅ In-memory кэш внутри сессии

### Единственный нюанс

**Кнопка «Конвертировать MD→JSON»** — её стоит нажать **до** запуска конвейера. Сейчас в БД ~1381 урок в Markdown-формате. Если конвертировать их сначала, то `find_similar_lesson_content` будет находить их при поиске и переиспользовать. Без конвертации поиск по БД тоже сработает (функция ищет по `content IS NOT NULL AND length > 100`), но скопированный контент будет в старом Markdown-формате — а конвейер при записи нового контента уже использует JSON.

### Рекомендация

1. Сначала нажмите **«Конвертировать MD→JSON»** — это одноразовая операция, ~30 сек
2. Потом нажмите **«Запустить все»** — конвейер обработает 16 курсов с максимальным переиспользованием контента

Никаких изменений в коде не требуется — всё готово к запуску.
