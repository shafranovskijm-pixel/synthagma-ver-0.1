

## Загрузка документов и ввод данных студентов со стороны организации

### Текущее состояние

- **Студент** может загружать свои документы (паспорт, СНИЛС, документ об образовании) через `StudentDocumentsUpload` в личном кабинете
- **Организация** может только **просматривать и удалять** загруженные документы во вкладке «Документы» карточки студента (`DocumentsTab`), но **не может загружать** новые
- СНИЛС и ФИО можно ввести только через ФРДО-диалог, который доступен из вкладки «Курсы» и привязан к конкретному зачислению

### Решение

Расширить вкладку «Документы» в карточке студента (организационная сторона), добавив:
1. **Кнопки загрузки документов** — организация сможет загружать паспорт, СНИЛС, документ об образовании за студента (аналогично студенческому интерфейсу)
2. **Блок ввода СНИЛС** — поле с маской `XXX-XXX-XXX XX` для быстрого ввода СНИЛС без захода в ФРДО
3. **Блок ФИО** — поля для фамилии, имени, отчества, даты рождения, которые сохраняются в `student_frdo_data`

### Изменения

| Файл | Что меняется |
|------|-------------|
| `src/components/organization/student-detail/DocumentsTab.tsx` | Добавить секцию загрузки документов (4 типа с кнопками «Загрузить»), блок ввода СНИЛС с маской, блок ФИО/дата рождения. Данные СНИЛС и ФИО сохраняются в `student_frdo_data` (upsert) |
| `src/hooks/useStudentDetailCard.ts` | Добавить загрузку `student_frdo_data` при открытии карточки, функции `saveFrdoField()` для сохранения отдельных полей (СНИЛС, ФИО, дата рождения), передать их в хук |

### Детали

- Загрузка документов уже реализована в хуке (`handleUploadClick`, `handleFileChange`) — нужно только добавить UI-кнопки в `DocumentsTab`
- СНИЛС форматируется через существующий `formatSnils()` из `src/utils/formatSnils.ts`
- Данные ФИО/СНИЛС сохраняются в таблицу `student_frdo_data` через upsert (INSERT ON CONFLICT UPDATE), не требуется миграция
- Без изменений в БД — все таблицы и RLS уже существуют
