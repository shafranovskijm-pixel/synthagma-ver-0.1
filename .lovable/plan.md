

## Анализ текущей реализации

**Что уже работает:**
- Шаблон «Аврора» залит во все секции и помечен `tier: "free"` — доступен всем планам, гейтинг по тарифу не блокирует.
- Применение мерджит данные шаблона в `landing_content` (slug, accent_color, SEO, тарифы из `course_pricing_tiers` остаются).
- Кнопка `«Применить шаблон»` уже есть.

**Что не так / отсутствует (узкие места):**
1. **Нет кнопки «Посмотреть»** — пользователь не может увидеть, как шаблон выглядит, не применив его.
2. **Поверхностный мердж (`{...existing, ...pending.data}`)** — если у пользователя есть кастомизация в `hero`, она полностью затирается на hero шаблона. Корректнее идти по секциям и затирать только те, что есть в шаблоне.
3. **Шаблон обезличен** (вода типа «Стратегия, которая работает») — не похож на реальный продающий лендинг. Нужны 2–3 ниши с конкретикой: маникюр, IT, языки, охрана труда.
4. **Превью-картинка одна и плоская** — нет ощущения «галереи».
5. **Нет аналитики «какой шаблон применили»** — на будущее для рейтинга.
6. **Слот «Скоро будет больше» загромождает сетку** при 1 шаблоне — лучше прятать когда шаблонов ≥ 3.
7. **Конструктор страницы не подсвечивает, что текущий контент — из шаблона** — сложно понять «можно ли применить другой шаблон без потерь».

## Что делаем

### 1. Кнопка «Посмотреть» (главное)

В каждой карточке шаблона в галерее — две кнопки:
- **«Посмотреть»** (variant outline) — открывает полноэкранный диалог с реальным рендером лендинга по данным шаблона. Внутри — те же `Landing*Section` компоненты, что используются на публичной странице курса, но в `isEditing={false}`. Подставляются реальные `orgName`, `courseTitle`, `accentColor` текущего курса. Снизу диалога — кнопка «Применить этот шаблон» и «Закрыть».
- **«Применить»** (variant default) — как сейчас, через AlertDialog подтверждения.

Новый файл: `src/components/course-editor/LandingTemplatePreviewDialog.tsx` — `Dialog` на весь экран (`max-w-6xl h-[90vh]`), внутри `ScrollArea` рендерит секции в `sections_order` (скрывает `sections_hidden`). Переиспользует все существующие `LandingHeroSection`, `LandingPricingSection`, и т.д.

### 2. Три полноценных продающих шаблона вместо одного

Вместо одного абстрактного «Аврора» — **3 готовых шаблона разных ниш**:

| ID | Название | Ниша | Акцент |
|---|---|---|---|
| `aurora` | «Аврора» | Универсальный премиум (бизнес/IT) | бирюза `#22b8a6` |
| `beauty` | «Атéлье» | Бьюти-курсы (маникюр, визаж, парикмахер) | пастель-розовый `#e879a6` |
| `safety` | «Эталон» | Охрана труда / ДПО / профобучение | синий `#2563eb` |

Каждый шаблон — со своим `hero.subtitle`, `audience`, `learn`, `benefits`, `pricing` (3 тарифа с реалистичными ценами для ниши: бьюти 4900/9900/19900, ОТ 3500/7500/15000, универсал 9900/19900/39900), `reviews` с правдоподобными именами и текстами, `faq` под нишу (вопросы про оборудование/материалы для бьюти, про удостоверения для ОТ).

Новые файлы:
- `src/lib/landing-templates/beauty.ts`
- `src/lib/landing-templates/safety.ts`
- В `index.ts` добавить в массив.

### 3. Улучшение применения шаблона (узкое место №2)

В `LandingTemplatesGallery.handleApply` мерджить **по секциям** (а не shallow):
```ts
const merged = {
  ...existing,
  ...pending.data,
  // SEO и аналитика — точно сохраняем
  seo: existing.seo,
  analytics: existing.analytics,
  enrollment_form: existing.enrollment_form,
  external_url: existing.external_url,
};
```
Это гарантирует: SEO, аналитика, форма записи и редирект **не сбрасываются** при применении шаблона.

### 4. Метка применённого шаблона + аналитика

Добавить в `landing_content` поле `applied_template_id: string | null`. Сохраняется при применении. В `LandingTemplatesGallery` карточка применённого шаблона получает бейдж «Активный» и подсветку.

Польза: позже сделаем «откатить шаблон / перейти на другой» с предупреждением, а также соберём метрику популярности.

### 5. Прятать слот-плашку когда шаблонов 3+

В сетке: `LANDING_TEMPLATES.length < 3` → показываем «Скоро будет больше», иначе скрываем.

### 6. Будущие функции (не делаем сейчас, но закладываем структуру)

Уже сейчас тип `LandingTemplate` поддерживает `tier`. Чтобы заложить рост:
- В `types.ts` добавить опциональные поля `category?: 'business'|'beauty'|'edu'|'lang'|'it'`, `cover_color?: string`, `is_new?: boolean` — для будущих фильтров и бейджа NEW.
- Документировать в комментарии файла, как добавить новый шаблон (3 шага: создать `xxx.ts`, добавить в `index.ts`, положить превью в `assets/landing-templates/`).

Гейтинг по тарифу через `tier !== 'free'` — добавим, когда подключим первый `pro`-шаблон. Сейчас все три `tier: 'free'`.
