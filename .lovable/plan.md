## Что меняем в `SalesShiftView.tsx`

### 1. Приветствие «Привет, Алёна»
Сейчас в режиме «Просмотр от лица менеджера» `user` — админ, поэтому имя падает на email-префикс («24»). Возьмём имя из `getAdminSalesView().fullName`, если админ импресонирует; иначе — как сейчас (sales_managers → profiles → email). Из полного ФИО берём только первое слово («Алёнка» / «Алёна»). Для счётчиков «дозвонов» и managerId в этом режиме используем `viewAs.managerId` и `viewAs.userId`, чтобы прогресс показывал реальные звонки менеджера, а не админа.

### 2. Карточка кликается целиком, без отдельной кнопки «Позвонить»
- Убираем правые кнопки «Позвонить» и «Открыть».
- Весь `<div>` строки становится `<button>`-подобным (`role="button"`, `tabIndex`, `onClick`, `onKeyDown` для Enter/Space) с hover/focus-стилями.
- По клику: `openLead(lead)` → открывается `CompanyDrawer`, где уже живут скрипт, кнопка Novofon-звонка и лог итога звонка. Автозвонок из ленты не делаем — пусть менеджер решает внутри карточки (в drawer уже есть кнопка «Позвонить»). Верхний `ColdCallScriptCard` остаётся как общий скрипт первого касания — не удаляем.

### 3. Вкладки «В работе» / «Обработано»
Над лентой добавляем `Tabs` (shadcn) с двумя значениями: `active`, `done`.

Определение «обработано»:
- лид имеет активность (`sales_lead_activities`) от текущего менеджера сегодня (created_at ≥ начало дня), ИЛИ
- статус лида ∈ {`not_interested`, `proposal_sent`, `contract_sent`, `won`, `lost`, `demo_scheduled`, `callback_later`} и updated_at ≥ начало дня.

Реализация:
- Один раз при загрузке (и по realtime-инвалидации, которая уже подписана) тянем `sales_lead_activities.select(lead_id, created_at).eq('manager_id', mid).gte('created_at', startOfDay)` → `Set<processedLeadIds>`.
- `queue` из `buildShiftQueue` фильтруем: `active` = не в set И статус не «финальный сегодня»; `done` = в set ИЛИ финальный статус сегодня.
- Пагинация (10 на страницу) и счётчик в бэйдже применяются к активной вкладке. При переключении вкладки сбрасываем `page = 1`.
- На вкладке «Обработано» карточка показывает бэйдж со статусом/результатом (по последней активности — берём `description` первой строки «Результат: …»). Клик так же открывает drawer, чтобы можно было посмотреть/дообработать.

Автоперенос после обработки: `onSaveAndNext` уже закрывает drawer; т.к. `processedLeadIds` пересчитывается по realtime `sales_lead_activities`, лид исчезнет из «В работе» и появится в «Обработано» без ручного refresh.

### Технические детали
- Новый state: `viewAs = getAdminSalesView()` считаем один раз, `processedIds: Set<string>`, `tab: 'active' | 'done'`.
- Функция `loadProcessed(mid)` вызывается из того же useEffect, что и `refreshCounters`, и из realtime-подписки на `sales_lead_activities` (уже есть).
- Никаких изменений схемы БД, edge-функций и других файлов не требуется.
- `ColdCallScriptCard`, `CompanyDrawer`, `TestCallDialog` остаются как есть.

### Проверка
- Под админом «Войти как Алёнка» → приветствие «Привет, Алёнка!», счётчики её.
- Клик по любой карточке в ленте открывает drawer; внутри есть звонок и скрипт.
- После сохранения итога звонка карточка уходит со вкладки «В работе» и появляется на «Обработано» (realtime).
