
Причина, почему у тебя «как будто откатывается» в режиме разработки, по текущему коду почти наверняка в механике кеш-бастинга:
1) В `index.html` inline-скрипт использует статичный `CACHE_VER = 'v2026-03-19'` (не привязан к каждой новой сборке).
2) Там же логика `key-init` сейчас не гарантирует reload после очистки кеша (очистка может произойти, но страница остаётся на старом уже загруженном JS до следующего ручного обновления).
3) Для preview-домена нет жёсткого «одноразового» принудительного обновления при входе в редактор.

Из-за этого в редакторе можно снова видеть старый UI (например, без последних правок), даже если код уже новый.

Что внедряем (устойчиво, без ручной магии):

1. Переписать ранний cache-bootstrap в `index.html`
- Убрать текущую ветку с `CACHE_VER/key-init`.
- Сделать единый `purgeAndReloadOnce(guardKey)`:
  - unregister всех SW,
  - очистка `CacheStorage`,
  - `location.reload()` ровно 1 раз по guard-ключу в `sessionStorage`.
- Для preview (`hostname` содержит `preview--` или `localhost`) запускать этот purge+reload автоматически при первом заходе в сессию.
- Для production/public — запускать purge+reload при смене «версии ассетов» (не статичная строка, а вычисляемый идентификатор текущего module-script src/сборки).

2. Синхронизировать `main.tsx` с новым bootstrap (без конфликтов guard-ключей)
- Разделить guard-ключи:
  - build-refresh guard,
  - remote-refresh guard,
  - manual-refresh guard.
- Оставить version-check в `main.tsx` как вторую линию защиты, но чтобы он не конфликтовал с inline-скриптом.
- Не допускать циклов перезагрузки при любом сценарии.

3. Укрепить ручной фолбэк обновления интерфейса
- В `src/utils/forceClientRefresh.ts` использовать те же guard-правила, что и в bootstrap.
- Кнопку «Обновить интерфейс» на логине оставить, но сделать максимально заметной (чтобы пользователь мог восстановиться за 1 клик, если снова залип на старом клиенте).

4. Добавить быстрый технический индикатор версии (для диагностики «старый/новый UI»)
- Показать внизу логина маленький build-id (или timestamp сборки) только в preview/dev режиме.
- Это сразу даст визуально понять, что реально загрузилось, и снимет спор «точно ли новая версия».

Файлы, которые будут изменены:
- `index.html` — полный пересмотр inline cache/SW bootstrap.
- `src/main.tsx` — развязка guard-ключей и согласование с bootstrap.
- `src/utils/forceClientRefresh.ts` — единый надежный manual refresh-путь.
- `src/pages/Login.tsx` — улучшение видимости ручного обновления + (в preview) отображение build-id.

Проверка после внедрения:
1) Открыть preview в редакторе → должен загрузиться актуальный UI (без ручного Ctrl+F5).
2) Закрыть/открыть preview снова → снова актуальная версия, без «отката».
3) Нажать «Обновить интерфейс» на логине → 1 controlled reload, без циклов.
4) Сверить build-id на экране с ожидаемой новой сборкой.
5) Проверить опубликованный сайт: обычный вход, без лишних перезагрузок и без деградации UX.
