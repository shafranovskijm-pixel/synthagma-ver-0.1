# Расширенный отчёт диагностики соединения

## Что добавим

На страницу **«Проверка соединения»** (`/connection-check`) добавим новый блок **«Информация об устройстве и сети»** ниже существующих 4 проверок. Эта информация автоматически попадает в скачиваемый/копируемый отчёт — пользователю не нужно ничего объяснять, достаточно прислать файл вам.

## Какие данные собираем

### 1. Устройство и браузер
- User Agent (полная строка)
- Тип устройства (Desktop / Mobile / Tablet) и ОС (Windows / iOS / Android / macOS) с версией
- Браузер и его версия (Chrome 131, Safari 18, Yandex и т.д.)
- Язык интерфейса, часовой пояс
- Размер экрана и devicePixelRatio
- Признак PWA-режима (`display-mode: standalone`)
- Признак Telegram WebView / VK / встроенного браузера соцсетей (частая причина странных сбоев)

### 2. Сеть (без раскрытия точного IP)
- Сетевой тип и скорость через `navigator.connection` (4g/wifi/3g, downlink, RTT, saveData)
- **Гео по IP** через бесплатный `https://ipapi.co/json/` (страна, регион, город, провайдер/ASN, организация). Это покажет: мобильный оператор? корпоративная сеть? VPN с зарубежным IP?
- Признак VPN — эвристика: страна не RU + название ASN содержит «VPN/Proxy/Hosting»
- Онлайн/офлайн статус браузера

### 3. Кеш и версия PWA
- Активна ли регистрация Service Worker, его scope и состояние
- Список Cache Storage с количеством записей (видно, что закешировано старое)
- Версия приложения из `appVersion.ts` / build hash
- Размер использованного storage через `navigator.storage.estimate()`
- Статус прокси-режима (`getProxyStatus()` из `proxyFetch.ts`) — включён ли резервный канал через Cloudflare Worker

### 4. Доменная диагностика
- С какого домена открыто (cyrillic `синтагма.рф` vs `sintagma.com.ru` vs `lovable.app`) — частая проблема iOS
- Был ли применён авторедирект с кириллического домена

### 5. Расширенные сетевые пробы (в дополнение к текущим 4)
- Пинг до `cloudflare.com` (быстрый сторонний эталон)
- Пинг до `api.sintagma.com.ru` (если прокси настроен) — отдельной строкой, чтобы видеть, работает ли резервный канал, когда прямой не работает
- Проверка доступности Kinescope (`kinescope.io`) — для жалоб на видео

## Как это выглядит на странице

Под существующими 4 проверками появляется свёрнутая по умолчанию карточка **«Подробная информация об устройстве»** с кнопкой «Развернуть». Внутри — компактный список «ключ: значение» с группами (Устройство / Сеть / Кеш / Домен). Все эти данные автоматически попадают в текстовый отчёт при нажатии «Скачать отчёт» / «Копировать отчёт» — структурированной секцией в конце.

Пробы из п.5 показываются как обычные строки в общем списке проверок — с зелёным/красным/жёлтым индикатором.

## Технические детали

### Новые/изменённые файлы

- **`src/utils/deviceDiagnostics.ts`** (новый) — функция `collectDeviceInfo()`, возвращает структурированный объект со всеми полями выше. Парсит UA через лёгкий собственный матчер (без внешних либ — Bowser весит 30кб, не нужен). Делает безопасный `fetch('https://ipapi.co/json/')` с таймаутом 4с и graceful-fallback (если заблокирован — пишет «недоступно», не валит страницу).
- **`src/utils/connectionDiagnostics.ts`** — добавляем 2 новые пробы: Cloudflare и (опционально) прокси-канал api.sintagma.com.ru. Расширяем `buildDiagnosticsReport()` так, чтобы он включал секцию Device Info с понятными подписями на русском.
- **`src/pages/ConnectionCheck.tsx`** — рендерим новую сворачиваемую карточку `DeviceInfoCard` с данными из `collectDeviceInfo()`. При первом рендере подгружаем инфу параллельно с пробами.
- **`src/components/diagnostics/DeviceInfoCard.tsx`** (новый) — UI-компонент карточки с группировкой и кнопкой «Копировать только эту секцию».

### Приватность

- IP-адрес в отчёт **не пишем** напрямую, только страну/город/провайдера. Это снимает вопросы по 152-ФЗ.
- Запрос к `ipapi.co` идёт от браузера пользователя, а не с нашего сервера — мы не храним их IP.
- Никаких cookies/localStorage с этой страницы не читаем (кроме `getProxyStatus()`).

## Что это даст вам

Когда пользователь пришлёт отчёт, вы за 5 секунд увидите:
- **Telegram WebView + iOS 17** → классические глюки с auth-cookie
- **Yandex Browser + старая версия PWA** → нужен сброс кеша
- **IP-страна = NL, ASN = "Hetzner"** → у человека VPN, который уводит трафик через хостинг (часто блокируется на стороне платежей)
- **Service Worker неактивен** → блокирует антивирус
- **Прокси-режим включён, но прямой канал OK** → можно посоветовать выключить
