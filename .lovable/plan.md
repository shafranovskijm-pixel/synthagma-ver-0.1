

## Проблема

Сейчас конвейер показывает минимум информации:
- Счётчик `0/208 готово` обновляется только после полного завершения курса
- Очередь свёрнута по умолчанию — не видно, что происходит
- При ошибке лог не раскрывается автоматически
- Нет итогового сводного отчёта (сколько всего вопросов решено, сколько пропущено, причины остановки)
- `currentPhase` показывает текущее действие, но не сохраняет историю

## План улучшений

### 1. Автоматическое раскрытие очереди при запуске
При нажатии «Запустить все» — `setQueueOpen(true)`, чтобы пользователь сразу видел лог.

### 2. Расширенный лог с деталями ошибок
Добавить в `LogEntry` поле `skippedBatches` (число пропущенных батчей после 3 retry) и `totalQuestions` (сколько всего вопросов было в курсе). В очереди показывать:
- ✅ `"45 тестов решено, 2 уроков"` — для успешных
- ⚠️ `"23/50 решено, 3 батча пропущено (rate limit)"` — для частично решённых
- ❌ `"Ошибка: Network error"` — для сбоев

### 3. Итоговая сводка после завершения
После окончания конвейера показать карточку-сводку:
- Всего курсов обработано: X
- Успешно: Y, с ошибками: Z
- Всего тестов решено: N
- Всего уроков заполнено: M
- Время работы: T мин

### 4. Трекинг пропущенных батчей в processCourse
Добавить счётчик `skippedBatches` в функцию `processCourse`. Возвращать его в результате. Если батч пропущен после 3 retry — `skippedBatches++`. Это позволит показать в логе, что курс обработан частично.

### 5. Сохранение currentPhase в лог при ошибке
Если `processCourse` бросает исключение, сохранять `currentPhase` в `log.message`, чтобы было видно, на каком шаге произошёл сбой.

### Конкретные правки

**Файл: `src/components/admin/BulkPipelineWidget.tsx`**

1. **LogEntry** — добавить `skippedBatches?: number`, `totalQuestions?: number`
2. **processCourse** — возвращать `{ ok, lessonsFilled, testsSolved, skippedBatches, totalQuestions }`; считать `skippedBatches` при неудачных retry
3. **handleStart** — добавить `setQueueOpen(true)` в начале; сохранять `currentPhase` в `message` при ошибке; после цикла показать итоговую сводку через toast или отдельный state
4. **Итоговая сводка** — новый state `summary` (totalSolved, totalFilled, totalErrors, duration). Показать карточку после завершения
5. **UI очереди** — в колонке «Детали» показывать `skippedBatches` если > 0 (жёлтая иконка + текст)
