
Цель: исправить импорт так, чтобы курсы реально создавались, распределялись по текущим категориям, отсутствующие категории создавались автоматически, а программы с 250+ часами попадали в блок профподготовки.

1) Что сейчас ломает результат
- В `ProgramListImporter.tsx` часть ошибок “глотается”:
  - при создании категорий не проверяется `error`;
  - при создании `marketplace_courses` не проверяется `error`.
  В итоге можно получить “0 создано” без понятной причины.
- Для “Рабочие профессии” ставится `parent_type: "Профессиональное обучение"`, а витрины/админ-группировка ожидают фиксированные типы (`Повышение квалификации`, `Профессиональная переподготовка`, `Охрана труда / Пожарная безопасность`, `Рабочие профессии`), из-за этого раздел не попадает в нужную ветку.
- Дедупликация через `ilike` по первым 30 символам слишком грубая и может ложно пропускать курсы.

2) Что реализуем
- Перепишем логику импорта в `ProgramListImporter` на детерминированную:
  - нормализация названия (lowercase, схлопывание пробелов, удаление служебной пунктуации);
  - дедупликация по нормализованному точному совпадению, а не по `ilike %slice(0,30)%`.
- Добавим явный классификатор:
  - по текущим категориям (Охрана труда, Пожарная безопасность, Экологическая безопасность, Разное, Рабочие профессии);
  - если категория отсутствует — создаём;
  - правило 250+ часов: отправляем в “Профессиональная подготовка” (под `Профессиональная переподготовка`) согласно вашему требованию.
- Исправим `parent_type` для новых категорий:
  - рабочие — `Рабочие профессии`;
  - профподготовка 250+ — `Профессиональная переподготовка`;
  - остальное — по текущей иерархии.
- Сделаем импорт идемпотентным:
  - повторный запуск не создаёт дубли;
  - создаёт только реально отсутствующие курсы.
- Добавим прозрачный отчёт после запуска:
  - создано / пропущено / ошибок;
  - список конкретных ошибок (категория, курс, причина).

3) Синхронизация уже существующих данных (чтобы исправить “сейчас ноль”)
- В том же процессе импорта добавим режим “досоздать и распределить”:
  - создать недостающие категории;
  - создать отсутствующие курсы из перечня;
  - проставить `category_id` у импортированных курсов, если пусто или неверно.
- Это закроет текущую ситуацию без ручной правки каждой записи.

4) Файлы
- `src/components/admin/ProgramListImporter.tsx` — основная логика импорта, классификатор, проверка ошибок, идемпотентность, отчёт.
- `src/hooks/useAdminMarketplace.ts` — нормализация `parent_type` (совместимость и корректная группировка).
- `src/components/student/StudentCourseStore.tsx` и `src/hooks/useCourseStoreManager.ts` — та же нормализация группировки, чтобы категории одинаково отображались в админке и витрине.

5) Критерии готовности
- После импорта в админке не “0” по “Рабочие профессии”.
- Курсы из файла появляются в нужных категориях.
- 250+ часов попадают в ветку профподготовки.
- Повторный запуск не плодит дублей.
- Пользователь видит понятный итог с ошибками поштучно, а не “молча 0”.
