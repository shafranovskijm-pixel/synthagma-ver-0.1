

# План: исправить «Разделы меню» + добавить Продажи + объединить документооборот

## Проблема 1. UI настроек врёт

`OrgProfileTab.tsx` показывает 5 тумблеров с локальным `DEFAULT_MENU = { все: true }`, а реальный сайдбар читает 16 полей из `useDashboardSettings.ts` с другими дефолтами. Тумблеры не показывают, что реально включено.

**Решение:** переписать раздел «Разделы меню» так, чтобы:
- Источник правды — `normalizeMenuSettings` из `useDashboardSettings.ts` (а не локальный `DEFAULT_MENU`).
- Показывать **все** управляемые секции единым списком, разбитым на 4 группы:
  - **Обучение:** Курсы, Ученики, Компании, Задания, Чаты *(всегда видны, серым цветом)*
  - **Аналитика:** Статистика, Ссылки регистрации
  - **Бизнес:** Финансы *(всегда)*, **Продажи** *(новый тумблер)*, ИИ-преподаватели, Маркетплейс, Витрина, Подписка
  - **Документооборот:** Документы, Журналы, ФРДО, Охрана труда
- Тумблер показывает реальное состояние из БД (включая `false` по умолчанию).
- Бейдж «Beta» рядом с «Продажи» и «ИИ-преподаватели».
- Бейдж «Платный» рядом с тарифными модулями (Охрана труда — Профессиональный).

## Проблема 2. Продажи спрятаны

Сейчас `showSales` включается только через `?enableSales=1`. Сделать тумблер видимым в настройках — с предупреждением «Раздел в beta. Включает CRM-функции: КП, договоры, рассылки».

## Проблема 3. Документы vs Продажи — объединить умно

Полностью объединять нельзя (разная аудитория), но можно сгруппировать. Предлагаю **«Документооборот» как единый раздел верхнего уровня** с внутренними табами:

```text
┌─ Документооборот ────────────────────────────────────────┐
│  [Учебные] [Коммерческие] [Журналы] [Шаблоны] [Корзина]  │
├──────────────────────────────────────────────────────────┤
│ • Учебные   → удостоверения, дипломы, протоколы, ФРДО    │
│ • Коммерч.  → КП, договоры, счета, акты сверки           │
│ • Журналы   → реестры выдачи (учебных + коммерческих)    │
│ • Шаблоны   → шаблоны учебных + email-шаблоны для рассыл │
│ • Корзина   → soft-delete 30 дней (общая)                │
└──────────────────────────────────────────────────────────┘
```

При этом раздел **«Продажи»** остаётся как отдельная вкладка для **активной CRM-работы** (воронка, лиды, канбан, рассылки, задачи менеджера) — это процесс, а не архив.

**Граница:**
- **Продажи** = процесс (lead → deal → close). Канбан, задачи, звонки, рассылки.
- **Документооборот → Коммерческие** = артефакты этого процесса (готовые КП, подписанные договоры, счета). Версионирование, share-ссылки, корзина, печать.

Это даёт пользователю одно место для «найти любой документ» и одно место для «работать с продажами».

## Что получит пользователь

- **Тумблеры в настройках = реальная картина меню.** Видно, что включено, что нет.
- **«Продажи» можно включить из UI**, не зная про `?enableSales=1`.
- **Один раздел «Документооборот» на все типы документов** — учебные и коммерческие в одном месте, с общей корзиной и журналами. Раздел «Продажи» остаётся для активной работы с воронкой.
