

# Анализ и улучшения конвейера автоматизации

## Текущие проблемы

1. **Последовательная обработка** — курсы обрабатываются один за другим, каждый вопрос ждёт 5с между батчами и 3с между уроками. При 148 курсах и ~700 вопросов это часы работы.

2. **Батч всего 20 вопросов** — ИИ способен обработать 40-50 вопросов за раз (особенно Gemini с большим контекстом), но батч зафиксирован на 20.

3. **Нет возобновления** — при остановке/ошибке конвейер стартует заново. Нет сохранения прогресса между сессиями.

4. **Нет параллелизма на уровне уроков** — контент уроков генерируется строго один за другим, хотя они независимы.

5. **Дубликаты AI-вызовов** — если курс уже частично обработан, конвейер всё равно загружает и проверяет все данные.

6. **Rate limit 10 req/min** — жёсткий лимит в edge function, но клиент ждёт 5с (12 req/min потенциально), что вызывает 429 ошибки.

7. **Нет верификации качества** — ИИ может дать неверный ответ, но нет механизма перепроверки (двойной вызов или проверка другой моделью).

## Предлагаемые улучшения

### 1. Увеличить размер батча вопросов (20 → 40)
Gemini и GigaChat-Pro справляются с 40 вопросами за один вызов. Это сокращает количество API-вызовов вдвое.

**Файл:** `useBulkPipeline.ts` — изменить `batchSize = 20` на `batchSize = 40`.

### 2. Параллельная генерация контента (2-3 урока одновременно)
Вместо последовательного заполнения пустых уроков, отправлять 2-3 запроса параллельно через `Promise.all` с ограничением concurrency.

**Файл:** `useBulkPipeline.ts` — шаг 4 (Fill empty text lessons): обернуть в пул с concurrency=2.

### 3. Сохранение прогресса в localStorage (Resume)
При каждом обработанном курсе записывать его ID в localStorage. При перезапуске — пропускать уже обработанные. Кнопка «Продолжить» вместо «Запустить все» если есть незавершённый прогресс.

**Файлы:** `useBulkPipeline.ts` + `BulkPipelineWidget.tsx`
- Ключ: `pipeline_completed_ids`
- При старте: фильтровать courses по уже обработанным
- Кнопка «Сбросить прогресс» для перезапуска

### 4. Адаптивные задержки вместо фиксированных
Сейчас 5с между батчами и 3с между уроками — одинаково для GigaChat и Lovable AI. Lovable AI быстрее, задержки можно уменьшить. Определять задержку по последнему использованному провайдеру.

**Файл:** `gigachat/index.ts` — возвращать `model` в ответе (уже делает). `useBulkPipeline.ts` — если модель содержит "Gemini", сократить паузу до 2с.

### 5. Режим верификации: двойная проверка ответов
Опциональный режим «Перепроверка»: после решения теста одной моделью, отправить подозрительные вопросы (где ИИ не уверен или explanation пустой) на проверку второй моделью.

**Файлы:** `gigachat/index.ts` — новый action `verify_answers`, `useBulkPipeline.ts` — флаг `enableVerification`.

### 6. Серверный конвейер (Edge Function)
Перенести логику обработки курса целиком на backend. Это исключает проблемы с закрытием вкладки, экономит roundtrip и позволяет использовать service role для обхода RLS.

**Файл:** Новая edge function `bulk-pipeline/index.ts`
- Принимает `course_id`, выполняет все шаги
- Клиент только запускает и polling-ом проверяет статус
- Прогресс сохраняется в таблицу `pipeline_progress`

### 7. Умный пропуск уже решённых
Сейчас suspicious detection проверяет "все ответы одинаковые + нет пояснений". Добавить: если ответ есть И есть explanation длиной >20 символов — считать вопрос надёжно решённым и не пересылать.

**Файл:** `useBulkPipeline.ts` — уточнить фильтр `unanswered`.

## Приоритет реализации

| # | Улучшение | Эффект | Сложность |
|---|-----------|--------|-----------|
| 1 | Увеличить батч до 40 | -50% вызовов | Низкая |
| 2 | Умный пропуск решённых | -20-30% вызовов | Низкая |
| 3 | Адаптивные задержки | -30% времени | Низкая |
| 4 | Resume (localStorage) | Надёжность | Средняя |
| 5 | Параллельный контент | -40% времени | Средняя |
| 6 | Верификация ответов | Качество | Средняя |
| 7 | Серверный конвейер | Надёжность | Высокая |

Рекомендую начать с пунктов 1-3 (быстрые wins) и 4 (resume), затем 5-6.
