
## Контекст

Сейчас в кабинете ученика согласие на обработку ПД подписывается одним кликом по чекбоксу — без признания факта использования ПЭП. В проекте уже есть инфраструктура: шаблон Соглашения об использовании ПЭП (`pepAgreementTemplate.ts`, версия `v1.0`), таблица `pep_agreements`, готовый компонент `PepAgreementDialog`. Юридически (по 63-ФЗ) сначала пользователь должен **принять Соглашение об использовании ПЭП**, и уже после этого его действия в системе (вход + клик «Подписать») признаются ПЭП.

Пароль повторно вводить не нужно — ключом ПЭП по нашему стандарту является сам факт авторизации в учётной записи (логин+пароль уже введены при входе).

## Что сделаем

### 1. Два независимых документа в кабинете ученика

В блоке «Документы → Требуют действия» появляются **две отдельные позиции**:

```text
1. Соглашение об использовании ПЭП          [Подписать]
2. Согласие на обработку персональных данных [Подписать]
```

Кнопка «Подписать» у согласия на ПД **активна только** если уже принято Соглашение об использовании ПЭП (иначе — disabled с подсказкой «Сначала примите Соглашение об использовании ПЭП»).

Это даёт правильный порядок: ПЭП-соглашение → потом любые подписи через ПЭП.

### 2. Соглашение об использовании ПЭП — отдельный пункт

Новый компонент `StudentPepAgreementCard.tsx`:

- Кнопка «Открыть и подписать» → `PepAgreementDialog` с полным текстом из `getPepAgreementText({ org_name, org_inn, user_name, user_email, current_date })`.
- При клике «Я ознакомился(ась) и принимаю» создаётся запись в `pep_agreements`: `agreement_text`, `agreement_version`, `accepted_at`, `ip_address` (получаем через лёгкую edge `get-client-ip` — у нас уже паттерн используется), `user_agent`.
- После принятия — зелёная карточка «ПЭП принято от ДД.ММ.ГГГГ» + кнопка «Скачать соглашение (PDF)».

Если запись уже есть и версия совпадает — пункт сразу отображается как выполненный в блоке «Готово».

### 3. Согласие на обработку ПД — теперь подписывается ПЭП без пароля

Перерабатываем `StudentConsentForm.tsx`:

- Шаг «прочитал → галочка → Подписать ПЭП».
- Перед сохранением проверяется наличие актуального `pep_agreements` (версия `v1.0`). Если нет — кнопка disabled, подсказка ведёт к пункту №1.
- При клике «Подписать ПЭП»: insert в `student_consents` с обогащённой метой:
  - `policy_version` = `СПД-v1.0` (новая константа `CONSENT_VERSION` в файле).
  - `policy_url` = постоянный URL текста (можно публичный путь `/legal/consent-pd` или null на старте).
  - `ip_address` — из той же edge `get-client-ip`.
  - `user_agent` — `navigator.userAgent`.
  - `purposes` — массив стандартных целей (зачисление, обучение, выдача документов и т.п.).
- Сразу показывается зелёная карточка «Подписано ПЭП ДД.ММ.ГГГГ ЧЧ:ММ» + штамп `PepSignatureStamp` с ФИО и временем + ID Соглашения о ПЭП, на основании которого подпись юридически значима.

### 4. Скачивание PDF со штампом ПЭП

Меняем текущий `handleDownload` (сейчас отдаёт .txt) на HTML-документ через `printHtmlContent` из `src/utils/printHtmlToPdf.ts` (используется по всему проекту):

Новый файл `src/lib/consentPdf.ts` с двумя функциями:

- `buildConsentPdfHtml({...})` — текст согласия + блок «ПОДПИСАНО ПРОСТОЙ ЭЛЕКТРОННОЙ ПОДПИСЬЮ» с реквизитами: ФИО, email, дата/время, IP, версия согласия, ссылка на Соглашение о ПЭП (ID и дата принятия).
- `buildPepAgreementPdfHtml({...})` — то же для самого ПЭП-соглашения.

В `StudentConsentForm`: кнопки «Скачать согласие (PDF)» и «Скачать протокол подписания» (используем `buildProtocolHtml` из `src/utils/signatureProtocol.ts` адаптированно — вторая, опциональная).

### 5. Edge-функция `get-client-ip` для записи реального IP

Тонкая публичная функция: возвращает `{ ip }` из заголовков `x-forwarded-for` / `cf-connecting-ip`. Без auth, CORS открыт. Если функция уже есть в проекте — переиспользуем; если нет — создадим. На практике достаточно одного вызова перед вставкой в БД.

### 6. Версионирование текста согласия на ПД

- Константа `CONSENT_VERSION = "СПД-v1.0"` в `StudentConsentForm.tsx`.
- Если у ученика уже есть подписанное согласие, но `policy_version` не совпадает с актуальной версией — статус «требуется переподписание новой редакции», кнопка «Подписать новую редакцию», старая запись остаётся в истории. Старые записи без `policy_version` считаются действительными (не форсируем переподписание задним числом).

## Технические детали

**Новые / изменённые файлы:**

- `src/components/student/StudentPepAgreementCard.tsx` — новый компонент-карточка для пункта №1.
- `src/components/student/StudentConsentForm.tsx` — переработка флоу, удаление пароля, проверка наличия `pep_agreements`, обогащённая запись.
- `src/components/student/StudentDocumentsTab.tsx` — добавление пункта «Соглашение об использовании ПЭП» в `actionItems`/`doneItems` (загружаем последний `pep_agreements` пользователя при mount).
- `src/lib/consentPdf.ts` — новый, билдеры HTML для PDF.
- `supabase/functions/get-client-ip/index.ts` — лёгкая функция (если ещё нет).

**БД и RLS:** изменений не требуется. `student_consents` и `pep_agreements` уже содержат все нужные поля; INSERT-политики для авторизованных пользователей корректны.

**Совместимость:** старые записи `student_consents` без `policy_version` остаются «действительными». Появление пункта №1 (ПЭП) не блокирует уже подписанные согласия задним числом — только новые.

## Что увидит ученик

1. «Документы» → блок «Требуют действия»:
   - **Соглашение об использовании ПЭП** → читает в попапе → «Я ознакомился и принимаю» → пункт уходит в «Готово» с кнопкой «Скачать (PDF)».
   - **Согласие на обработку ПД** → читает текст → ставит галочку → «Подписать ПЭП» → готово, штамп, кнопка «Скачать (PDF)».
2. В разделе «Готово» оба пункта отображаются с датой и кнопкой скачивания PDF, в котором внизу печатается полный блок реквизитов ПЭП.
