

# Документооборот: визуальная полировка + недостающий функционал

После двух предыдущих спринтов критика и перфоманс закрыты. Теперь разбираю **что плохо выглядит, какие кнопки отсутствуют и каких сценариев не хватает** в реальной работе.

## Что нашёл

### A. Визуал и «уплывающие плашки»

1. **KPI-сетка `grid-cols-2 md:grid-cols-4`** ломается на 1280–1500px при открытом сайдбаре на 224px: цифры жмутся в 2 ряда, бейджи `Конверсия 87%` уходят в overflow. Нужно `grid-cols-2 md:grid-cols-2 xl:grid-cols-4` + `min-w-0` на карточках.
2. **Двойная обводка** в `journals` и `frdo`: внешний `bg-card lg:rounded-r-2xl` + внутренний `bg-card rounded-xl border` создают «карточку в карточке» с разными радиусами. На 2K мониторе видно явно. Убрать внутренний контейнер — фон/бордер уже есть снаружи.
3. **Сайдбар вкладок** `lg:w-56 xl:w-64` — на 1366px съедает 28% ширины контента. Сделать `lg:w-52 xl:w-60` + collapse-в-иконки (как в основном `OrgSidebar`) с кнопкой ☰ в шапке секции.
4. **Шапка секции** `flex items-center justify-between px-4 lg:px-6 py-4 border-b`: справа пусто во всех табах кроме `org` (только «Массовая загрузка»). Туда же должны уходить **контекстные кнопки текущей вкладки** (см. раздел B).
5. **Описания вкладок** (`SECTION_DESCRIPTIONS`) обрезаются на узких экранах без `truncate` / `line-clamp-1`. Плюс описания нет для `orders/protocols` (рядом стоят кнопки, но контекста не хватает).
6. **`KpiCard`** — иконка `w-5 h-5` + цифра `text-2xl` + `title text-xs`: при значении `1 234 567` цифра ломает лейаут карточки на 1280px. Нужно `text-xl xl:text-2xl` + `tabular-nums truncate`.
7. **«Корзина» — пустой стейт без визуала**: только текст «Корзина пуста» — нужен большой `Trash2` опак-30, заголовок и подсказка «Удалённые документы появляются здесь и хранятся 30 дней».
8. **`IncomingDocumentsManager`** — список без поиска/фильтра. На 50+ документах превращается в бесконечный скролл. Нужен поиск по названию/ИНН/контрагенту + фильтр по типу.
9. **`SignaturesJournal`** на узких экранах: 8 столбцов таблицы вызывают горизонтальный скролл. Нужно скрывать `signed_ip`/`signed_user_agent` на `<xl`, переносить в expand-row.
10. **Бейджи статусов** `org_documents` (`Действует/Истекает/Просрочен/Архив`) живут в `<div>` без иконки — глазами не сканируется. Добавить мини-иконку (Check/Clock/X) рядом.
11. **Описание шага «Конструктор» и «Документы орг.»** содержат кнопку «Загрузить шаблон/Скачать стенд», но при `activeTab="constructor"` шапка пустая — кнопка лежит внутри секции. Перенести в общую шапку.
12. **Mobile-таб-бар** `lg:hidden flex overflow-x-auto` без скролл-индикатора — пользователь не понимает, что справа ещё 8 вкладок. Добавить градиент-fade справа.

### B. Недостающие кнопки и быстрые действия

13. **KPI-дашборд: KPI-карточки не кликабельны**. Клик по «Ожидает подписи: 12» должен сразу открывать `signatures` вкладку с фильтром `status=sent`. Сейчас просто число. Добавить `onClick` → `setActiveTab('signatures', { status: 'sent' })`.
14. **«Экспорт KPI в PDF/Excel»** — нет кнопки выгрузки сводки за период (для собственника / отчёта учредителю). Добавить кнопку «Экспорт» рядом с «Обновить».
15. **`IncomingDocumentsManager`** — нет кнопок:
    - **«Связать с договором/счётом»** (поля `related_signature_id`, `related_billing_doc_id` в БД уже есть, но в UI не используются).
    - **«Скачать»** (только «Открыть» в новой вкладке).
    - **Bulk-загрузка** (drag-n-drop сразу нескольких сканов с автозаполнением даты по EXIF/PDF метаданным).
    - **Превью PDF/JPG** в Dialog (сейчас `target="_blank"` — выпадает из контекста).
16. **Корзина** — нет кнопки «Очистить старее N дней» для админа орг. Сейчас покупать каждое жмём по одному.
17. **`OrgDocumentsManager`** — у документа нет:
    - **«Заменить файл»** (новый файл с сохранением метаданных, сейчас надо удалить и загрузить заново).
    - **«Назначить ответственного»** (поле есть, но редактируется только при загрузке).
    - **«История версий»** (загружали 3 раза — увидеть кто/когда).
    - **«Поделиться ссылкой»** (короткая токен-ссылка с TTL, чтобы отправить аудитору без логина).
18. **`CounterpartiesSection` → договоры компании** — нет кнопок:
    - **«Создать акт по договору»** (сейчас акт делается отдельно, без привязки к договору).
    - **«Создать счёт по договору»**.
    - **«Запросить ПЭП повторно»** для договоров со статусом `expired/rejected`.
19. **`SignaturesJournal`** — нет:
    - **«Напомнить»** (повторно отправить email подписанту, когда статус `sent`/`viewed` 7+ дней).
    - **«Отменить подписание»** (для статуса `sent` — установить `status=cancelled` + уведомить).
    - **«Скопировать ссылку для подписания»** (`signature_token` → ссылка в буфер, чтобы отправить через мессенджер).
    - **Bulk-actions** (выделить 5 договоров → «Скачать все протоколы ПЭП в ZIP»).
20. **`EducationDocumentsJournal`** — массовый ZIP уже есть в плане, но также нет:
    - **«Отправить документ выпускнику на email»** (PDF удостоверения сразу в письмо).
    - **«Сгенерировать QR-код проверки подлинности»** (URL `/verify/:reg_number` с публичной валидацией).
21. **Глобальный поиск по документообороту** (Cmd+K) — есть `GlobalCommandPalette`, но он не индексирует `incoming_documents`, `org_billing_documents`, `document_signatures`. Добавить эти источники в палитру.

### C. Сценарии, которых пока нет вообще

22. **Шаблоны исходящих писем для документов**. При отправке счёта/акта по email — каждый раз пишем тему и тело руками. Нужен раздел «Шаблоны писем» с `{{recipient_name}}/{{doc_number}}/{{amount}}` — переиспользовать движок из массовой генерации.
23. **«Реестр исходящих документов»** (журнал отправок) — кому, когда, что отправили. Сейчас есть `document_issuance_log` для образовательных, но нет аналога для счетов/актов/договоров. Нужен общий журнал отправок (`document_send_log`).
24. **Напоминания «оплатить счёт»** — для `org_billing_documents` с `is_paid=false` за 7/3/1 день до срока (поле `due_date` нужно добавить в БД).
25. **Двусторонний акт-сверки** — генерация акта-сверки взаиморасчётов с компанией за период (по `company_documents` + `org_billing_documents` где `buyer_inn = company.inn`). Кнопка в карточке компании «Сформировать акт сверки».
26. **«Документ к прочтению» для сотрудников** — например, новая инструкция по охране труда. Загрузил → пометил «обязательно к прочтению» → каждый сотрудник на дашборде видит «Прочитать и подтвердить» → в журнале запись с подписью. Сейчас нет.
27. **Срок хранения и автоудаление по 152-ФЗ** — для согласий ПД и договоров с физлицами по закону хранение 5–75 лет в зависимости от типа. Нужно поле `retention_until` + cron-уведомление за 30 дней до истечения «можно архивировать».
28. **Печать/экспорт «Журнала входящих документов»** в Excel — сейчас только просмотр в UI.

## План работ

### Итерация 1 — Визуальная полировка (без БД)
1.1. KPI-сетка → `grid-cols-2 xl:grid-cols-4`, `KpiCard text-xl xl:text-2xl tabular-nums`, `min-w-0` на карточках.
1.2. Убрать двойную обводку в `journals/frdo` (один контейнер вместо двух).
1.3. Сайдбар → `lg:w-52 xl:w-60` + кнопка-сворачивания в иконки (≡ → `w-14`). Сохранять состояние в localStorage `documents.sidebar.collapsed`.
1.4. Скролл-fade-маска справа в mobile-табах.
1.5. Бейджи статусов в `org_documents` → с иконками (Check/Clock/AlertTriangle/Archive).
1.6. `SignaturesJournal` — скрыть `IP/UserAgent` колонки на `<xl`, перенести в expand.
1.7. Пустые состояния (`Корзина`, `Входящие`, `Подписания`) — крупная иконка + заголовок + подсказка + CTA-кнопка.

### Итерация 2 — Недостающие кнопки и быстрые действия
2.1. **KPI**: клик по карточке → переход на нужную вкладку с предустановленным фильтром (через `tabNavigation` + `searchParams`).
2.2. **KPI**: кнопка «Экспорт сводки» → PDF + Excel за выбранный период.
2.3. **`IncomingDocumentsManager`**:
    - Поиск + фильтр по типу + bulk-загрузка через DnD-зону.
    - Превью PDF/JPG в Dialog (`<iframe>/<img>`).
    - Поля «Связать с договором» (Select из `document_signatures` орг) и «Связать со счётом» (Select из `org_billing_documents`) в форме загрузки.
    - Кнопка «Скачать».
2.4. **`OrgDocumentsManager`**:
    - Кнопка «Заменить файл» (без потери метаданных).
    - Кнопка «Поделиться ссылкой» — генерация короткого токена через новую таблицу `org_document_share_links(id, document_id, token, expires_at, view_count)` + публичный `/d/:token` viewer.
    - Кнопка «История версий» → отдельный диалог с `org_document_versions` (новая таблица, в которую `useOrgDocumentsManager` пушит при заменах).
2.5. **`CounterpartiesSection` → carousel компании**: кнопки «Создать счёт по договору», «Создать акт по договору», «Повторное подписание ПЭП» рядом с каждым договором.
2.6. **`SignaturesJournal`**:
    - «Напомнить» (edge-функция `remind-signature` шлёт email повторно).
    - «Отменить подписание» (статус `cancelled`).
    - «Скопировать ссылку».
    - Bulk-выделение → «Скачать ZIP протоколов».
2.7. **`EducationDocumentsJournal`**:
    - «Отправить выпускнику на email» (использовать SMTP).
    - QR-код подлинности → встраивается в HTML удостоверения.
2.8. **`GlobalCommandPalette`**: добавить источники `incoming_documents`, `org_billing_documents`, `document_signatures`.
2.9. **Корзина**: кнопка «Очистить старее 7/14/30 дней» (для администратора орг).

### Итерация 3 — Новые сценарии (с миграциями БД)
3.1. **Шаблоны писем** — таблица `email_templates(id, organization_id, slug, subject, body_html)` + UI в «Конструктор → Письма». При отправке счёта/акта дёргать шаблон и подставлять переменные.
3.2. **Журнал отправок** — таблица `document_send_log(id, organization_id, doc_kind, doc_id, recipient_email, sent_by, sent_at, delivery_status, opened_at)`. Триггер при отправке через любую edge-функцию.
3.3. **Напоминания «оплатить счёт»** — добавить `due_date` в `org_billing_documents`, cron-функция `process-invoice-payment-reminders` шлёт email-напоминания за 7/3/1 день и 1/7/14 день после срока.
3.4. **Акт-сверки** — кнопка «Сформировать акт сверки за период» в карточке компании. Edge-функция собирает все `company_documents` + `org_billing_documents` по `inn`, строит таблицу «Дебет/Кредит/Сальдо», возвращает HTML/PDF.
3.5. **«Документ к прочтению»** — поле `org_documents.requires_acknowledgement boolean` + таблица `org_document_acknowledgements(document_id, user_id, acknowledged_at, signature_token)`. Виджет «Требует прочтения» в дашборде сотрудника.
3.6. **Срок хранения 152-ФЗ** — `org_documents.retention_until` + cron-уведомление за 30 дней «можно архивировать по истечении срока».
3.7. **Экспорт журнала входящих в Excel** (xlsx через `xlsx` или `exceljs`).

## Что НЕ делаю
- Не трогаю `useDocumentsKpi/useRecycleBin` RPC (стабильны).
- Не переписываю `EducationDocumentsJournal/JournalsManager/FRDOManager` — они защищены памятью.
- Не делаю OCR полнотекстовый поиск — это отдельный спринт.
- Не делаю drag-n-drop сортировку категорий в `OrgDocumentsManager`.

## Технические детали

**Итерация 1** — только фронт:
- `src/components/organization/DocumentsKpiDashboard.tsx`, `tabs/DocumentsTab.tsx`, `RecycleBinManager.tsx`, `IncomingDocumentsManager.tsx`, `OrgDocumentsManager.tsx`, `signing/SignaturesJournal.tsx`.

**Итерация 2** — фронт + edge-функции:
- Новая edge `remind-signature` (берёт `document_signatures.id`, шлёт email повторно с тем же `signature_token`).
- Новая публичная страница `/d/:token` для расшаренных документов.
- Расширение `GlobalCommandPalette.tsx`.
- Миграция: `org_document_share_links`, `org_document_versions`.

**Итерация 3** — большие миграции и новые edge:
- `email_templates`, `document_send_log`, `org_document_acknowledgements`.
- Новые поля: `org_billing_documents.due_date`, `org_documents.retention_until`, `org_documents.requires_acknowledgement`.
- Edge: `process-invoice-payment-reminders` (cron каждый день 09:00), `generate-reconciliation-act`.

## Решение от вас

1. **Все 3 итерации** (рекомендую — закрывает визуал + кнопки + новые сценарии) — большой заход.
2. **Итерации 1 + 2** (визуал + кнопки, без новых таблиц) — средний заход, сразу заметно пользователю.
3. **Только Итерация 1** (быстрая полировка интерфейса) — минимум.
4. **Итерация 1 + точечно из 2/3** — скажите номера пунктов (например, «1.* + 2.3 + 2.6 + 3.3»).
