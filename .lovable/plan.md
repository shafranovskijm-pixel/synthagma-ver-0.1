

# План: починить и доработать вебинары — чат, демонстрация экрана, отзывчивость, наложение UI

## Что сейчас сломано (нашёл в коде)

### 1. Чат — его буквально НЕТ в интерфейсе
- В БД всё готово: таблица `webinar_chat_messages`, RLS-политики (auth + anon), realtime-подписка, RPC `webinar_post_chat` с rate-limit 10 сообщений/60с — миграции `20260422060530`, `20260422062832`.
- В `WebinarSidebar.tsx` только две вкладки: **Q&A** и **Опросы**. Вкладки «Чат» нет.
- В `src/pages/WebinarLive.tsx` (RoomShell) — вкладки «Люди / Q&A / Опросы», **тоже нет чата**.
- Поэтому пользователи и говорят: «чат не работает» — его попросту негде открыть.

### 2. Демонстрация экрана не работает / не нажимается
В `EmbeddedWebinarPlayer.tsx` (строки 460-491) есть `WelcomeOverlay` — заглушка «Добро пожаловать на вебинар Синтагма». У него `absolute inset-0 z-[5]`. Он закрывает **весь видеоконтейнер**, в том числе **нижнюю control-bar LiveKit с кнопками камера / микрофон / поделиться экраном / чат / leave**. Эти кнопки физически под оверлеем и **не кликаются**.
Скрывается оверлей только когда `tracks.length > 0` (камера или screen-share уже включены). Но чтобы их включить — нужно нажать кнопку под оверлеем. Замкнутый круг.

Это же объясняет «**презентация накладывается на кнопки, некоторые кнопки не работают**» — это и есть тот самый Welcome-оверлей.

В токене (`livekit-issue-token/index.ts`, строка 219) для хоста выставлен `canPublish: true` без ограничения `canPublishSources`, значит права на screen-share у LiveKit **есть** — проблема чисто во фронтенде с z-index.

### 3. Тормоза при подключении
- `LiveKitRoom` запускается с `connect={true}` и `video={true}, audio={true}` сразу, без PreJoin-экрана. На медленном соединении одновременный handshake + публикация камеры + микрофона занимает 5-15 секунд, в это время UI замораживается.
- На странице `/webinar/:id/live` (строка 254-263) то же самое.
- В `LiveKitEmbed` рендерятся **два** компонента `<WebinarSidebar>` (десктоп и мобильный) с одинаковыми пропсами → **две одинаковые подписки realtime** на канал `qa-${webinarId}` → дубль событий, лишние ререндеры.

### 4. Дополнительные слабые места
- **Top-bar LiveKit-плеера** (строка 386) с `z-10` и `absolute top-2` тоже перекрывает верхний ряд video-tile'ов LiveKit. На малых высотах окно тайлов уезжает под бар.
- **Чат для гостей**: даже когда добавим вкладку, в гостевом флоу `EmbeddedWebinarPlayer` гости получают `viewOnly`, но в `WebinarSidebar` пропс `isHost={!viewOnly}` — это норм для Q&A, но для чата нужен отдельный флаг «может ли гость писать», который сейчас не передаётся.
- **Realtime пересоединение**: если канал realtime отвалился (короткий разрыв сети), QA/Polls/Chat не переподписываются. Нужно ловить status `CHANNEL_ERROR / TIMED_OUT` и делать `removeChannel + recreate`.
- **CreateRoom max_participants = 100** — для тарифа Профессиональный это ок, но Stop кнопка `handleStopLive` не вызывает `livekit-stop-recording` и не выгоняет участников из room — комната остаётся «висеть» 600 сек по `empty_timeout`.

## Что делаю

### A. Добавляю полноценный чат в UI

**Новый компонент** `src/components/webinars/WebinarChatPanel.tsx`:
- Подписка на `webinar_chat_messages` через Realtime (фильтр `webinar_id=eq.{id}`).
- Initial fetch последних 200 сообщений с пагинацией «Загрузить старые».
- Отправка через RPC `webinar_post_chat(p_webinar_id, p_sender_identity, p_sender_name, p_content, p_is_guest)` — уже существует, обрабатывает rate-limit (10/60с).
- Toast «Слишком часто, попробуйте через минуту» при rate-limit.
- Авто-скролл к низу при новом сообщении (если пользователь у низа).
- Цветные бейджи: «Ведущий» (для is_host), «Гость» (для is_guest), серый ник для авторизованного зрителя.
- Поле ввода с `Enter` = отправить, `Shift+Enter` = перенос строки, лимит 500 символов.
- Для `viewOnly` гостей в `WebinarPublic` — пишут как `is_guest=true, is_host=false`.

**Подключаю в двух местах:**
1. `WebinarSidebar.tsx` — добавить третью вкладку «Чат» (default), порядок: **Чат / Q&A / Опросы**.
2. `WebinarLive.tsx` (RoomShell) — добавить вкладку «Чат» в TabsList, итого 4 вкладки: **Чат / Люди / Q&A / Опросы**, по умолчанию открыта «Чат».

### B. Чиню Welcome-оверлей (главная причина «кнопки не работают»)

В `EmbeddedWebinarPlayer.tsx` (строки 460-492):
- Добавляю `pointer-events-none` корневому div'у `WelcomeOverlay` → визуально остаётся, но **клики проходят сквозь него** к LiveKit control-bar внизу.
- Уменьшаю z-index до `z-[2]` (чтобы overlay не закрывал даже визуально нижнюю панель управления — она у LiveKit имеет более высокий z).
- Оставляю красивый «Добро пожаловать», но он гарантированно не блокирует кнопки.
- Делаю overlay чуть короче по высоте (`bottom-20`), чтобы зрительно тоже не лезть на control-bar.

### C. Чиню top-bar LiveKit-плеера

`LiveKitTopBar` (строка 386):
- Добавляю `pointer-events-auto` на сам бар, но оборачиваю в контейнер `pointer-events-none` чтобы **левая часть видеообласти оставалась кликабельной** для LiveKit-tile-меню.
- Переношу бар чуть вверх (`top-1`), уменьшаю `py-2` → `py-1.5`, чтобы он занимал меньше места.

### D. Ускоряю подключение (отзывчивость)

**На странице `/webinar/:id/live`:**
- Меняю стартовое поведение `LiveKitRoom`: `audio={false}, video={false}` при первом mount → подключение к комнате идёт мгновенно (только сигналинг, без захвата камеры).
- После события `Connected` (через `RoomContext`/`useConnectionState`) автоматически публикую mic+cam. Если хост хочет сначала проверить себя — он увидит control-bar и сам нажмёт «Включить камеру».
- Добавляю короткий PreJoin-экран только для хостов: «Сейчас вы войдёте в эфир. [Включить камеру и микрофон] [Войти без камеры]» (опциональная галочка «не показывать снова», сохраняется в localStorage).

**В `EmbeddedWebinarPlayer` (модалка организации):**
- Аналогично: `video={!viewOnly && joined}, audio={!viewOnly && joined}`, где `joined` поднимается после ручного клика «Войти в эфир» либо автоматически через 800мс.

### E. Чиню дубль realtime-каналов

В `LiveKitEmbed` (строки 302-323):
- Убираю мобильный отдельный `<WebinarSidebar>` — вместо этого делаю один компонент, который через `lg:` модификаторы меняет компоновку (либо drawer на мобильных через Sheet, либо tabs внизу).
- Это убирает вторую подписку на realtime → меньше дублей событий.
- В QAPanel и новом ChatPanel добавляю `useRef` для канала и проверку «уже подписан» — защита от race-condition при ре-mount.

### F. Realtime-самовосстановление

В `WebinarChatPanel`, `WebinarQAPanel`, `WebinarPollsPanel`:
- Подписка через `.subscribe((status) => { if (status === 'CHANNEL_ERROR' || status === 'TIMED_OUT') reconnect() })`.
- `reconnect()` делает `removeChannel(ch)` + повторный `channel().on().subscribe()` через 2 сек.
- При успешном переподключении — повторный fetch последних 50 сообщений на случай пропущенных событий.

### G. Чистка после остановки эфира

В `WebinarsManager.handleStopLive`:
- Если запись активна (`recording_status === 'active'`) — сначала вызвать `livekit-stop-recording`.
- Через `livekit-create-room` уже создан `roomName`. Делаю новую edge-функцию `livekit-end-room` (DeleteRoom через twirp): админский JWT с `roomAdmin: true`, дёрнуть `RoomService/DeleteRoom`. Это мгновенно отключит участников и освободит ресурсы LiveKit (важно для тарифа — экономит минуты).
- В UI тост: «Эфир завершён, участники отключены».

## Как проверим после внедрения
1. Открыть вебинар как хост → видеть control-bar внизу, кликнуть «Поделиться экраном» — окно браузера предложит выбрать экран. Сейчас этого не происходит из-за overlay.
2. Открыть в правой панели вкладку «Чат» → отправить сообщение → второе окно (другой пользователь / гость по `/w/<token>`) видит его в realtime.
3. На медленном Wi-Fi (throttle Slow 4G в DevTools) подключение к комнате занимает <2 сек до «вошёл», камера публикуется отдельно по готовности.
4. Завершить эфир → участники в гостевом окне получают «эфир завершён», а не висят бесконечно.
