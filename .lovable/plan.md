

# План: исправление вебинара в рассылке + продающие шаблоны + аудит слабых мест

## 1. Исправить «Не найдена организация для размещения вебинара»

**Причина:** `CreateWebinarQuick` (для админа платформы в разделе «Рассылка») берёт `organization_id` из `profiles` админа. У платформенного админа этого поля нет → ошибка.

**Решение:**
- В `CreateWebinarQuick.tsx` добавить fallback‑логику:
  - сначала пробуем `profiles.organization_id`,
  - если пусто и пользователь — admin платформы → показываем `Select` со списком организаций (как в `AdminCreateWebinarDialog`), по умолчанию первая.
  - сохраняем выбор в `localStorage('broadcast_webinar_org_id')`, чтобы не выбирать каждый раз.
- Дополнительно создаём запись в `webinars` с типом `external` (через прямую ссылку `/w/:token`) — без вызова LiveKit, как сейчас, но с корректной `organization_id`.

## 2. Исправить «продающую» рассылку: новый шаблон «Презентация платформы»

Создаём в `emailTemplates.ts` новую функцию `getPresentationEmailHtml()` и `getPresentationEmailSubject()` (категория `presentation` уже есть в `TEMPLATE_CATEGORIES`).

**Содержание шаблона** (на основе реальных преимуществ из памяти проекта):

**Структура письма:**
1. **Заголовок:** «Sintagma — образовательная платформа полного цикла для УЦ и предприятий»
2. **Блок «Что даёт платформа» — 4 иконки:**
   - 🎓 200+ готовых программ ДПО, ПО и «Рабочие профессии» (маркетплейс)
   - 🤖 ИИ‑конструктор курсов: 35 уроков за 5 минут (GigaChat + Gemini)
   - 📊 ФИС ФРДО: автоматическая отчётность Excel 35/41 колонка
   - 🎬 Видеохостинг Kinescope с DRM + вебинары LiveKit
3. **Блок «Документооборот»:**
   - Авто‑выпуск удостоверений/дипломов при 100% прогресса
   - Электронная подпись (63‑ФЗ), журналы регистрации
   - Договоры, КП, счета — генерация в Word/PDF
4. **Блок «Безопасность и соответствие»:**
   - Шифрование PII (`pgp_sym_encrypt`)
   - 54‑ФЗ, 63‑ФЗ, 152‑ФЗ
   - Серверная проверка тестов
5. **Блок «Гибкость тарифов»:**
   - Free forever (10 учеников)
   - 5 тарифов до Максимального
   - Кастомные лимиты по запросу
6. **Приглашение на встречу** (если меетинг прикреплён): дата, время, кнопка «Подключиться»
7. **CTA‑кнопка:** «Запланировать звонок» / «Перейти к встрече»
8. **Подпись + сайт sintagma.com.ru**

Дизайн — в фирменной палитре Teal/Cyan (HSL 174 72% 46%), карточный лэйаут, без gold/yellow, белый фон, скругления 16px.

**Подключение:**
- В `getEmailHtml()` и `getEmailSubject()` добавить тип `"presentation"`.
- В `EmailTemplatesManager` шаблон будет автоматически доступен в категории «Приглашение на презентацию» (если будет внесён в `email_templates` как is_default через миграцию — см. п. 4).

## 3. Дополнительные продающие шаблоны (системные, для всех организаций и платформы)

В миграции добавляем 4 системных шаблона (scope='platform', is_default=true):

| Категория | Название | Цель |
|---|---|---|
| `cold` | «Первое касание — Sintagma» | Краткое знакомство, ссылка на демо |
| `presentation` | «Приглашение на презентацию платформы» | Подробный продающий шаблон (п.2) |
| `followup` | «После презентации — материалы и КП» | Прислать материалы, мягкий следующий шаг |
| `proposal` | «Коммерческое предложение» | С ссылкой на тарифы и кнопкой «Обсудить» |
| `reactivation` | «Возвращайтесь — что нового на платформе» | Для холодной базы, со ссылкой на /whats-new |

Все шаблоны — в едином стиле Teal/Cyan, с переменными `{{name}}`, `{{org_name}}`, `{{action_url}}`.

## 4. Миграция БД

Вставка 5 системных шаблонов в `email_templates`:
```text
scope='platform', organization_id=NULL, is_default=true, deleted_at=NULL
category=cold|presentation|followup|proposal|reactivation
```
Используем `ON CONFLICT DO NOTHING` по уникальному ключу (имя+scope), чтобы миграция была идемпотентной.

## 5. Аудит слабых мест системы рассылок (что обнаружено)

```text
┌─────────────────────────────────────────────────────────────────┐
│ ПРОБЛЕМА                          │ ВЛИЯНИЕ          │ ФИКС     │
├─────────────────────────────────────────────────────────────────┤
│ 1. CreateWebinarQuick падает      │ блокер для        │ п.1      │
│    у админа платформы              │ продаж            │          │
│ 2. Нет «золотых» продающих        │ менеджеры пишут   │ п.2-4    │
│    шаблонов в коробке              │ с нуля            │          │
│ 3. Нет UTM-меток в ссылках        │ нет аналитики     │ опц.     │
│    кампаний                        │ воронки           │          │
│ 4. Нет A/B теста темы              │ ниже Open Rate    │ опц.     │
│ 5. Нет автосохранения чернов.     │ потеря при F5     │ опц.     │
│ 6. Нет валидации HTML на          │ возможны          │ опц.     │
│    битые теги                      │ битые письма      │          │
│ 7. Нет планировщика отправки      │ нельзя на         │ опц.     │
│    (send_at)                       │ «утро вторника»   │          │
│ 8. Нет персональных переменных    │ только {{name}}   │ опц.     │
│    {{org_name}}, {{plan}}          │                   │          │
│ 9. Нет «отписаться» в продающих   │ риск спам-жалоб   │ ⚠️ важно │
│    шаблонах (только в трансакц.)   │                   │          │
│10. Нет предпросмотра в Inbox      │ не видим как      │ опц.     │
│    (тестовая отправка есть, но     │ отрисуется в      │          │
│    нет «отправить себе превью»)    │ Gmail/Mail.ru)    │          │
└─────────────────────────────────────────────────────────────────┘
```

**В этой итерации делаем критичное:**
- **п.1** — фикс блокера вебинара
- **п.2–4** — 5 продающих шаблонов
- **п.9** — добавляем стандартный футер «Если вы не хотите получать письма от Sintagma, ответьте СТОП» во все продающие шаблоны (юридическая защита)

Остальное (UTM, A/B, планировщик, автосохранение) — отдельным спринтом, по запросу.
