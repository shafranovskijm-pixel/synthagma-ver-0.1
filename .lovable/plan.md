## Проблема

На `/admin` в разделе «Продажи» показывается личный кабинет менеджера («Привет, Алёнка!», Скрипт звонка, Смена). Причины:
1. Компонент `SalesManager` один и тот же для `/admin` и `/sales`; ранее сделанное автопереключение на вкладку «Менеджеры» для админов срабатывает только если в `localStorage` **нет** `admin_sales_view`. У вас там осталось значение от прошлой сессии «Войти как» → компонент считает вас импersonated и открывает shift-вид.
2. В шапке `/admin` отсутствуют главные админские действия по продажам: назначить план дозвонов, загрузить базу лидов, увидеть текущих менеджеров с логинами/паролями.

## Что сделаю

### 1. Отдельная админская страница продаж

Создаю `src/components/admin/sales/SalesAdminView.tsx` и в `AdminDashboard.tsx` для вкладки `sales` рендерю **её** вместо `SalesManager`. Импersonation при этом полностью игнорируется — админский вид всегда админский.

Структура страницы (сверху вниз, «просто и по делу»):

```text
┌─ KPI-строка: Менеджеров активно · Лидов в базе · Дозвонов сегодня · КП за неделю
├─ Блок «Менеджеры по продажам»
│    Таблица: ФИО · Логин · Пароль (скрыт, кнопка «Показать»/«Сбросить») ·
│             План дозвонов/день · Статус · [История] [Войти как] [Деактивировать]
│    Кнопки сверху: [+ Добавить менеджера] [Пригласить по ссылке]
├─ Блок «База лидов»
│    Счётчик всего/назначено/свободно + [Загрузить CSV] [Добавить вручную]
│    [Раздать свободные лиды менеджерам] (равномерно между активными)
│    [Открыть полный список лидов] → LeadsManager в диалоге
└─ Блок «Быстрые действия»: КП-шаблоны, Договоры, Настройки Novofon
```

Компоненты переиспользую как есть: `SalesManagersList` (там уже логины/пароли/история/войти как), `LeadsManager`, `ManagerStatsDialog`. Новый — только обёртка `SalesAdminView` + инлайн-редактор плана дозвонов и «раздать свободные лиды».

### 2. План дозвонов на день

Добавляю в таблицу `sales_managers` колонку `daily_calls_target integer default 80`. В карточке менеджера — инпут с автосохранением. На стороне менеджерского вида (SalesShiftView) число «Сегодня у тебя N дозвонов» берётся уже из этого поля (сейчас захардкожено 80).

### 3. Возврат из «Войти как»

При заходе на `/admin` (в `AdminDashboard`) автоматически очищаю зависший `admin_sales_view` из localStorage, чтобы админ никогда больше не видел shift-экран внутри своей админки.

### 4. Пароли менеджеров

Показ существующего пароля невозможен (bcrypt в auth.users). В строке менеджера будет кнопка **«Сбросить пароль»** → генерируется новый, показывается один раз в модалке с копированием (как сейчас при создании). Это уже есть на бэке в edge-функции создания менеджера — добавляю ей режим `action: 'reset_password'`.

## Технические детали

- Миграция: `alter table sales_managers add column daily_calls_target int not null default 80;` + GRANT/RLS не трогаем (таблица уже настроена).
- Edge-функция `create-sales-manager` → расширяю до `manage-sales-manager` с `action: create|reset_password`; старый роут сохраняю для совместимости.
- `SalesShiftView` — заменяю константу 80 на значение из `sales_managers.daily_calls_target` текущего пользователя.
- `AdminDashboard.tsx`: в `useEffect` при монтировании — `clearAdminSalesView()`.
- Роут `/sales` остаётся личным кабинетом менеджера (для Алёнки и тестового), туда админ попадает только через «Войти как».
