
## Понял задачу

Глобальный AI-чат поддержки в правом нижнем углу на **всех страницах** (включая главную, кабинеты ученика/организации/админа). Отвечает ИИ (GigaChat → Lovable AI fallback), вся переписка дублируется в Telegram и в админ-панель. Видимость переписки строго ограничена.

## Что нужно уточнить

**1. Передача в Telegram — как?**
- a) В **существующий чат поддержки** `@sintagma_support` (один общий канал, все диалоги вперемешку с разделителями `--- Диалог #ID ---`)
- b) Отдельные **темы (topics)** в супергруппе — каждый диалог = своя тема, можно отвечать прямо из Telegram, ответ улетает обратно ученику
- c) Просто **уведомления админу** в личку, без двусторонней связи

**2. Когда ИИ передаёт диалог человеку?**
- a) **По кнопке** «Связаться с оператором» в чате
- b) **Автоматически**, если ИИ 2 раза подряд не смог ответить / прозвучали ключевые слова («оператор», «человек», «жалоба»)
- c) **Оба варианта**

**3. Что с гостями на главной странице?**
- a) Спрашиваем имя+email/телефон **сразу** перед первым сообщением
- b) Даём писать **анонимно**, просим контакты только когда хочет связаться с оператором или ИИ не справился
- c) Анонимно полностью, контакты не запрашиваем

**4. История чата для возвращающихся пользователей**
- a) Авторизованные видят **всю свою историю** диалогов с поддержкой
- b) Только **текущая сессия**, после перезагрузки — новый чат
- c) История есть, но можно **«начать новый диалог»** кнопкой

## Предварительный план (доработаю после ответов)

### 1. БД
- `support_conversations` — диалог (user_id или guest_contact, organization_id, status: `ai`/`human`/`closed`, источник: `landing`/`student`/`organization`)
- `support_messages` — сообщения (conversation_id, role: `user`/`ai`/`operator`, content, telegram_message_id)
- RLS: видит только автор + глобальные админы (по `has_role('admin')`)

### 2. Виджет чата (правый нижний угол)
- Компонент `SupportChatWidget` в `App.tsx` — рендерится **на всех роутах**
- Скрыт на `/admin` (там админ работает с диалогами иначе) и в режиме impersonation
- Кнопка-пузырёк в Teal/Cyan стиле, при клике — окно 380×560
- Состояния: гость / ученик / организация — UI и контекст промпта подстраиваются

### 3. Edge-функция `support-chat`
- Принимает сообщение, сохраняет в `support_messages`
- Подтягивает контекст: профиль, организация, история диалога
- Вызывает GigaChat (системный промпт «техподдержка Sintagma», знает про тарифы, FRDO, конструктор курсов, оплату); fallback → Lovable AI (`google/gemini-2.5-flash`)
- Стримит ответ обратно
- Дублирует и вопрос, и ответ в Telegram через коннектор

### 4. Системный промпт ИИ
Профессиональная техподдержка платформы Sintagma. Знает:
- Тарифы (Бесплатный → Максимальный, лимиты учеников/курсов)
- Возможности (конструктор, ИИ-генерация, ФИС ФРДО, вебинары Kinescope, ИИ-аватар)
- Юридические аспекты (54-ФЗ, 63-ФЗ, оферта)
- Команды для эскалации (если не знает — предлагает оператора)
- Тон: вежливый, конкретный, без воды, на «вы»

### 5. Telegram-интеграция
Зависит от ответа на вопрос #1.

### 6. Админ-панель: «Чаты поддержки»
- Новый раздел в `/admin` рядом с «Рассылка»
- Список диалогов (фильтры: активные / с человеком / закрытые / по организации / по ученику)
- Просмотр переписки ИИ↔пользователь
- Кнопка «Перехватить диалог» — админ начинает писать сам, ИИ замолкает
- Realtime через Supabase Realtime на `support_messages`
- Бейдж непрочитанных в сайдбаре админа

### 7. Видимость (RLS)
- Пользователь видит **только свои** диалоги
- Глобальный админ видит **все**
- Менеджер организации **не видит** диалоги своих учеников (только админ платформы)
- Гостевые диалоги привязываются к `guest_token` в localStorage

### 8. Замена существующей кнопки
В архиве `_archived/OrgSupportChat.tsx` и текущая виджет-иконка Telegram (видна на скриншоте справа внизу) — заменим на новый виджет.
