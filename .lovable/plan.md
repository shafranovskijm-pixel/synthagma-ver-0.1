
## Задача
В диалоге «Медиатека» добавить:
1. Кнопку удаления файла прямо из списка (особенно для тех, что помечены «Не используется»).
2. Культурную подсказку-баннер с просьбой удалять ненужные видео ради экономии места на сервере.

## Что меняем

**Файл:** `src/components/course-builder/MediaLibraryDialog.tsx`

### 1. Иконка-кнопка «Удалить» в строке файла
- Появляется при ховере справа от названия (рядом с бейджами «Используется/Не используется»).
- Стиль: `ghost` + `text-destructive`, иконка `Trash2`.
- Клик → `e.stopPropagation()` (чтобы не открывался превью) → `AlertDialog` с подтверждением.
- При подтверждении: `supabase.storage.from(file.bucket).remove([file.path])`, локально убрать из списка, `toast.success("Файл удалён")`.
- **Защита:** если `file.usage === "Используется"` — показываем дополнительное предупреждение в подтверждении («Файл используется в уроке. Удаление сломает отображение. Продолжить?»). Не блокируем, но красно подсвечиваем.

### 2. Информационный баннер сверху (под поиском)
Светло-Teal фон (`bg-primary/5 border border-primary/20 rounded-xl`), иконка `Sparkles` или `Leaf`, короткий текст:
> «Совет: удаляйте видео и файлы, которые больше не используются — это освобождает место на сервере и ускоряет работу платформы. Спасибо, что заботитесь о порядке 💚»

Показываем баннер всегда, когда в списке есть хотя бы один файл с `usage === "Не используется"`. Иначе скрываем (чтобы не мозолил глаза).

### 3. Счётчик неиспользуемых
Рядом с заголовком «Медиатека (N файлов)» добавить тонкий бейдж: «N не используется» (если > 0) — кликабельный, фильтрует список только по неиспользуемым.

## Технические детали
- Удаление работает только для файлов из бакетов `course-files` / `presentations` (внутренний Storage). Для `course-videos` (внешний бакет) — используем `extClient` через `get-external-storage-config` (как уже сделано в `useStorageManager.handleDelete`).
- После удаления — `setFiles(prev => prev.filter(...))` без полного перезапроса.
- Никаких миграций и edge-функций.
- RLS: пользователь организации уже имеет DELETE-доступ к своим объектам в `course-files` (используется в `useStorageManager`), поэтому права хватит.

## Риски
- Минимальные. Если файл реально используется в уроке — после удаления видео-блок покажет «битую» ссылку. Подтверждение с предупреждением снижает риск.
