

# Анализ проблем с перенаправлениями и долгой загрузкой

## Найденные проблемы

### 1. PWA Service Worker кеширует старую версию (ГЛАВНАЯ ПРИЧИНА)

В `vite.config.ts` настроен PWA с workbox, который агрессивно кеширует файлы приложения. Даже после публикации новой версии, браузер пользователя может продолжать показывать старый закешированный код (с логикой "Перенаправление..."), пока Service Worker не обновится.

Хотя `skipWaiting: true` и `clientsClaim: true` установлены, обновление SW происходит только при следующем визите на сайт, и старый кеш может "держаться" долго.

**Решение:** Добавить версионирование кеша и механизм принудительного обновления при критических изменениях.

---

### 2. Нет `navigateFallback` в конфигурации Workbox

В конфигурации Service Worker отсутствует параметр `navigateFallback: '/index.html'`. Это означает, что при прямом переходе на маршрут вроде `/student` на кастомном домене, Service Worker не знает, что нужно отдать `index.html`. Это может приводить к 404 ошибкам.

**Решение:** Добавить `navigateFallback: '/index.html'` в настройки workbox.

---

### 3. Последовательная загрузка авторизации (1-3 секунды задержки)

В `useAuth.tsx` процесс инициализации выполняется последовательно:
1. `getSession()` -- запрос к серверу (~500ms-1s)
2. `fetchUserRole()` -- ещё один запрос к БД (~500ms-1s)
3. Только после этого `setLoading(false)`

Всё это время пользователь видит экран загрузки "Загрузка...".

**Решение:** Кешировать роль пользователя в `localStorage` и использовать её как начальное значение, обновляя в фоне.

---

### 4. Жёсткий редирект в RegisterOrganization.tsx

В файле `src/pages/RegisterOrganization.tsx` (строка 285) используется:
```
window.location.href = "/organization";
```
Это полная перезагрузка страницы вместо клиентской навигации, что вызывает повторную инициализацию всего приложения.

**Решение:** Заменить на `navigate("/organization", { replace: true })` после обновления состояния auth.

---

## План исправлений

### Шаг 1. Добавить `navigateFallback` в workbox конфигурацию
В `vite.config.ts` в секцию `workbox` добавить:
```
navigateFallback: '/index.html'
```

### Шаг 2. Кешировать роль пользователя в localStorage
В `useAuth.tsx`:
- При получении роли сохранять её в `localStorage`
- При инициализации читать кешированную роль как начальное значение
- Это позволит показывать интерфейс мгновенно, а не ждать ответа сервера

### Шаг 3. Заменить `window.location.href` на React навигацию
В `RegisterOrganization.tsx` заменить жёсткий редирект на `navigate()`.

### Шаг 4. Добавить механизм очистки устаревшего SW-кеша
Добавить в `main.tsx` обработку обновления Service Worker с автоматической перезагрузкой при обнаружении новой версии.

---

## Ожидаемый результат
- Страницы на кастомном домене перестанут показывать 404 при прямом переходе
- Время начальной загрузки сократится с 1-3 секунд до мгновенного (за счёт кеширования роли)
- Старые версии кода не будут "застревать" в кеше Service Worker
