
## Задача
В диалоге «Медиатека» (выбор ранее загруженных файлов) пусто, хотя при импорте курсов было перенесено много видео и файлов в бакет `course-files`. Нужно понять, почему файлы не подтягиваются.

## Исследование

Нужно проверить:
1. `MediaLibraryDialog.tsx` — как формируется запрос: листинг бакета или таблица-индекс? Какой фильтр `organizationId` применяется?
2. Реальный путь, по которому сохраняются файлы при импорте курса (`supabase/functions/_shared/skillspace-media.ts` уже видно — там путь `${organizationId}/${uuid}.${ext}` в бакете `course-files`).
3. Совпадает ли префикс листинга в `MediaLibraryDialog` с тем, как импорт сохраняет файлы.
4. Бакет для видео — в `FileUploadDialog` видно различие: видео идут в `course-videos` (если внешнее хранилище), иначе `course-files`. А импорт пишет в `course-files`. А медиатека листает какой?
5. Проверить RLS-политики на `storage.objects` для `course-files` — может ли пользователь организации читать свои объекты.

## Гипотезы (в порядке вероятности)

1. **Несовпадение пути**: медиатека листает, например, `${organizationId}/uploads/` или корень с другим префиксом, а импорт сохраняет в `${organizationId}/<uuid>` напрямую → листинг видит «пусто».
2. **Другой бакет**: медиатека смотрит в `course-videos` или `media-library`, а импорт пишет в `course-files`.
3. **Импорт пропустил видео**: в `skillspace-media.ts` есть явный `Skipping video file (memory constraint)` — видео не переносились вовсе, остались как внешние ссылки на skillspace.ru. Тогда в Storage их физически нет, и медиатека правильно показывает «пусто».
4. **RLS на storage.objects** не даёт SELECT для роли организации.

## План действий

1. Прочитать `src/components/.../MediaLibraryDialog.tsx` — какой бакет, какой префикс, как фильтрует.
2. Прочитать `useMediaLibrary` (или соответствующий хук) — источник данных (Storage API `.list()` vs таблица).
3. Через `supabase--read_query` посмотреть, что реально лежит в `storage.objects` для бакета `course-files` с префиксом текущей организации (есть ли там вообще файлы, и по каким путям).
4. Сверить с кодом импорта.
5. Если причина — несовпадение префикса: исправить запрос медиатеки на корректный префикс `${organizationId}/` и листать рекурсивно.
6. Если причина — отдельный бакет для видео: либо листать оба бакета, либо показывать таблицу-индекс `lesson_media` (если есть).
7. Если причина — импорт пропускает видео: объяснить пользователю и предложить либо снять ограничение «skip video», либо добавить отдельную таблицу-индекс с записями обо всех импортированных URL (включая внешние ссылки), чтобы медиатека показывала их.
