
Цель: убрать «откат» на старый интерфейс в режиме разработки (Preview) и сделать загрузку всегда актуальной без ручных действий.

### Короткий диагноз по текущему коду
- На скрине у тебя на `/` открывается старый экран логина, хотя в текущем коде `/` уже должен рендерить лендинг (`Index`) — это признак старого клиентского бандла.
- В `index.html` preview-очистка сейчас завязана на `sessionStorage`-ключ `__purge_preview-session`: после одного срабатывания в сессии дальнейшие обновления могут не форситься.
- Там же `assetId` читается из `script[type="module"]` до гарантированного появления entry-script, из-за чего детект смены ассетов может работать нестабильно.

### План исправления

1) Пересобрать bootstrap в `index.html` (главный фикс)
- Заменить текущую preview-логику на **одноразовый reload через URL-маркер**, а не через «вечный» session guard.
- Алгоритм:
  - если preview/localhost и нет `__preview_refresh=1` → очистка SW/cache + `location.replace` с `__preview_refresh=1`;
  - после перезагрузки убрать маркер из URL через `history.replaceState`, чтобы следующий заход снова мог обновиться.
- Это уберёт залипание на старой версии в длинной сессии редактора.

2) Сделать гарантированный cache-bust entry-скрипта в Preview
- В `index.html` загружать `/src/main.tsx` в preview с query-параметром (например, `?v=${Date.now()}`), чтобы браузер не брал старый модуль из кеша.
- Для production оставить обычную схему.
- Это критично именно для режима разработки, где путь entry статичный.

3) Стабилизировать проверку версии в `src/main.tsx`
- Оставить текущую проверку `__BUILD_TIMESTAMP__`, но синхронизировать guard-ключи с новой bootstrap-схемой (чтобы не было конкурирующих перезагрузок).
- Добавить «мягкий» fallback: если был reload по bootstrap, не запускать повторный reload по build-check в ту же итерацию.

4) Унифицировать ручное восстановление
- В `src/utils/forceClientRefresh.ts` привести ключи/очистку к той же модели, что в bootstrap (`app-version`, `remote-cache-ver`, `__asset_id`, guard keys), чтобы кнопка «Обновить интерфейс» всегда давала тот же результат, что и авто-обновление.

5) Диагностика версии (чтобы сразу видно, что загружено)
- Оставить/усилить отображение build-id в preview и сделать его максимально однозначным (timestamp/версия), чтобы можно было сразу понять «новый клиент или старый».

### Файлы
- `index.html` — полная переработка preview bootstrap + cache-busted entry loading.
- `src/main.tsx` — согласование guard/reload последовательности.
- `src/utils/forceClientRefresh.ts` — унификация ручного обновления.

### Проверка после внедрения
1. Открыть Preview с нуля: должен подхватиться актуальный интерфейс (без «старого» `/`).
2. Закрыть/снова открыть Preview: версия должна оставаться актуальной.
3. Нажать «Обновить интерфейс»: один контролируемый reload, без циклов.
4. Сверить build-id в preview до/после изменений.
5. Проверить published URL: без лишних reload-петель и без регресса UX.
