

## Проблема
Пользователь видит в левом сайдбаре только 11 уроков (видно «Уроки (13)», но в списке видно 11, и на скриншоте обрезано). Подозрение — лимит выборки уроков (Supabase возвращает до 1000 строк по умолчанию, но возможен явный `.limit()` или пагинация с маленьким значением).

Нужно:
1. Найти, где загружаются уроки в `CourseBuilder.tsx` (или хук типа `useCourseBuilder`).
2. Проверить, есть ли `.limit()`, `.range()` или пагинация.
3. Проверить в БД фактическое количество уроков для курсов учётки **ИП Дмитриева Валентина Генриховна** — сравнить с тем, что показывает UI.
4. Если в БД уроков больше, чем в UI — убрать лимит / увеличить range / поправить запрос.

## Шаги диагностики (после approve)

1. **Чтение кода загрузки уроков:**
   - `src/pages/CourseBuilder.tsx` — найти `supabase.from('lessons').select(...)`.
   - Связанные хуки (`useCourseBuilder`, `useLessons`, и т.п.).
   - Проверить наличие `.limit()`, `.range()`, `.order()` без полной выборки.

2. **SQL-проверка через `supabase--read_query`:**
   - Найти организацию по названию ИП Дмитриева В.Г.
   - Для каждого её курса посчитать `COUNT(*) FROM lessons WHERE course_id = ...`.
   - Сравнить с тем, что отрисовано (на скрине «Уроки (13)»).

3. **Если найден лимит** — исправить:
   - Убрать `.limit()` / увеличить до 1000+ / использовать `.range(0, 9999)`.
   - Или добавить пагинацию с подгрузкой всех страниц в цикле.

4. **Если данных нет в БД** (а должны были скопироваться при дублировании) — проверить логику дублирования курса (`mem://features/organization/course-duplication-system` упоминает deep cloning включая тесты) и восстановить недостающие уроки.
