# Защита доступа к контуру автошколы при отзыве аккаунта

Дата подготовки: 27.10.2026, Asia/Vladivostok.

Статус перед слиянием PR №167: **DB_APPLIED / NATIVE_12_PASS / FRONTEND_CI_87_PASS / FRONTEND_NOT_RELEASED / AS_LIVE_PILOT_NOT_ACCEPTED**.
Серверная редакция B3 установлена отдельным проверенным установщиком R2; этот companion подготовлен для соответствия репозитория рабочей базе. Frontend PR №167 ещё не слит, полный рабочий пилот автошколы не принят. Новые guard-блоки companion-файла прошли отдельные 10 нативных проверок; исходные 12 серверных сценариев учитываются отдельно.

## Что меняется

[Миграция](../supabase/migrations/20261027010000_sintagma_driving_revocation_read_committed_three_helpers.sql) содержит ровно три проверенных определения существующих функций: `driving_can_manage(uuid)`, `driving_membership(uuid)` и `driving_assert_account(uuid, uuid, text)`.

Функции проверяют исходную авторизацию, отзыв доступа и актуальную привязку к организации. Для решения о доступе требуется изоляция `READ COMMITTED`; другой режим возвращает `25000`. Проверка использует существующий механизм блокировки субъекта удаления аккаунта. Если блокировка занята, функция возвращает `40001`, чтобы вызывающая сторона повторила проверку после завершения конкурирующей операции. Для отозванного аккаунта проверка управления возвращает отказ, проверка членства не выдаёт членство, а обязательная проверка аккаунта возвращает `42501`.

Сохраняются проверки действующего профиля, организации, подтверждённого email и активной роли ученика или инструктора. Миграция не меняет профили, состав школ, учебные результаты, курсы, финансовые данные или обычный кабинет слушателя. Она не добавляет роли, `GRANT`, публичные RPC, таблицы или политики RLS. Три функции сохраняют `SECURITY DEFINER` и фиксированный `search_path` из проверенной редакции.

`CREATE OR REPLACE` сохраняет владельца и ACL уже существующей функции. Поэтому перед тремя определениями добавлена отдельная ограниченная SQL-проверка: все три точные сигнатуры должны существовать, быть функциями владельца `postgres`, сохранять `SECURITY DEFINER` с точным `search_path=public` и не разрешать `EXECUTE` для `PUBLIC`, `anon` и `authenticated`. Та же проверка повторяется после замены. Отсутствующий объект или изменение доступа останавливают миграцию с `55000`, а не создают новую функцию с правами по умолчанию. Эти два guard-блока — новое усиление companion-файла; тела трёх функций остаются побайтно прежними. Guard не добавляет прав и не заменяет полную проверку приватного установщика R2.

## Подтверждённые проверки

- На изолированном PostgreSQL 17.11 выполнены 12 конечных сценариев с настоящими соединениями, ролями и конкурирующими транзакциями. Проверены отзыв доступа, конфликт двух разных субъектов и сохранение 29 таблиц вне тестовых отзывов. Это ограниченная локальная проверка выбранных путей, а не приёмка полного жизненного цикла удаления аккаунта или регистрации организации.
- Frontend CI завершился с 87 успешными тестами, включая точные 23 теста контура автошколы, и проверкой TypeScript. Проверены 13 выбранных файлов исходников и 47 исходных pins. Это не доказывает публикацию frontend и работу двух школ на рабочем сайте.
- Исходные три SQL-определения побайтно совпадают с проверенной редакцией B и с соответствующими операторами приватного установщика R2. SHA-256 исходного файла редакции B: `8dd6152a96cac95ccb37d26b6ac132352266c44f2648c761bf0efd73bbd83221`.

Банки вопросов, персональные идентификаторы, приглашения, пароли, снимки клиентских строк и приватные установочные проверки в репозиторий не включаются. Эта техническая проверка доступа не означает правовую или методическую аттестацию контура автошколы.

## Установка и журнал миграций

Версия companion-файла — `20261027010000`. Он содержит три `CREATE OR REPLACE FUNCTION` между двумя ограниченными guard-блоками, без внешних `BEGIN`/`COMMIT` и без записи в журнал миграций. Migration runner должен выполнить весь файл атомарно и учесть версию своим штатным механизмом.

В рабочей базе выполнена проверка V3 с автоматическим откатом; независимое чтение подтвердило восстановление исходного журнала из 641 записи. Затем исходный приватный установщик R2 применён один раз: журнал содержит 642 записи, максимальная версия — `20261027010000`. Отдельное чтение после commit прошло все 7 проверок установленного состояния. SHA-256 приватного протокола фактической установки и отдельного readback: `fc38cf1445515105ee3acdfe9edd9e6a7b0a8166e1bc6376366afbec0b6455dd`. Сам протокол, клиентские снимки и установщик в репозиторий не включаются.

R2 уже успешно установил функции и записал эту версию до слияния PR; последующее развёртывание должно увидеть существующую запись и пропустить миграцию. Имя файла совпадает с записанным именем версии `sintagma_driving_revocation_read_committed_three_helpers`. Нельзя повторно запускать SQL вручную, переименовывать файл для replay, удалять запись журнала или добавлять upsert для сокрытия расхождения. Companion нужен для соответствия репозитория установленным исходникам, а не для второй установки.

На другом окружении сначала сверяют существующие три функции, их владельца и ACL, актуальную схему и журнал. Только затем штатный runner применяет версию один раз. Приватный harness, тестовые субъекты, роли локальной лаборатории и её seed-данные в такую установку не переносятся.

Перед публикацией companion-файла выполнены 10 отдельных нативных проверок: положительный сценарий; отсутствие каждой из трёх функций; открытый EXECUTE для authenticated, anon и PUBLIC; изменение владельца, SECURITY DEFINER и search_path. Все отрицательные сценарии дали 55000, после каждого отката повторно прошли 18 проверок каталога и сохранились строки 29 таблиц. SHA-256 протокола: a0be9f053aaaf64878dbfcccae270477a70f36196f98a0f290e38bc0700f72d9. Это отдельные проверки нового guard, исходные 12 серверных сценариев их не заменяют. После установки нужны отдельное чтение определений, прав и журнала, выпуск frontend и проверка рабочего интерфейса с реальными ролями. Проверка двух синтетических QA-организаций должна сохранять существующие профили, результаты и чужие данные. Полный Cloud-пилот остаётся отдельным условием приёмки.
