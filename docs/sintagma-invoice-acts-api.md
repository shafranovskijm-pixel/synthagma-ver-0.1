# Акты СИНТАГМЫ через ChatGPT

Акты создаются в самой СИНТАГМЕ к существующим `subscription_invoices` за доступ к платформе. Они сохраняются в `org_billing_documents` и закрытом хранилище `billing-documents`. Счёт не переносится в 24ZXC и не изменяется.

## Команды и источник

1. `search_sintagma_billing_organizations` находит организацию по имени или ИНН.
2. `search_sintagma_invoices` с `source_kind=subscription_invoice` читает её счета. Неоднозначный выбор уточняется у пользователя.
3. `preview_sintagma_invoice_act` принимает точные ID организации/счёта и дату акта. Возвращает реквизиты, сумму, номер, hash исходных данных и `request_id`. Ничего не сохраняет.
4. `create_sintagma_invoice_act` сохраняет акт по конкретной команде пользователя и параметрам предпросмотра. Изменённый исходный счёт требует нового предпросмотра.

Сумма берётся полностью из счёта, в копейках. Другой плательщик берётся из `buyer_*` самого счёта; неизвестный подписант не подставляется от организации. Номер акта — `А-` и исходный номер счёта. Связь определяется точными ID, а не только номером.

Используется существующий шаблон `generateAct` с теми же печатью и факсимиле. Общий чистый renderer используется браузером и MCP. В текстовом предпросмотре изображения опущены и это явно отмечено; сохранённый HTML содержит оригинальные изображения. Это не электронное подписание или подтверждение принятия акта клиентом.

## Сохранение и доступ

- Каждая новая операция требует действующего пользовательского JWT, роли администратора платформы и отсутствия блокировки. Service role не применяется.
- `platform_invoice_acts` хранит неизменяемые исходные данные и HTML. Один API-акт связан с одним счётом, повторный request возвращает прежний результат.
- Сначала создаётся pending-снимок, затем HTML записывается без перезаписи и проверяется SHA-256. Видимая запись в документах появляется только после проверки файла.
- Ошибка хранилища оставляет восстанавливаемое pending-состояние. Нужно повторить тот же request, а не генерировать новый документ.
- Прежние акты распознаются по существующему маркеру счёта. Общая проверка новых помеченных записей координирует сохранение через сайт и MCP. Исторические записи не очищаются.
- Акт из корзины не перевыпускается автоматически. Его следует восстановить в СИНТАГМЕ.
- Ссылка на закрытый HTML действует 120 секунд. Статус сохранения, наличие файла и отправка клиенту различаются.

В этом выпуске нет отправки клиентам, изменения суммы исходного счёта, частичных актов и переноса в 24ZXC.
