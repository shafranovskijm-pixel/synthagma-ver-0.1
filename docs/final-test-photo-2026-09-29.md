# Фото перед итоговым тестом — S-029

Локальная реализация от 29.09.2026, ветка `codex/final-test-photo`, исходный `origin/main` — `06206ca80d3cce604a45caa98ade745948b27178`. Production, реальные фотографии слушателей и учебные результаты не изменялись.

## Поведение

- В основных настройках курса добавлен независимый переключатель «Фото перед итоговым тестом». Поле `courses.require_final_test_photo` по умолчанию `false`; существующая идентификация при входе в курс не заменяет новую проверку.
- Перед каждой новой попыткой последнего теста курса открывается существующий интерфейс камеры. Записывается JPEG, без видео и звука. Попытка расходуется только после сохранённого сервером подтверждения и начала теста.
- Новый сценарий не меняет аватар профиля и общую историю `video_identifications`. Фотография хранится в закрытом bucket `final-test-photos` и связана с конкретной попыткой.
- В существующей карточке результата теста организация видит фотографию и дату. Для отображения используется короткая подписанная ссылка; ошибка чтения не выдаётся за отсутствие фотографии.
- Повторный сетевой запрос и продолжение начатой попытки сохраняют прежнюю попытку. Для новой попытки нужна новая фотография. Возврат к незавершённому окну проверки может потребовать новый снимок; старый незавершённый challenge становится недействительным. После отмены или перехода к другому уроку поздний ответ не запускает тест.
- Уже начатые до включения настройки сессии продолжаются по сохранённым условиям. Ручной/очный зачёт сохраняет прежнее поведение.

## Серверный контракт

Миграция: `supabase/migrations/20260929120000_final_test_photo.sql`.

- `prepare_final_test_photo(p_lesson_id, p_request_id)` выдаёт серверный challenge и приватный путь загрузки. Подтверждение действует 20 минут до старта; истечение этого срока после начала не прерывает тест.
- `complete_final_test_photo(p_challenge_id)` проверяет пользователя, зачисление, объект Storage, путь, владельца, MIME, размер и время загрузки. Клиентское значение `verified` не является допуском.
- `start_test_attempt` атомарно связывает подтверждение с попыткой до расходования квоты. `submit_test_attempt` проверяет сохранённую связь; старый Edge `grade-test` также проходит через этот RPC. Прямые записи учащегося в таблицу результатов запрещены существующей миграцией.
- `get_student_test_state` сообщает `photoRequired`: клиент не определяет итоговый тест отдельно.
- `get_test_attempt_photo(p_attempt_id)` принимает ID сессии или результата, проверяет владельца либо право `students.read` соответствующей организации и возвращает приватный путь.

Итоговым считается последний урок типа `test`: известные модули по `order_index`, внутри них уроки по `order_index`, затем уроки без известного модуля. При равных индексах сервер использует UUID как устойчивое дополнительное правило. Общее направление совпадает с `courseLessonOrder`; прежний интерфейс курса при равных индексах сохраняет входной порядок, поэтому допуск определяется только серверным `photoRequired`.

Это сохранение снимка с камеры. Распознавание лица, liveness и решение сотрудника о подтверждении личности не добавлялись.
