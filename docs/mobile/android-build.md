# Android СИНТАГМА

Исходная база: `d0f1b5c98b62102620a26d58a0e5c064fce42056`, 7 октября 2026.
Используется существующий Capacitor 8. В APK включён собранный интерфейс;
`server.url` не задан. Учебные данные загружаются из действующего backend.

## Реализовано в ветке

- Android Back возвращает по истории экрана, на корневом экране сворачивает приложение.
- Запуск ведёт на вход. Существующие роли/курсы/тесты используют тот же backend.
- Native localhost использует российский Nginx API proxy, обычный localhost — прежний транспорт.
- Камера/микрофон запрашиваются Android только при запуске соответствующего действия
  в существующем интерфейсе. Нет разрешений на полный доступ к файловой системе.
- Документы сохраняются через системный диалог выбора файла; лимит одного экспорта 20 МБ.
- Название, адаптивная иконка и заставка СИНТАГМА; HTTPS без mixed content; резервное
  копирование данных WebView отключено, чтобы не переносить сессии через backup.

## Сборка Windows на D:

Нужны Node.js 22+, JDK 21, Android SDK platform 36 и build-tools 36.0.0.
Настройте `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_USER_HOME`, `GRADLE_USER_HOME`,
`TEMP`, `TMP`, а также JVM `-Duser.home` и `-Djava.io.tmpdir` на каталоги D:.

Запустить `npm run android:debug` под Node 22. Сценарий собирает Vite, выполняет
`cap sync android`, затем Gradle. Результат и SHA-256: `artifacts/android/`.

Тестовый пакет: `ru.sintagma.app.debug`, версия `1.0-test`. Он не заменяет
будущий опубликованный пакет `ru.sintagma.app`.

`npm run android:release:unsigned` создаёт **неподписанный** release APK.
Перед загрузкой в магазин он должен быть подписан постоянным ключом издателя.
Ключ, пароли и персональные данные не должны попадать в Git или APK assets.

## Контроль выпуска

Сборка APK и проверки кода не подтверждают готовность к публикации. Нужны фактические
проверки на Android: запуск, вход/выход, курс, итоговый тест, сохранение документа,
камера с отказом и согласием, потеря сети, Back и восстановление после сворачивания.
Не использовать действующих учеников для тестовых попыток.

Отдельно проверить карточку RuStore, политику данных, путь удаления аккаунта,
реквизиты издателя, постоянную подпись и доступ модератора. Статус модерации
определяется кабинетом RuStore; локальная сборка не означает публикацию.
