# Редакции собственных программ и точные файлы

Работа относится только к текущим собственным курсам организации `4ac2c05a-d8b5-4e72-ba31-f2c743091d95`. Клиентские копии, старые попытки, оценки, финансовая история, тарифы и договорная постоплата СГТ сохраняются. Телефония отложена.

## Отдельные состояния

Текущий курс, неизменяемое досье, решение по досье, публикация шаблона и утверждение учебным центром различаются. Фиксация байтов не является методической или правовой приёмкой. Сохранённое досье выбирается явно; его предпросмотр не заменяется текущим файлом или банком вопросов. Изменение исходника не переписывает прежнее досье, решение или результат обучения.

Файлы фиксируются только штатным входом уполномоченного модератора: сервер создаёт intent по точной ссылке, новый `platform-course-file` получает исходник через обычный authenticated Storage read и сохраняет фактические байты с SHA-256. Чтение работает по receipt; браузер проверяет область, размер и полный хеш. Публичные и подписанные ссылки не служат запасным источником. Технический предел одной операции8MiB не является тарифным ограничением учеников или СГТ.

## Выпуск

Пять миграций: `20261028000000`, `20261028000001`, `20261028080000`, `20261028140000`, `20261029010000`. Установщик проверяет конкретные исходники и отсутствие каждой записи, затем применяет и регистрирует только эту партию атомарно. Нельзя запускать общий db-push/reconcile или повторять уже применённые миграции профиля/журнал ремонта. Исходные версии первых трёх старше профиля123000; это не причина переписывать существующую историю.

Наследуемые ACL очищаются исключительно у создаваемых в этой транзакции объектов, после проверки OID, владельца и типа. Глобальные default ACL, роли и старые объекты не меняются. Строгие финальные GRANT/postguard сохраняются.

Edge entry: `supabase/functions/platform-course-file/index.ts`; gateway `verify_jwt=true` дополняет проверку обычного пользователя и текущих прав в SQL. `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` берутся только из существующего server runtime; значения не выводятся. `PCF_ENFORCEMENT_SHA256` — результат свежего проверенного установленного `pcf_v1_enforcement_stamp()`, а не хеш файла миграции или старой репетиции. Без корректной конфигурации обработчик закрыт. Публикация статического сайта не доказывает выпуск Edge.

## Проверки и продолжение

Пакет прошёл полный TypeScript и production Vite build на актуальном main188. Фронтенд:34файла/401assertion плюс7 проверок ожидания. Изолированный PostgreSQL:113сценариев,38клиентов и32этапа с естественным exit0. Cloud-репетиция пяти точных частей и14контрольных компонентов автоматически откатилась;41контрольная группа данных совпала внутри и при отдельном чтении после неё. Эти уровни проверки не заменяют реальный Auth/Storage и проверку рабочего сайта.

Все delivery capability flags остаются false до отдельной реальной приёмки. Существующий reader текущего досье пока удерживает публикацию программ с файловыми материалами; фиксация или предпросмотр не обходят это условие. После записи истории нельзя удалять новые namespace/receipts для отчёта или механически склеивать старые DROP-inverses. При проблеме сохраняются история и данные, отзывается выпуск приложения/Edge либо выпускается точечное forward-исправление.
