# Редакции собственных программ и точные файлы

Работа относится только к текущим собственным курсам организации `4ac2c05a-d8b5-4e72-ba31-f2c743091d95`. Клиентские копии, старые попытки, оценки, финансовая история, тарифы и договорная постоплата СГТ сохраняются. Телефония отложена.

## Отдельные состояния

Текущий курс, неизменяемое досье, решение по досье, публикация шаблона и утверждение учебным центром различаются. Фиксация байтов не является методической или правовой приёмкой. Сохранённое досье выбирается явно; его предпросмотр не заменяется текущим файлом или банком вопросов. Изменение исходника не переписывает прежнее досье, решение или результат обучения.

Файлы фиксируются только штатным входом уполномоченного модератора: сервер создаёт intent по точной ссылке, новый `platform-course-file` получает исходник через обычный authenticated Storage read и сохраняет фактические байты с SHA-256. Чтение работает по receipt; браузер проверяет область, размер и полный хеш. Публичные и подписанные ссылки не служат запасным источником. Технический предел одной операции8MiB не является тарифным ограничением учеников или СГТ. Фиксация по существующему серверному протоколу снимает текущую отметку проверки собственного курса в каталоге и обновляет его область редакции: после неё требуется новое досье и отдельное решение. Это не изменение клиентских копий или результатов.

## Выпуск

Пять миграций: `20261028000000`, `20261028000001`, `20261028080000`, `20261028140000`, `20261029010000`. Установщик проверяет конкретные исходники и отсутствие каждой записи, затем применяет и регистрирует только эту партию атомарно. Для штатной фиксации текущего файла добавляется отдельная миграция `20261029013000_platform_course_current_file_capture`: сервер в одной транзакции проверяет ожидаемую редакцию, текущую ссылку и свежий intent. Её отдельный регистратор добавляет ровно одну запись651 после установленной базы650. Нельзя запускать общий db-push/reconcile или повторять уже применённые пять миграций, профиль или журнал ремонта. Исходные версии первых трёх старше профиля123000; это не причина переписывать существующую историю.

Наследуемые ACL очищаются исключительно у создаваемых в этой транзакции объектов, после проверки OID, владельца и типа. Глобальные default ACL, роли и старые объекты не меняются. Строгие финальные GRANT/postguard сохраняются.

Edge entry: `supabase/functions/platform-course-file/index.ts`; gateway `verify_jwt=true` дополняет проверку обычного пользователя и текущих прав в SQL. `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` берутся только из существующего server runtime; значения не выводятся. `PCF_ACCEPTED_ENFORCEMENT_SHA256` — неизменный несекретный fingerprint в серверном entry, взятый из свежего подтверждённого COMMIT и отдельного `pcf_v1_enforcement_stamp()`. Значение не берётся из запроса, переменной окружения или автоматически из текущей базы; хеш миграции и старой репетиции не подходят. При изменении принятого SQL требуется новая проверка и выпуск source pin. Вход свежей фиксации сверяет fingerprint до Storage; прежний исторический replay и чтение receipt сохраняют собственные текущие проверки прав и не объявляются глобально выключенными этим pin. Публикация статического сайта не доказывает выпуск Edge.
