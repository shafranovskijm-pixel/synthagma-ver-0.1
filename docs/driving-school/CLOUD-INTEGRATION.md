# Автошколы в СИНТАГМЕ: контракт переноса MVP

## Согласованное решение владельца, 06.09.2026

Встроить уже собранный локальный MVP автошкол в существующую СИНТАГМУ. Общая регистрация и вход СИНТАГМЫ; backend — её действующий Lovable Cloud. Не отдельный Auth, Node-сервис, SQLite, Supabase-проект, Cloudflare/Sites или платный Timeweb-сервер. Не переносить локальные аккаунты, пароли и демонстрационную базу.

Рабочая feature-ветка основана на проверенном production GitHub main 7a2d9e08a7d337103920524f37443d5b9a1e13b0. Не заменять main другим старым Lovable snapshot. До приёмки не Publish/merge/deploy, не выполнять DDL/DML Live, не применять чужие pending-миграции. SQL автошколы сначала сохранить файлом для проверки; отсутствие таблиц должно давать ясное состояние «модуль ещё не подключён», а не фиктивные данные/успех.

## Сохранить работающий продукт

- Не менять обычный кабинет ученика, редактор курсов, зачисление, документы ГОРЭЛТЕХ, тарифы, T-Банк/Novofon, рассылки, общий стиль лендинга и существующие RLS/SQL helpers.
- Реализовать новые модули и изолированную миграцию с префиксом `driving_`. Не отключать RLS и не выдавать anon/authenticated unrestricted writes.
- Переиспользовать существующие UI primitives, Supabase client, AuthProvider/useAuth и согласованный в приложении proxy transport. Не добавлять второй клиент с прямым supabase.co URL и не менять общий Nginx/proxy ради модуля.
- Общий вход через `/login?next=...`, регистрация новой организации через существующий `/register-organization` и её Edge handler. Вновь зарегистрированная автошкола должна завершить обычную регистрацию и попасть в подключение модуля. Существующий владелец подключает модуль идемпотентно, без повторного создания организации/Auth user.
- Не доверять роли, organization_id и user_id из URL/localStorage/client payload без серверной проверки. Различать profiles.id и profiles.user_id.

## Интерфейс и маршруты

1. На лендинге/в футере компактный вход «Автошколы — Beta», без переделки лендинга. Страница `/auto-schools` содержит вход/регистрацию и честное описание пилота, ведёт в общий Auth, не отдельную форму пароля.
2. В кабинете организации модуль `/organization/driving-school`, либо согласованный со штатным router эквивалент, с действующим Org context. Пункт «Автошкола — Beta» виден владельцу или явно уполномоченному сотруднику; не показывать рабочий доступ студенту по одному наличию профиля.
3. Сам модуль сохраняет структуру локального MVP: Сегодня; Расписание; Ученики; Команда и автомобили; Обучение и выпуск; Финансы; Настройки/Помощь. Карточка ученика: обзор, занятия, теория, оплаты, документы. Использовать визуальную структуру файлов `reference/*`, а не создавать другой макет. Сохранить мобильное меню.
4. Для driving-ученика/инструктора отдельный защищённый маршрут с общей сессией и серверной driving membership. Не менять глобальный `/student` и его маршрутизацию. У инструктора только назначенные занятия/ученики; ученик видит себя. Не давать инструктору global organization/admin или org_staff.teacher автоматически.

## Данные и права

- Сущности школы связаны с существующей organizations.id; существующие ученики связываются по подтверждённому profiles.user_id/auth.users.id. Новый ученик создаётся только существующим register-student с его лимитами и проверкой результата. Если полноценное связывание инструктора требует дополнительного безопасного приглашения — реализовать scoped одноразовое приглашение, не второй Auth.
- Нужны программы/версии (категория, трансмиссия, план практики), группы, назначение ученика программе/группе/инструктору, автомобили, инструкторы и смены, занятия, финансовые записи, экзамены, аудит.
- Tenant-composite FK либо эквивалентная серверная защита всех связей. Owner/staff: актуальный проверенный `can_access_organization` + конкретное разрешение. `has_org_staff_permission` в одиночку не проверяет expires_at. Ученик/инструктор: отдельная membership и проверка назначения, не широкое право по profiles.organization_id.
- При нескольких организациях не брать первую произвольную. Использовать штатный выбранный org context, подтверждённый сервером. Подмена tenant — отказ. Admin-view только через штатный авторизованный механизм.
- Все записи серверные и переживают reload. Не выдавать fallback demo/localStorage за Cloud. Ошибки загрузки/сохранения видимы, toast успеха только после подтверждённой записи.

## Рабочие правила MVP, не потерять при переносе

- Запись на практику: ограничения по смене, горизонту, инструктору, автомобилю, трансмиссии и доступному остатку; пересечения ученика/инструктора/автомобиля запрещены транзакционно, в том числе при двух одновременных запросах. Смежные интервалы разрешены.
- Перенос/отмена: учитывают исходную запись и освобождают резерв; student deadline соблюдается; запрещено выдавать повторный запрос за новое занятие. Бронь не означает проведённое обучение.
- Факт/неявка: подтверждать только после конца занятия, владельцем либо назначенным инструктором. Фактические минуты отдельно от плановых/резерва. Идемпотентное подтверждение. Коррекция с причиной и аудитом, без превышения плана. Общее время хранить UTC, ввод/показ по явно выбранному часовому поясу школы, не неявно по времени компьютера.
- Программы и план практики задаёт школа по своим документам. Не объявлять демонстрационные 600 минут законодательным нормативом.
- Ручные начисления/оплаты в копейках: operation-id + payload idempotency; повтор не создаёт вторую оплату. Исправление сохраняет исходную запись и причину, меняет баланс через reversal, не удаляет историю. Банковской интеграции нет.
- Теорию предпочтительно связать с существующими рабочими курсами/тестами СИНТАГМЫ. Если переносится отдельный простой урок/вопрос из MVP, проверка на сервере, правильные ответы ученику не возвращать. Не выдавать демонстрационные вопросы за официальный банк ПДД.
- Экзамены — ручные записи внутреннего/внешнего результата с датой/протоколом. Не имитировать государственную отправку/выдачу документа.
- Журнал практики, результаты и экспорт содержат факты этой школы/ученика. Документы обозначены «Черновик»: исходные утверждённые формы автошкол пока не предоставлены. CSV безопасен для открытия в таблицах; печать не включает навигацию.

## Приёмка переноса

Сначала код + проект SQL + targeted tests/typecheck/build, без Live DDL. Отдельно проверить SQL на изолированном PostgreSQL с фактическими auth/tenant контрактами. Затем backup gate и только точечная новая миграция, read-only postflight, backend, frontend и реальный синтагма.рф (Lovable publish не равен Timeweb domain deploy).

Сценарии: общий вход старой организации; новая регистрация с возвратом; подключение модуля без дубля; две школы не видят/не меняют друг друга; чужой student/instructor/expired staff получает отказ; ученик с группой; запись/конфликт/отмена/перенос; факт/неявка/коррекция; повтор оплаты; тест/экзамен; журнал/экспорт; reload. Рабочие курсы, зачисление и обычный student UI не регрессируют.
