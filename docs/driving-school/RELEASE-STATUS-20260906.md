## Временная защита, подтверждена Live

SQL `20260906114000_driving_module_pilot_gate.sql` проверен локально на одноразовой in-memory PGlite БД с отдельными legacy-свидетелями, затем выполнен вручную через SQL editor одной транзакцией. Отозваны права PUBLIC/anon/authenticated только на 30 новых функций, 15 новых таблиц и driving_audit_id_seq. Ничего не удалено. Это обратимая изоляция непроверенного модуля, не откат данных.

После применения: клиентских EXECUTE anon=0, authenticated=0; школы/ученики/занятия/приглашения/финансы=0. Контрольные отпечатки ACL старых объектов до и после совпали:

- public functions, кроме driving_: `2cb9295f1e340a937cdc051a7823a1b3`.
- public relations, кроме driving_: `70750f8b25c6c7912abe87619c579507`.

Это не полная E2E-проверка LMS. История supabase_migrations для ручного safety gate пока не регистрировалась; при оформлении выпуска учитывать этот факт, не предполагать по таблице истории, что gate не применён. Повтор SQL gate идемпотентен при том же наборе функций.

## Не готово / запрет на обещание клиентского пилота

- Общая регистрация с возвращением в автошколу и связка действующего ученика — предстоит.
- Перенос runtime UI/стилей/API-адаптера — предстоит; reference-файлы не подключены в приложение.
- Исправление Cloud SQL, проверка auth/RLS/границ организаций/конкурентных запросов — предстоит.
- Тесты перенесённого модуля, публикация реального синтагма.рф и E2E — не выполнены.

Не снимать safety gate автоматическим широким GRANT. Сначала точечно исправить SQL, проверить в изолированной БД и общую регистрацию, затем предоставить только необходимые права. Не применять чужие pending migrations. Не выпускать перегенерированные types без проверки сохранения существующих контрактов. Не выдавать локальную SQLite-версию за Cloud-пилот.
