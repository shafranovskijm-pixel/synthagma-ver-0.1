## Граница пилота

Включены только текущий собственный source и одна явно разрешённая синтетическая QA-копия с точными организацией, provenance, версиями и картой 15 элементов. Название, похожий контент и общий `source_course_id` не включают клиентские копии автоматически. Регистрация не создаёт пользователей, персональные гранты, зачисления или учебные результаты.

Завершение подтверждается сервером по трём тестам с порогом 70 и четырём проверенным практикам со score в диапазоне 0–100. Порог 70 обязателен только для итоговой практики; оценки остальных практик не превращаются в неутверждённое дополнительное требование. Ограниченная процедура продления истёкшего активного доступа сохраняет identity, progress, status и прежние результаты.

Таблицы политики, привязки и доказательств не выдаются напрямую клиенту. Узкий authenticated RPC `get_platform_learning_task_proof(uuid, uuid)` проверяет текущего участника, курс, элемент и точную версию. Он не отдаёт банк ответов, чужие персональные данные или глобальное разрешение на клиентские курсы.

## Условия публикации frontend

1. Сохранить фактический DB readback и совпадение записанной версии `20261027000000` с companion source. DB gate уже пройден; повторная установка не нужна.
2. Выпустить отдельно проверенный frontend. Наличие файлов миграции или успешный SQL readback не подтверждают публикацию frontend.
3. Проверить живые экраны и полный синтетический учебный сценарий с реальными правами. До этого статус рабочего UI остаётся `NOT_ACCEPTED`.

Создание нового namespace не использует `CREATE TABLE IF NOT EXISTS` или ledger-upsert. На production версия уже учтена; не следует повторно исполнять SQL вручную, переименовывать миграцию для replay или добавлять `ON CONFLICT` для сокрытия расхождения ledger. Существующий оператор `ON CONFLICT` внутри функции записи completion evidence — сохранённая дедупликация runtime-события, не обход установки.

На новом окружении migration runner должен выполнять файл атомарно: начальная регистрация использует writer fences, удерживаемые DDL до commit. Миграция не загружает seed-курсы или банк: source и синтетический QA tuple с точными версиями должны быть подготовлены отдельно. При несовпадении схемы, владельца, полномочий или literal hash выпуск должен остановиться для проверки.

## Сохранение данных и оставшиеся границы

Материалы, банк вопросов, прежние попытки и баллы, клиентские курсы и их цены не переписываются этой схемной миграцией. Содержательные исправления программ и их приватные журналы остаются вне публичного SQL companion.

Операционная фиксация завершения не является утверждением образовательной программы, предметной приёмкой, аттестацией, выдачей документа или нормативным основанием. Изменения телефонии в этот выпуск не входят.

После появления законных bindings/evidence не допускается разрушительный rollback с удалением таблиц или истории. Расхождения исправляются отдельным проверенным forward-изменением с сохранением данных.
