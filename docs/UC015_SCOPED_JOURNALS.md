# UC015: журналы с областью и источниками

Документ описывает пакет миграции `20261021200000_uc_scoped_journal_context_exports.sql`. Наличие этого файла не подтверждает публикацию: фактический выпуск, нативные проверки и проверка рабочего интерфейса фиксируются отдельно в артефактах релиза.

## Область журнала и прежние данные

Журнал создаётся для организации либо конкретной группы. Для группы сервер сам определяет курс и подтверждённую версию программы; клиент передаёт только идентификатор группы. Область закрепляется при создании. Если связь группы с программой изменилась, прежний журнал остаётся доступен для чтения, истории и выгрузки; новые изменения в нём недоступны. При отсутствии подтверждённой программы создать журнал группы нельзя.

Прежние журналы организации, их определения, строки и импорт из браузера сохраняют API версии 1. Они не переносятся автоматически. Новые журналы используют прежние серверные определения схем, но отдельные закрытые таблицы строк, истории, запросов и выгрузок. API версии 1 исключает новые журналы из списка и не допускает обращения к ним напрямую.

## Права

| Действие | Требование |
| --- | --- |
| Читать журнал, историю и сохранённую выгрузку | Актуальное `journals.read`, доступ платформы и соответствующая область |
| Подготовить сохранённую выгрузку | Те же права чтения; `journals.write` не требуется |
| Создать или исправить журнал/строку, изменить архив | Дополнительно актуальное `journals.write` |
| Работать преподавателю | Только назначенная ему группа; роль преподавателя сама по себе не даёт запись |

Проверки выполняются сервером при каждом запросе, повторе и скачивании. Отзыв назначения группы прекращает доступ. Ограниченный преподаватель не получает доступ к журналам всей организации; ограничения просмотра и записи для viewer/sales сохраняются. Права на просмотр связанных занятий и результатов также проверяются соответствующим образовательным контуром.

## Строка, источник и исправление

Строка относится к выбранному лицу либо явно создаётся **без указания лица**. В последнем случае ученик не назначается автоматически. Такой режим недоступен, если схема содержит поля с семантикой ФИО, телефона, email, должности или подписи лица. Произвольный текст не проходит универсальное распознавание персональных данных: не включайте в него сведения о неуказанных третьих лицах.

Схема допускает до 32 полей. Строковое значение ограничено 4 000 единицами UTF-16, серверный JSON значений одной записи — 32 КиБ UTF-8. Это проверки размера и типа, а не распознавание чужих персональных сведений.

Для журнала группы можно выбрать серверный источник:

- проведённое занятие — точную версию, её хеш и соответствующий состав;
- решение по результату — точные сведения об обучении, состоянии результата, машинном расчёте и решении преподавателя;
- отсутствие связи — ручные сведения, которые не становятся подтверждённым образовательным фактом.

Участник и источник строки закреплены. Для другого лица или другой версии источника создаётся новая строка. Изменение ручных значений требует причины, проверяет ожидаемую версию и сохраняет предыдущую редакцию. При конфликте следует обновить данные; после неопределённого результата используется **«Повторить тот же запрос»**, а не новый запрос на создание.

Каждая редакция сохраняет собственную схему, подписи и типы полей. Переименование или удаление столбца новой схемы не меняет старые значения и историю. Если занятие исправлено или результат изменился, прежняя ссылка сохраняется с признаком неактуального источника. Ручные поля «Результат»/«Оценка» не заменяют решение преподавателя; завершение курса не подтверждает посещение.

## Сохранённые HTML и JSON

В редакторе используйте **«Подготовить сохранённую выгрузку»**, затем **«Скачать HTML»** или **«Скачать JSON»**. Сервер фиксирует полный набор строк, включая архивные, всю историю и исходные схемы каждой редакции. Видимая страница таблицы не служит источником выгрузки; одна версия заголовка журнала также не заменяет версии всех строк.

Сервер сохраняет `manifest_text` и `html_text` один раз вместе с SHA-256 их байтов UTF-8. Повторное скачивание возвращает эти строки после новой проверки доступа и хешей. Последующие исправления журнала или обновление клиентского шаблона не пересобирают прежнюю выгрузку. Для нового состояния нужен новый снимок. JSON сохраняет типы, `null`, ведущие нули строковых номеров и точный текст десятичных значений; HTML экранирует текст и показывает сохранённые редакции.

Один полный снимок ограничен **1 000 строками, 10 000 редакциями истории и 8 МиБ суммарного UTF-8 текста HTML + JSON**. При превышении сервер отклоняет снимок целиком, не обрезает его и не создаёт частичный результат. Это техническая граница одной выгрузки, **не лимит хранения строк, не ученический слот и не тарифный лимит**. Правила месячных назначений, постоплаты и безлимитного договора СГТ этот пакет не меняет.

## Удаление персональных копий

Штатные локальные функции подсчёта и удаления персональных данных учитывают новые строки, историю, авторов, ссылки и выгрузки. При разрешённом удалении лица связанные сохранённые выгрузки и квитанции удаляются; строки самого субъекта удаляются, остальные затронутые копии консервативно редактируются. Это касается и текста автора в записи без указания лица.

Сервер не выдаёт персональную выгрузку после её удаления и не пересчитывает содержимое под прежним хешем. Уже скачанный пользователем файл сервер отозвать не может. Проверять удаление следует на синтетических данных штатным механизмом, без прямого изменения таблиц.

## Для разработчика и проверки выпуска

Публичная граница — `read_scoped_custom_journals(uuid,jsonb,jsonb)` и `apply_scoped_custom_journal_action(uuid,jsonb,bigint,uuid,jsonb)`, контракт ответа версии 2. Пять таблиц `uc_scoped_journal_*` закрыты RLS и отсутствием прямых прав; внутренние функции доступны только владельцу. Новые RPC доступны `authenticated` и выполняют собственные проверки.

Все изменения строк/схем/архива и создание снимка используют одну блокировку строки журнала. Сервер сохраняет весь снимок атомарно. Чтение связывает копируемые данные и точный набор субъектов/авторов в одном SQL-снимке, затем проверяет их privacy-fence до выдачи ответа. Если необходимую блокировку или актуальный доступ подтвердить нельзя, сервер возвращает отказ/конфликт, а не незащищённую копию.

До публикации нужны нативная проверка реальных RPC и проверка интерфейса двумя независимо авторизованными сотрудниками: общие данные и конфликт исправлений; отказ чужой группе; более одной страницы строк/истории; идентичность повторного скачивания после правок; отказ после отзыва доступа; штатное удаление персональных копий. Старые данные, ACL, тарифы и образовательные факты проверяются на сохранность отдельно.

Журнал и выгрузка не выделяют официальный номер, не выдают документ об образовании и не создают электронную подпись. Поле «Подпись» остаётся непроверенным текстом. Реестр официальной выдачи и подписание относятся к отдельным этапам дорожной карты.
