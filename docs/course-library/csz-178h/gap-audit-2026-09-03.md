# Gap-аудит электронной библиотеки ЦСЗ, курс 178 часов

Дата проверки: 2026-09-03

Область проверки: локальный `candidate-manifest.json`, реестр URL,
исходные файлы на диске D: и read-only просмотр первичных веб-источников.
Старый курс, Supabase, Storage, staging и production не изменялись.

## Решение

**NO-GO для импорта и публикации.** Манифест имеет `not_approved`,
`import_ready=false`, `overall_decision=NO_GO`; ID нового курса и всех модулей
отсутствуют. Ни один из 28 внешних ресурсов не имеет статуса `APPROVED`, у всех
стоит `import_action=HOLD`. Два внутренних файла существуют, но их имена прямо
указывают «ДЛЯ УТВЕРЖДЕНИЯ» и они также остаются `HOLD_UNTIL_APPROVED`.

Zero-I/O валидатор может проверить только структуру манифеста. Он не доказывает
существование курса в базе, tenant, 178 часов, unpublished-состояние, feature
flag, принадлежность module ID или отсутствие повторного импорта.

## Обязательные пробелы до MANIFEST_VALID

1. Создать отдельный новый курс ЦСЗ на 178 часов и получить его UUID. Старый
   опубликованный курс `e3737d51-c092-4564-b2a6-4c9b86245ff4` остаётся в
   hard denylist и не меняется.
2. Получить UUID всех 11 модулей нового курса и подтвердить их принадлежность
   этому курсу в staging.
3. Утвердить состав библиотеки: для каждой принимаемой строки поставить только
   согласованную комбинацию `approval_status=APPROVED`, `import_action=IMPORT`,
   `library_status=active` и ровно один источник.
4. Утвердить два собственных PDF и определить, к каким модулям или ко всему
   курсу они относятся.
5. Для link-only материалов зафиксировать решение «храним только внешнюю
   ссылку». Для копирования файлов получить достаточное основание и сохранить
   его в `usage_basis`.
6. После этого выполнить отдельную DB-backed проверку migration/RLS/Storage и
   только затем рассматривать транзакционный импорт.

## Что можно закрыть без внешних отправок

1. Повторно открыть и записать точные title/content-type для всех доступных
   официальных и manufacturer link-only URL.
2. Найти первичные официальные замены для 02–06, 26 и 27; замену принимать
   только при точном совпадении документа/модели.
3. Проверить PDF 09–25 на соответствие заявленному изделию и редакции, вычислить
   SHA-256 только для локально разрешённых копий; это не заменяет правовое
   решение.
4. Подготовить проект матрицы `module_no -> материал`, не заполняя выдуманные
   module UUID.
5. Подготовить link-only вариант манифеста, исключающий 22, 26–28 и внутренние
   PDF до утверждения. Он всё равно должен остаться `NO_GO`.
6. Прогонять zero-I/O validator и тесты локально. Не запускать migration/import
   и не менять `approval_status`, пока нет нового курса, module UUID и решения
   владельца продукта.

- создание нового курса и модулей в контролируемой среде;
- staging DB/RLS/Storage E2E и отдельное решение о production.
