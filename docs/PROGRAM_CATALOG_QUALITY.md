# Качество программ и ключей тестов

Проверка каталога — инженерная проверка. Она не утверждает образовательную программу и не заменяет решение учебного центра о праве выдавать документ.

## Ключи и попытки

- `correct_answer` — целый индекс с нуля. Для непустого массива вариантов допустим диапазон от0 до length−1.
- NULL разрешён для черновика вопроса, но такой вопрос не считается готовым для валидированного теста.
- Проверка готовности учитывает границы индекса и ошибки чтения; сбой запроса не даёт статус «готово».
- Ограничение `prog_test_questions_nonnull_answer_key_valid` создаётся NOT VALID: старый банк не переписывается молча, но новые записи и UPDATE проверяются. Даже изменение explanation старой некорректной записи требует сначала подтверждённого ключа.
- Не исправлять все индексы сдвигом −1 и не считать чужую копию правильным источником. Для каждого изменения нужны проверенный материал/первичный источник, редакция, точное соответствие вопроса и вариантов и сравнение прежней строки.
- Предметная проверка может выявить двусмысленность самого вопроса или отсутствие правильного варианта. Тогда создаётся прослеживаемая новая редакция вопроса/вариантов с обоснованием.
- Тестовые ответы и полный банк не публиковать в Git, логах и публичных артефактах. Частные content-batches применять отдельно с журналом, после проверки источников.
- Начатая попытка сохраняет `test_attempt_sessions.questions_snapshot`; завершённая — прежний score/result. Исправления банка действуют на новые попытки. Старые снимки, оценки, лимиты попыток и квоты не сбрасывать и не пересчитывать.
- Одноимённые занятия могут быть разными редакциями. Проверка/автоисправление не удаляет их вместе с lesson_progress, вопросами и файлами.

## Паспорт

Часы и вид берутся из явного паспорта материала и сверяются с учебным планом. Не выводить квалификацию и тип документа из названия курса или отметки ПК/ПП. Известные коды: `qualification_upgrade`, `professional_retraining`; подтверждённые часы сохраняются в `frdo_duration_hours`.

Первый ограниченный пакет содержит новые50: два подтверждённых поля, только NULL→значение; прежние значения и остальные поля не меняются. Материалы и источники остаются прежними. Документ выдачи для этой партии не подтверждён и остаётся неизвестным. Это не создаёт `program_fact_versions`, не утверждает файл программы и не связывает его автоматически с группой/выдачей.

## Журнал и выпуск

`prog_content_repair_journal` сохраняет прежнюю/новую строку, хеши JSONB и основание исправления. Он закрыт для клиентских ролей и не содержит попыток/личных дел учеников. Записи не переписываются и не удаляются; правильные ключи доступны только серверному владельцу данных.

Штатное снятие `is_validated` при изменении курса/занятия/вопроса сохраняется. Не отключать триггер и не возвращать готовность всем курсам. Для точной изменённой партии требуется новая инженерная проверка; курс с пустым тестом или некорректным ключом не переутверждать как готовый.

Срез аудита26.10.2026: 624 организационных курса, 376 платформенных карточек, 362 активные валидированные, 295 публичных. Эти числа не постоянные тарифные или программные лимиты. Первый аудит644некорректных ключей/102курса не означает непроходимость каждого курса. Остаток ремонта рассчитывается по фактическим данным.

Тарифные решения, безлимитная постоплата СГТ, старые договоры/счета и отложенная телефония сохраняются.
