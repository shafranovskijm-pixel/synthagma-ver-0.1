# ГОРЭЛТЕХ: серверные факты документов, кандидат v15

## Что меняется

- Приказы о зачислении/отчислении и список учеников используют строки из
  серверных запросов, а не HTML, присланный браузером.
- Связи — ID ученика, организации, группы, курса и зачисления. Одинаковые ФИО
  не объединяют людей. Порядок отображения — ФИО, затем ID при совпадении.
- Состав — активные профили текущей группы. Незачисленный участник остаётся
  в черновике приказа с замечанием, а не исчезает из документа.
- Паспорт и образование читаются только из `student_frdo_data` текущей
  организации. Дополнительно исправлен такой же tenant-фильтр в GroupFolderTab.
  Edge читает этот личный источник с JWT вызывающего пользователя, а не через
  service-role обход RLS: право `documents.manage` само по себе не расширяет
  доступ к паспортам. Строки, скрытые RLS, не считаются подтверждёнными данными.
- Программа, часы и даты трёх документов берутся из сохранённой группы/курса.
  Некорректные даты не исправляются догадкой. Основание приказа остаётся пустым
  по согласованной правке клиента; подписант и исходные DOCX не изменены.
- При недоступном источнике его частичные страницы не сохраняются как полные
  данные: остаётся отдельное замечание. Отсутствие необязательных данных не
  запрещает создание курса, зачисление или получение черновика.
- `variables_snapshot` хранит `row_sources`, `fact_issues`, `source_issues`.
  Это подтверждает происхождение строк, но ещё не является неизменяемым
  транзакционным снимком всех фактов группы.
- В списке документов сохранённые замечания доступны после перезагрузки:
  «Требует проверки» и раскрываемые причины. Dry-run с замечаниями показывает
  предупреждение, а не безусловный успех; скачивание черновиков не отключено.

## Границы готовности

Ни один файл не переводится в `final`; официальные номера не резервируются.
Итоговая аттестация, книга регистрации, расписание и пропуск пока используют
старый транспорт фактов. Ручные данные и атомарная финализация ещё требуют
доработки. Нельзя выдавать эту версию за завершённый комплект ГОРЭЛТЕХ.

Новая точная ревизия Edge и клиентского dry-run:
`goreltech-group-package-server-facts-v15`. Старая ревизия не принимается
новым клиентом для dry-run: проверка не должна незаметно обратиться к старому
генератору. Обычное сохранение остаётся черновым.

1. Отдельно выпустить минимальный frontend tenant-фильтр после его locked gate.
2. Для v15 завершить unit/component/DOCX проверки, app TypeScript и build.

   перезагрузку, замечания, скачивание и визуальную сверку всех девяти DOCX.
