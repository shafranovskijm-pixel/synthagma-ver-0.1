# UC026: закрытая диагностика защитных отказов

Изменение добавляет различимые причины unsafe_target в одном сетевом helper. Лог содержит только постоянный маркер [PublicationCheckGuard] и один код из закрытого набора в DEPLOYMENT_MAPPING.json. URL, адреса соединений, HTTP заголовки и тела, ошибки провайдера, токены и идентификаторы в новые логи не передаются. Сбой логирования перехватывается до прежнего отказа.

Сохранены исходный порядок проверок, DNS pinning, проверка TCP/TLS peer и TLS hostname, отсутствие передачи учётных данных, ограничения размера/времени/редиректов, очистка соединения и весь JWT/actor/service/lease/CAS/SQL контур. Схема observation и ответы API не меняются.

Проверено локально одним запуском: 41/41 (22 прежних транспортных и worker/JWT проверки плюс 19 новых paired privacy/regression). Новые проверки сопоставляют настоящий старый и новый helper: точные сетевые действия и результаты, 15 причин, приватные исключения шести сетевых await, отказ логгера и ALPN. Это изолированные тесты с подставной сетью, не доказательство работы облачного Deno.

Один разрешённый API build собрал ровно 5 TS исходников и один внешний npm:@supabase/supabase-js@2.90.1, без сетевого получения SDK. runtime.bundle.js — сгенерированный файл; редактировать следует shared helper или runtime-source.ts, затем повторять явно проверенную упаковку. Thin index.ts, runtime-source.ts и supabase/config.toml сохранены байт в байт. Исторические материалы предыдущего выпуска не переписываются.

Отдельное прежнее падение CLI esbuild до stdin сохранено. Последующий успешный API build не объясняет причину того падения и не засчитывает прежнюю сборку приложения. Облачная причина unsafe_target, native SDK resolution и рабочая приёмка ещё не подтверждены. После выпуска root выполнит одну новую обычную проверку существующей редакции; повтор уже committed job возвращает сохранённый результат и не создаёт нового сетевого наблюдения.
