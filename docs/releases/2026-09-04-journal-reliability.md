# Ручные журналы: сохранение и восстановление после сбоя

## Область изменения

Только кабинет организации: `JournalEditor` и `useJournalEditor`.
Интерфейс ученика, прохождение курсов, исходные DOCX и схема базы не изменяются.
Основа ветки: `595249eb42d7b59d73293c4d734695b743f72efa`.

## Исправления

- Посещаемость показывает фактически записанный статус, а не значок присутствия для всех значений.
- Пустая отметка и неизвестное старое значение не выдаются за присутствие.
- `entry_control` сохраняет `attendance`, как и журнал посещаемости.
- Обновление ограничено журналом, учеником, датой, ID и прочитанной версией `updated_at`.
- Сохранённая отметка проверяется повторным чтением. Нулевая строка, ошибка или расхождение не показываются как успех.
- После неподтверждённого изменения дальнейшие записи отключены. Кнопка «Перезагрузить журнал» снимает блок только после успешной загрузки.
- Повторные клики до перерисовки не вставляют второй экземпляр записи.
- Поздний ответ другого журнала не подменяет текущие данные. Возврат A → B → A во время записи требует свежей загрузки после её завершения.
- Создание и удаление проверяют возвращённую запись и принадлежность организации. При неопределённом ответе перечитывается список; существующий выбор сохраняется.
- Ошибки загрузки видны в интерфейсе; просмотр и выход остаются доступны.

## Подтверждённая локальная проверка

- 5 файлов, **74 теста прошли**: hook defaults/persistence, фактические popover-кнопки посещаемости/оценок, безопасность списка журналов и контекст группы.
- JSON: `D:/CodexTmp/sintagma-journal-final-targeted-20260904.json`.
- ESLint для пяти изменённых исходных/test-файлов: exit 0.
- TypeScript приложения (`tsc -p tsconfig.app.json --noEmit`): exit 0.
- Production build — отдельный gate; его терминальный результат и SHA фиксируются в continuation checkpoint после завершения.

Это не доказательство production E2E: запросы Supabase в hook-тестах замоканы.
Для приёмки нужны вход в кабинет организации, реальная запись/перезагрузка, переключение журналов и проверка ошибки соединения.

## Что этот релиз не закрывает

1. Ручные отметки пока не связаны с генератором Word-журнала ГОРЭЛТЕХ: компилятор оставляет `MARK_1..4` пустыми и помечает источник `unavailable_blank`.
2. В текущей схеме ручной журнал привязан к курсу, но не к группе. Нельзя автоматически выбирать «последний журнал курса» для группы: нужна явная связь.
3. В исходном шаблоне подтверждён знак `V`; обозначения отсутствия, опоздания и уважительной причины должен подтвердить заказчик. Они не придуманы этим изменением.
4. Между независимыми клиентами отсутствующая уникальность `journal_id/user_id/entry_date` остаётся задачей схемы. Текущие guards предотвращают локальный повтор и обнаруживают имеющиеся дубли, но не заменяют ограничение базы.
5. Публикация frontend, Edge-функций и миграций выполняется отдельно. Ветка не должна считаться опубликованной по одному Git push.
