## Что подтверждено в frontend

- ГОРЭЛТЕХ: проверка подписантов и пересборка ровно девяти Word-документов через `compile-group-class-journal`.
- Результаты тестирования: просмотр и XLSX-экспорт с ФИО, email, курсом, тестом, результатом, баллами и максимальным баллом.
- Охрана труда: кнопка `Черновик XML (Beta)` и явное предупреждение, что это внутренний формат СИНТАГМЫ; совместимость с актуальной XSD/API Минтруда не заявляется.
- Документы ГОРЭЛТЕХ формируются как черновики; неподтверждённые значения не должны превращаться в официальный документ.

## Что намеренно не запускалось на реальной группе

Авторизованная кнопка пересборки не является dry-run: она загружает новый пакет в private Storage, создаёт девять строк `group_documents` и переводит предыдущие версии тех же типов в `is_current=false`.

Поэтому пакет не генерировался на действующей группе клиента. Для полного production-E2E нужна заранее подтверждённая disposable QA-группа внутри tenant ГОРЭЛТЕХ с синтетическим слушателем и проверенными подписантами. Отдельная тестовая организация не подходит: сервер проверяет профиль ГОРЭЛТЕХ.

## Риск статической публикации

На `синтагма.рф` отсутствующий путь `/assets/<hash>.js` сейчас возвращает SPA `index.html` с HTTP 200 вместо 404. Нельзя заменять только `index.html`: весь `dist` должен переключаться атомарно с сохранением rollback-копии. Для `/assets/*` нужен настоящий 404, для hashed assets — immutable cache, для `index.html` — no-cache.

## Решение о релизе

- **Текущий production main:** уже развёрнут; повторная публикация без изменения commit функционально ничего не добавит.
- **ГОРЭЛТЕХ:** код и backend в production; финальная клиентская приёмка девяти DOCX остаётся pending до безопасного E2E на QA-группе.
- **Электронная библиотека ЦСЗ:** `NO-GO` для merge, migration и production до staging DB/RLS/Storage E2E и утверждённого манифеста.
