## Исправленный разрыв

Мастер договора сохранял запись, но пакет получал только браузерный номер. Серверный источник пропуска не содержал договоров и всегда оставлял `CONTRACT_BASIS_LINE` пустым.

- DOCX-мастер передаёт сохранённый UUID. HTML-мастер получает реальные UUID из insert-returning либо проверки точного сохранённого набора.
- Сервер читает только выбранные UUID с правами вызывающего пользователя. Проверяются организация, группа, компания, сценарий, состояние записи и состав по UUID, а не по совпадению ФИО.
- В заполненном пропуске номер берётся из сохранённого договора. При нескольких договорах перечисляются номера. Ссылка на черновик договора не означает, что он подписан.
- Неполное покрытие состава группы явно отмечается; общая строка не изображает договор на всех учеников. Недоступные/некорректные выбранные записи блокируют сохранение, без перехода к расширенным правам.
- В пакетный `variables_snapshot` включены источники и покрытие. Пустой бланк остаётся пустым.
- Для повторной попытки до POST сохраняются неизменяемые UUID договоров и режим заполнения. После перезагрузки восстанавливаются оба параметра. Для старой операции без этих сведений доступна проверка квитанции, но не повтор с догаданными параметрами.
- При потере ответа HTML-мастера повтор в открытом мастере только проверяет сохранение: без повторного создания договоров, PDF и номеров. Восстановление этого мастера после полной перезагрузки здесь не реализовано.

Существующий механизм операции гарантирует один подтверждённый пакет. Это не обещание заморозки всех исходных записей БД, дат и подписантов до первой успешной фиксации; после фиксации повтор возвращает прежнюю квитанцию.
