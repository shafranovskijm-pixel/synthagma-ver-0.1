# Создание ученика: потерянный ответ не запускает повторную запись

## Исправление

`useStudentManagement` вызывал неидемпотентный `register-student` через общий
`safeInvoke` с автоматическими повторами. При регистрации без email и логина
повтор после потери ответа мог создать второй аккаунт с новым внутренним логином.
Это подтверждённый путь по коду, не утверждение о дублях на production.

Теперь только этот вызов передаёт `retry: false`. Синхронная защита также не
допускает два одновременных вызова из одного экземпляра формы. Успешное создание
и проверка принадлежности выбранной группе сохранены.

## Неизвестный результат

- Потерянный ответ, HTTP 408/5xx или отсутствие идентификатора ученика не означают успех.
- Форма показывает постоянное предупреждение. ФИО и выбранная группа сохраняются,
  в том числе после закрытия и повторного открытия при активном предупреждении.
- Обновление списка помогает проверить результат, но не доказывает остановку записи.
- Перед ручным повтором требуется явное подтверждение проверки. Отсутствие ученика
  в списке само по себе не является таким подтверждением.
- Ответы текущего обработчика HTTP 400/401/403/404/409 означают явный отказ до записи
  либо подтверждённую компенсацию. Неполное создание обрабатывается прежним
  `partial_success` контрактом. `safeInvoke` лишь дополнен необязательным
  `httpStatus` из настоящего `FunctionsHttpError`; повторы других вызовов не менялись.

Это не серверная идемпотентность регистрации и не защита двух независимых вкладок.
Полная перезагрузка пока не сохраняет состояние неизвестной регистрации.
Автоматически повторять запрос или объявлять отсутствие строки откатом нельзя.

## Доказательства

- Четыре целевых файла: 37 тестов, exit 0.
  `D:/CodexTmp/sintagma-register-student-no-retry-20260904.json`.
- После исправления close/reopen: четыре теста формы, exit 0, один дополнительный
  сценарий. `D:/CodexTmp/sintagma-register-student-reopen-20260904.json`.
- Интеграционный тест использует настоящий `safeInvoke` и детектор сети; подменён
  только транспорт. Returned/thrown `Failed to fetch` дают один invoke, включая
  продвижение таймеров на 60 секунд; проверяются HTTP и пустое подтверждение.
- Проверены повторный callback, освобождение блокировки, успешная выбранная группа,
  сохранение полей и сброс подтверждения ручного повтора.

Интерфейс ученика, исходные DOCX, Edge и схема базы этим исправлением не меняются.
App TypeScript, сборка и удалённый SHA фиксируются в release checkpoint после commit.
Нужна отдельная проверка опубликованной версии в кабинете организации.
