# ГОРЭЛТЕХ: читаемость документов и проверка группы при регистрации

Дата: 04.09.2026. Пакет поверх 7e4727109. Статус: кандидат в рабочей ветке, НЕ production-приёмка.

## Что изменено

- Пропуск: только текст таблицы явно использует 6,5 pt вместо случайного наследования 12 pt. Четыре узкие ячейки дат имеют локальные боковые поля 54 twips; дата выводится двумя строками DD.MM. / YYYY. Книжная ориентация, девять колонок, исходные цвета и шапка сохранены. Ручные отметки по UUID/дате/слоту из v22 сохранены, номер договора не придумывается.
- Ведомость и приказ об отчислении: продолжение длинной фамилии остаётся в области ФИО, а не под подписью преподавателя. Размер шрифта и полное имя не сокращаются. Исходные DOCX не редактируются; меняются подготовленные шаблоны через версионированный генератор.
- Компилятор и клиент требуют `goreltech-group-package-server-facts-v23`, включая заголовок, JSON fallback и проверку повторного ответа. Старые v21/v22 не выдаются за новый результат.
- Справочник групп теперь загружается единым запросом: ошибка чтения не кэшируется как успешный пустой список.
- `register-student` v4 до создания аккаунта/профиля проверяет существование группы, принадлежность организации, а также курс группы, на который может зачислить триггер. Проверка применяется и к регистрационной ссылке, и к авторизованному вызову; параметры ссылки нельзя подменить телом запроса.
- Два точных кода подтверждённого отказа до записи (`GROUP_PREFLIGHT_FAILED`, `GROUP_COURSE_PREFLIGHT_FAILED`, HTTP 500) показывают ошибку проверки группы. Неизвестные 5xx, потерянные ответы и коды только в тексте по-прежнему считаются неопределёнными; автоматического повтора создания нет.
- Шаблон Nginx открывает браузеру `x-sintagma-register-student-revision`, в том числе на ошибках. Это изменение шаблона, а не применение конфигурации на сервере.

## Оставшиеся условия до полной готовности

1. P1: проверка группы/курса и запись профиля пока не атомарны. Нужен guard в транзакции БД против смены группы/курса между preflight и записью, с SQL-тестами. Существующие таблицы/миграции этого diff не менялись.
2. P2: выбор группы с курсом должен подтверждать фактическое активное зачисление на её курс. Сейчас подтверждение отдельно выбранного курса не покрывает все случаи group-only, включая ранее истёкшее зачисление.
3. Основание пропуска — реальный связанный договор; полная визуальная приёмка девяти документов и blank/long остаются открытыми.
4. Раздельное развёртывание миграций, Edge v23/v4, frontend и Nginx; затем сценарий UI → сохранение → повторное чтение → DOCX на действительном домене. Push/build этого не доказывают.
5. Ранее запрошенное конкретное разрешение на резервную копию production с персональными данными на D пока не получено. Отклонённые экспорты/передача и unsafe URL не обходятся.
6. Официальные XSD/API Минтруда и тестовый импорт не подтверждены. Внутренний XML нельзя называть проверенной официальной выгрузкой.
7. Отдельный backlog: глобальный SDK демо T-Банка ещё загружается на лендинге и обслуживает admin tester; его можно убрать отдельно с отключением tester. Рабочий платёжный SDK ученика другой и в этот пакет не входит.

Интерфейс ученика не менялся. Полная цель остаётся активной; пакет не является заявлением «ГОРЭЛТЕХ полностью готов».
