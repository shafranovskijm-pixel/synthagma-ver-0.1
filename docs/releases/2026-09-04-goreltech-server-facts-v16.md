# ГОРЭЛТЕХ: ведомость и книга регистрации, кандидат v16

Статус: кандидат разработки, не подтверждение публикации или готовности всего
комплекта. Дополняет v15; исходные Word-шаблоны не изменяются.

## Реализованный объём

| Документ | Источник строк |
| --- | --- |
| Приказы о зачислении и отчислении | Активный состав группы + зачисления, серверные ID (v15) |
| Список обучающихся | Состав + доступные личные данные своей организации (v15) |
| Итоговая ведомость | Состав + зачисление + последний по порядку тест курса + сохранённые попытки (v16) |
| Книга регистрации | Сохранённые записи реестра, связанные с зачислениями и группой (v16) |

Для этих пяти типов сервер не использует присланные браузером HTML-строки или
скрытые значения переменных. Историческое ФИО в записи документа может отличаться
от текущего профиля: связь проверяется по ID, конфликт отображается предупреждением.
Разные записи (включая оригинал и дубликат) не объединяются по ФИО или номеру.

Выборки разбиты на страницы с проверкой точного количества, границ, дубликатов и
tenant-связей. При ошибке источник целиком отбрасывает частичный результат.
Реестр, попытки и личные данные читаются с JWT пользователя и существующим RLS;
service-role не расширяет доступ к этим данным. Нулевой результат, скрытый RLS,
не считается доказательством отсутствия фактов. Это требует проверки живых ролей.

В режиме ручного бланка ведомость не заполняет результаты, а книга не подставляет
несуществующие выданные документы. Подписи/вручение автоматически не проставляются.
Справочник стран один для браузера и сервера: перенесён существующий каталог без
изменения значений (это не новая нормативная проверка справочника).

## Что нельзя считать решённым

1. В оригинале ведомости есть пример `96 → 5`, но нет полной шкалы 2–5 и правила
   выбора попытки. Вопросы отправлены пользователю; ответа пока нет. Поэтому
   `GRADE` пуст с замечанием, при нескольких попытках результат не выбирается
   произвольно. Единственная достоверная попытка даёт фактический процент.
2. Последний тест по `order_index` соответствует существующей конвенции курса,
   но не отдельному подтверждению итоговой аттестации. При равных позициях тест
   не выбирается. Порог — сохранённый `test_passing_score`, не фиксированные 70%.
3. Попытки до `enrollments.started_at` исключаются, включая микросекунды PostgreSQL.
   Сброс прохождения внутри того же зачисления не имеет отдельного run ID/границы.
   Это явно отмечается в ведомости. Изменение настроек после попытки не позволяет
   объявлять текущий порог историческим: остаётся только фактический процент.
4. `education_document_records.document_status=original/duplicate` — вид записи,
   не доказательство физической выдачи. Старые nullable-связи разрешаются через
   точное зачисление с предупреждением; противоречащие связи отклоняются. Документы
   с датой выдачи до начала группы исключаются из её книги.
5. Никакой файл не становится `final`, официальные номера не резервируются.
   Расписание/пропуск и остальные неканонические данные требуют отдельной работы;
   атомарная финализация, полный рендер всех страниц и авторизованный production
   E2E всего комплекта ещё не подтверждены.
6. Найденный отдельный дефект сброса обучения (`useCourseLearningFacade`) не
   исправляется в этом релизе: независимые DELETE/UPDATE не гарантируют атомарность.
   Нужны серверная транзакция и граница нового прохождения без потери истории.
7. Эта версия не делает внутренний XML охраны труда официальным XML Минтруда.
   Совместимость с актуальной XSD/API и тестовым импортом не подтверждена.

## Проверка и публикация

Ревизия: `goreltech-group-package-server-facts-v16`.

Новый клиент должен проверять точную ревизию перед dry-run **и сохранением**,
передавать её в запросе и проверять ответ до сообщения об успехе. Неоднозначный
ответ после записи не означает «ничего не сохранено»: сначала обновить список.
У сохранения отключены автоматические сетевые повторы (`safeInvoke.retry=false`):
потеря ответа не доказывает откат RPC. Dry-run может повторяться; поведение
остальных вызовов `safeInvoke` сохранено. Серверная идемпотентность всей партии
по ключу запроса остаётся отдельным этапом, ручной повтор после обрыва нельзя
считать гарантированно безопасным без сверки списка.
Сервер проверяет любой переданный revision; dry-run требует его всегда. Старые
открытые вкладки могут сохранить черновик без header во время обновления, но
строки всё равно собираются новыми серверными builders.

Порядок выпуска:

1. Полный locked gate exact commit: app TypeScript, тесты, production build,
   проверка маркера сборки и чистоты дерева. Отдельно Deno check Edge.
2. Развернуть Edge и подтвердить v16 обезличенной capability-проверкой через
   Nginx. Не публиковать frontend v16 поверх неподтверждённого старого Edge.
3. Опубликовать соответствующий frontend через согласованный GitHub/Lovable/
   Timeweb путь. Наличие кода в feature-ветке не равно публикации.
4. Под ГОРЭЛТЕХ: dry-run всех 9 файлов → сохранение → обновление страницы →
   чтение сохранённых замечаний → скачивание. Сверить шапки и все страницы Word
   с исходниками; для ведомости и реестра сверить исходные записи по ID.
5. Проверить негативные случаи на изолированных тестовых данных: чужая
   организация, однофамильцы, старое зачисление, отсутствие записи реестра,
   несколько попыток, отказ источника. Реальные данные клиента не менять ради теста.

Миграция отдельных протоколов охраны труда из предыдущего feature-кандидата
остаётся самостоятельным шагом. Не применять все миграции пакетом и не отправлять
весь feature в main до подтверждённого backend-релиза.

Первый кандидат `99d057c43aefe4404268688b99e706e55566bc04`: полный прогон
220 файлов / 1812 тестов passed (198.71 с). App TypeScript выявил четыре ошибки
вывода generic-типов в новом тестовом reader, поэтому кандидат **не прошёл**
release gate. Исправление типов выполнено без `any`-кастов; окончательный gate
должен также включить защиту от автоматического повтора сохранения.
