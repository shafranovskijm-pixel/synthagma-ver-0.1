## Карта слотов

### Общие скаляры

- Организация, группа, программа, даты, номера и реквизиты заполняются только из фактического payload/данных организации.
- В документах с подписью используются `[[SIGNATORY_POSITION]]` и `[[SIGNATORY_SHORT]]`.
- `otherDocuments[].signatory` задаёт подписанта конкретного документа. Если объект передан с пустыми `position` и `name`, оба поля остаются пустыми. Данные руководителя организации используются только когда объект `signatory` отсутствует целиком; отсутствующая должность организации не заменяется выдуманным значением.
- В расписании и ведомости используются `[[INSTRUCTOR_1_SHORT]]` и `[[INSTRUCTOR_2_SHORT]]`; это две отдельные строки подписи. Исходное `instructor_name` делится только по `;` или переводу строки. Второй слот пустой, если второго имени нет. Если имён больше двух, первое остаётся в первом слоте, а все остальные сохраняются во втором через `; ` без блокировки генерации.

## Точные формулировки и отрицательные проверки

- Приказ о зачислении сохраняет полную формулировку `дополнительной профессиональной образовательной программе повышения квалификации`; сокращение `ДПО` в этой формулировке запрещено.
- Заголовок часов — `Часов`.
- Приказ об отчислении сохраняет `Отчислить без выдачи удостоверений`.
- В шаблоны не вшиваются ФИО, должность `Генеральный директор`, демонстрационные слушатели или отметки `V` в резервных строках.
- После компиляции не остаются токены `[[...]]`.

## Сохранность OOXML-пакета

- Для семи документов меняется только `word/document.xml`.
- У книги регистрации дополнительно меняются только части, перечисленные в её `manifest.json`: подключается точная шапка из `enrollment_order.source.docx`, её relationships и исходное изображение; остальные части сохраняются.
- SHA-256 исходника и готового шаблона сверяются с манифестом перед компиляцией.
- Сформированный DOCX повторно открывается как ZIP; отсутствие обязательной части или несовпадение хэша является ошибкой, а не предупреждением.

## Render gates

1. Рендерить и визуально проверять все страницы каждого из восьми DOCX.
2. Сверять размер листа и ориентацию с таблицей выше.
3. Проверять фирменную шапку, отсутствие наложений/обрезания и читаемость таблиц.
4. Проверять минимальные строки, отсутствие выдуманных ФИО/отметок и сохранение всех фактических слушателей сверх минимума.
5. Для расписания и ведомости проверять две независимые строки подписи преподавателей; при одном преподавателе второй слот должен быть видимым, но пустым.
6. Для каждого документа проверять пустой подписант и подписант, явно переданный для этого документа.

Неопределённое на текущем этапе: фиксированное ожидаемое число страниц для каждого возможного состава группы. Оно не должно кодироваться как константа без согласованного контрольного набора данных.

Фактическая проверка заполненного контрольного комплекта от 24.08.2026, точные пути, SHA-256, команда Word-рендера и результат по каждой из 10 страниц зафиксированы в [`render-evidence-v1.1.md`](./render-evidence-v1.1.md).
